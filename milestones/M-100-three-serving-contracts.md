## 1. Objective

Разделить три интерфейса, которые сегодня склеены в одной структуре `Selector`, — без смены
имени слепка и без удаления осей `timeframe_ms`/`window_ms` из ключа (план §5):

1. **что сервер СЧИТАЕТ** — ключ расчёта резолвит сервер по профилю расчётов; всё, что вне профиля, —
   названный отказ `unsupported`;
2. **что пользователь СМОТРИТ** — выбор строк глубины (`view.depth_rows`) поверх готового расчёта;
3. **как это ДОСТАВЛЯЕТСЯ** — провод v12: снимок объявляет ключ (`calc_key_id`), определение
   (`calc_profile`), окно карты (`heatmap_window_e8`); версия провода отвязана от версии
   вычислительного состояния слепка; семантика карты зафиксирована целиком, и найденное
   нарушение `VB-I-2` на живом пути устраняется.

## 4. Конструкция — объявлено ДОСЛОВНО (против этого написаны оракулы)

### 4.1 Что сервер СЧИТАЕТ — `CT-RFC-09` §2.10.1

```rust
// crates/gateway-serve/src/admission.rs (или session.rs) — резолвер ключа расчёта
pub fn resolve_calc_key(client: &serde_json::Value /* selector из subscribe */,
                        policy: &AdmissionPolicy) -> Result<gateway::Selector, ResolveError>;
// bands: нет ⇒ policy.canonical_bands; == canonical ⇒ принять; иначе ⇒ Unsupported
// (timeframe_ms, window_ms, depth_cadence_ms) ∉ allowed_profiles ⇒ Unsupported (TD-242)
```
Код ошибки на проводе — `unsupported` (сообщение для полос называет `view.depth_rows`).
Порядок на подписке не меняется: разбор → резолв ключа → валидация → допуск → слот → готовность.

### 4.2 Что пользователь СМОТРИТ — `gateway::view` (`CT-RFC-09` §2.10.2)

```rust
// crates/gateway/src/view.rs — НОВЫЙ модуль, чистые функции
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct DepthRowKey { pub band_pct_e8: i64, pub side: String }   // "bid" | "ask"
#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct ViewSpec { #[serde(default)] pub depth_rows: Option<Vec<DepthRowKey>> }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ViewError { EmptyDepthRows, UnknownDepthRow(DepthRowKey), DuplicateDepthRow(DepthRowKey) }
impl ViewSpec { pub fn validate(&self, calc: &Selector) -> Result<(), ViewError>; }
pub fn project_view(series: &SeriesBundle, view: &ViewSpec) -> SeriesBundle;
```
Проекция применяется ТРАНСПОРТОМ к снимку и к каждому кадру подписки ПОСЛЕ расчёта и проверки
предела объёма (предел меряет полный расчёт — проекция его только уменьшает). `Sub` хранит
`ViewSpec`; конверт снимка v1 несёт `"view"`. Ошибка — код `invalid_view`.

### 4.3 Стабильный идентификатор — `gateway::calc_key` (`CT-RFC-09` §2.10.4)

```rust
// crates/gateway/src/calc_key.rs — НОВЫЙ модуль
pub const CALC_KEY_ENCODING: &str = "calc-key/v1";
pub fn canonical_calc_key_bytes(sel: &Selector) -> Vec<u8>;
pub fn calc_key_id(sel: &Selector) -> String;   // sha256 → 64 hex нижнего регистра
```
Имя слепка НЕ меняется (`selector_fingerprint` остаётся; переход — S3).

### 4.4 Провод v12 и версия состояния (`CT-RFC-09` §2.10.3, §2.10.5)

```rust
pub const GATEWAY_SCHEMA_VERSION: u32 = 12;                 // crates/gateway/src/lib.rs
pub mod checkpoint { pub const CALC_STATE_VERSION: u32 = 11; }  // байты 12..16 заголовка слепка
pub struct Snapshot { /* прежние поля */
    pub calc_key_id: String,
    #[serde(default)] pub calc_profile: Option<CalcProfileStamp>,   // {version: u32, sha256: String}
    pub heatmap_window_e8: i64,
}
```
Заголовок слепка пишет и сверяет `CALC_STATE_VERSION` — и в библиотеке (`read_and_validate`), и в
допуске (`readiness`). `11` — чтобы слепки, записанные до `M-100`, остались годными: деплой
`M-100` НЕ требует холодной пересборки.

### 4.5 Семантика карты — `CT-RFC-09` §2.10.6

Таблица — в RFC. Требование к коду одно: **колонка бакета в живом кадре = состояние бакета на
ПОСЛЕДНЕМ его наблюдении внутри кадра** (как у полного пересчёта), а не объединение наблюдений.

  строки глубины (≈ 24 % снимка). Карта (43 %) и профиль объёма (26 %) уходят целиком.
- **`calc_key_id` объявляется, но не используется** для имени слепка до S3; общий писатель — S2.
- **Пирамида разрешений карты (`П-027`) не решается** — окно карты лишь ОБЪЯВЛЯЕТСЯ (`TD-197`).
- **Событие с опоздавшим `ts_exch_ms`** переобъявляет прошлый бакет состоянием книги на момент
  события — принятое следствие close-семантики, а не дефект (RFC §2.10.6).
- **`legacy`-путь (`wsprobe`)** получает снимок v12 с новыми полями, но без `view` (селектор из env).

## 13. Маршрут

architect (набор) → **critic на СИЛЬНОЙ модели** (RAW-гейт: провод; §9: спека + RFC) → engine-dev
(задачи 1–5; порядок 4 → 1 → 3 → 2 → 5: сначала развязка версий, чтобы деплой не стоил пересборки)
→ tester → reviewer (PR-гейт, §8, задача 6) → architect (задача 7). Подписи founder'а НЕ требуется:
состав полос, профиль и обещание пользователю не меняются (`П-029`, `П-030`, `П-032` в силе).
