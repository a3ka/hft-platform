## 1. Ключевое решение — allow-list из хардкода в конфиг (развязка merge от раскатки)

**Проблема, которую оно решает.** До задач 1–3 набор символов был хардкод-константой.
Факт снят в форме **класса 1** (`A-030` §1) — на ревизии, ПРЕДШЕСТВУЮЩЕЙ первой задаче, а не
«сегодня»: реализация с тех пор закрыта, и настоящее время здесь стало бы ложью, а прежняя
форма (`grep -rn … crates/`) на сегодняшнем дереве даёт семь строк вместо четырёх.

```text
$ git grep -n "L2DELTA_CAPTURE_SYMBOLS" d75a1b7 -- 'crates/*/src/lib.rs'
d75a1b7:crates/venue-binance-futures/src/lib.rs:460:const L2DELTA_CAPTURE_SYMBOLS: &[&str] = &["BTCUSDT"];
d75a1b7:crates/venue-binance-futures/src/lib.rs:642:                if L2DELTA_CAPTURE_SYMBOLS.contains(&symbol.as_str()) {
d75a1b7:crates/venue-binance/src/lib.rs:251:            if L2DELTA_CAPTURE_SYMBOLS.contains(&symbol.as_str()) {
d75a1b7:crates/venue-binance/src/lib.rs:485:const L2DELTA_CAPTURE_SYMBOLS: &[&str] = &["BTCUSDT"];
```

Doc-comment у обеих констант говорит прямо: «расширение набора требует отдельного решения
founder'а». Значит правка константы = совершение решения Границы C **кодом**, а merge такого
кода = раскатка. Это сцепляет две разные вещи: инженерную готовность и продуктовое решение о
составе данных.

**Решение (нормативное для этого milestone'а).** Набор символов становится **конфигурацией с
дефолтом, равным сегодняшнему поведению**:

- источник — env `L2DELTA_CAPTURE_SYMBOLS` (список через запятую), как уже сделано для
  `EPOCH_ID` (`crates/recorder/src/main.rs:481`) — тот же операторский рычаг, та же форма;
- **дефолт при отсутствии/пустом значении — `["BTCUSDT"]`**, байт-в-байт текущее поведение;
- нормализация регистра при разборе (см. оракул O-4 — это не косметика, а дефект-кандидат).

Что это даёт:

1. **Merge безопасен** — прод после деплоя эмитит ровно то же, что до него. §8-eyes-on
   проверяет отсутствие изменения, а не наличие.
2. **Раскатка — операторский шаг**, а не коммит: founder называет состав, оператор выставляет
   env + новый `EPOCH_ID` и перезапускает. Граница C соблюдена буквально: **ни один агент не
   меняет состав данных**.
3. **Откат — рестарт без env**, а не revert коммита в проде.

Цена: одна ветка разбора конфига и её тесты. Альтернатива «править константу в milestone'е»
отвергнута — она требует founder-подписи ДО написания кода и делает откат деплоем.

## 2. Эпохи — обязательное условие раскатки (`CT-RFC-06` §3)

Изменение состава эмиссии — **режимный сдвиг**: форма не меняется, семантика потока меняется.
Ровно класс E-001, где границу эпохи пришлось восстанавливать постфактум по heartbeat'ам на
123 млн событий. Механизм маркировки существует end-to-end (T1-поле `SegmentHeader.epoch_id` →
`decide_open_segment` не переиспользует сегмент чужой эпохи → env `EPOCH_ID`), поэтому:

- **новый `EPOCH_ID` выставляется ДО рестарта** с новым составом; конвенция значения —
  `own-YYYY-MM-m45-<slug>`;
- **запись в `docs/data-epochs.md` делается ДО раскатки**, класс «режимный сдвиг», не «дефект»;
- `SCHEMA_VERSION` НЕ бампается — он про бинарную совместимость, не про семантику (§0).

**Остаточный класс, названный явно** (`CT-RFC-06` §3, находка R-019 F4): машинного fail-closed
на «состав эмиссии изменился, а `epoch_id` — нет» **не существует** — код сверяет `epoch_id` со
своим же конфигом, а не с фактическим составом потока. Забыли выставить → сегмент
переиспользуется и две эпохи молча смешаются. Здесь это закрывается **дисциплиной и verify-гейтом**
(задача #5), не кодом; машинная сверка состава — кандидат в отдельный milestone, сознательно вне
объёма.

### 3quinquies. Состав пишется ЛИТЕРАЛОМ: подстановка обходит подпись (`C-202` B-1/B-2/B-3)

`C-202` предъявил, что гейт круга 3 проверял **написание в YAML, а не то, что получит
recorder**. Форма `${L2DELTA_CAPTURE_SYMBOLS:-BTCUSDT,ETHUSDT}` выглядит подписанной и
переопределяется снаружи одной переменной. Замер воспроизведён мной:

```text
$ printf 'services:\n  recorder:\n    image: x\n    container_name: hft-recorder\n    environment:\n      L2DELTA_CAPTURE_SYMBOLS: ${L2DELTA_CAPTURE_SYMBOLS:-BTCUSDT,ETHUSDT}\n' > /tmp/w-subst.yml; L2DELTA_CAPTURE_SYMBOLS=BTCUSDT,ETHUSDT,SOLUSDT docker compose -f /tmp/w-subst.yml config | grep L2DELTA
      L2DELTA_CAPTURE_SYMBOLS: BTCUSDT,ETHUSDT,SOLUSDT
```

**Проверять эффективную конфигурацию средствами docker в CI нельзя** — его там нет
(`grep -c docker .github/workflows/ci.yml` → `0`). Развязка — запретить подстановку для
величины под подписью. Литерал не переопределяется ни окружением, ни `.env`:

```text
$ printf 'services:\n  recorder:\n    image: x\n    container_name: hft-recorder\n    environment:\n      L2DELTA_CAPTURE_SYMBOLS: BTCUSDT,ETHUSDT\n' > /tmp/w-lit.yml; L2DELTA_CAPTURE_SYMBOLS=BTCUSDT,ETHUSDT,SOLUSDT docker compose -f /tmp/w-lit.yml config | grep L2DELTA
      L2DELTA_CAPTURE_SYMBOLS: BTCUSDT,ETHUSDT
```

**Форма этих двух блоков переснята (`A-030` §1).** Прежняя редакция показывала в обоих
ОДНУ И ТУ ЖЕ команду `docker compose config` с ДВУМЯ разными выводами: мир (какой compose
разбирается) жил в прозе, а не в команде, и на дереве репозитория ни один из двух выводов
не воспроизводился — у сервиса `hft-recorder` этой переменной ещё нет вовсе, задача 7 не
раскатана. Теперь каждый блок САМ создаёт свой мир и потому воспроизводим кем угодно —
это перевод из класса 3 (свидетельство) в класс 1, который `A-030` §1 предписывает
предпочитать всегда, когда он достижим. Исполнимый коррелят на реальном дереве —
шаг `T10`, фикстурные миры — `T10c`.


**Цена названа:** оператор больше не сменит СОСТАВ переменной окружения — только коммитом.
Это не потеря операторского рычага, а требование границы C: состав данных меняет подпись, а
не переменная под рукой. `EPOCH_ID` подчинён тому же правилу — эпоха, разъехавшаяся с
составом, делает события двух составов машинно неразличимыми (класс `E-001`).

**Это уточняет §1 п.2 спеки**, где раскатка названа «операторским шагом: оператор выставляет
env». Уточнение, а не отмена: шаг остаётся операторским (значение выбирает founder, вносит
engine-dev), но носителем становится коммит, а не окружение хоста.

**Предел механизма назван, иначе «литерал = защита» прочтут шире, чем он есть**
(`A-030` §2, предписание круга 5). Статический гейт видит ровно `docker-compose.yml` и НЕ
видит трёх остаточных каналов: `docker-compose.override.yml`, `docker compose run -e` и
ручной запуск контейнера с иным окружением на хосте. Литерал закрывает подстановку в
СУДИМОМ файле — и только её. Остаточные каналы держит не `verify`, а деплой-гейт
`gates.md` §8 (sanity свежих событий по КАЖДОЙ площадке — уже в `П-026` §Порядок п.3) и
дисциплина доступа к хосту.

**`C-202` B-3 закрыт тем же решением:** форма `${VAR-default}` без двоеточия честна и даёт
подписанный набор при unset — но она ТОЖЕ подстановка, то есть переопределяема. Гейт
отвергает её не как «неверную», а как форму, допускающую обход; политика названа явно, и
ложного красного нет — есть запрет класса.

**`C-202` B-2 закрыт вынесением компаратора в `scripts/lib/rollout_symbols_check.py`.**
Прежний `T10c` редекларировал разбор и сравнение вместо исполнения `T10`; замер критика
воспроизведён: ослабление реального `T10` оставляло все десять сценариев пробы зелёными.
Теперь оба шага зовут ОДИН файл, и ослабление роняет пробу — предъявлено прогоном:
четыре сценария из тринадцати краснеют с точной диагностикой.

### 3septies. Оракул был годен только в мире ДО раскатки (найдено engine-dev'ом на `f3b84d4`)

Пятый круг гейта дал `NOTE`, dev внёс две строки — и `T10c` покраснела на пяти сценариях из
семи. Дефект был не в правке dev'а: правка корректна. Дефект был в МОЕЙ пробе.

**Механика.** `compose_with()` строила фикстуру ДОПИСЫВАНИЕМ ключа ниже якоря `HL_COINS`.
Пока задача 7 не исполнена, ключей в `docker-compose.yml` нет, и дописка работала. Как
только dev внёс настоящие ключи, дописка стала ДУБЛЕМ — а PyYAML применяет last-wins, и
побеждало реальное значение. Мутация исчезала, CLI видел подписанный состав и возвращал `0`,
проба ждала `1`. Воспроизведение (`git show f3b84d4`, затем разбор фикстуры) даёт
`'BTCUSDT,ETHUSDT'` там, где сценарий задумал `'BTCUSDT,ETHUSDT,SOLUSDT'`.

**Почему это хуже единичной ошибки.** Оракул ломался ровно в тот момент, ради которого
написан: он был годен ТОЛЬКО в мире до раскатки. Пройди он мимо — гейт остался бы красным
навсегда после исполнения задачи 7, и следующий агент «починил» бы его ослаблением.

**Класс — отсутствие setup-guard'а, а не дубль ключа.** `testing.md` §«Целостность гейта»
св. 3: проба, молча тестирующая не тот сценарий, есть плацебо самой себя. Четыре круга
разбирали РАЗЛИЧАЮЩУЮ СИЛУ суждения и ни один не спросил, несёт ли фикстура то, что сценарий
задумал. Это та же ошибка меры, что `Р-1`, но уровнем ниже: не «чем меряем», а «то ли
построили».

**Что сделано — по классу, а не по экземпляру:**

| правка | что закрывает |
|---|---|
| `strip_keys()` — фикстура строится ЗАМЕНОЙ, а не дописыванием | сам дубль ключа |
| режим `--extract` в CLI + `setup_guard()` на КАЖДЫЙ сценарий | КЛАСС: расхождение задуманного и построенного объявляется, а не молчит |

### D-1 (решение architect'а после ДВУХ REJECT подряд, `C-048` и `C-049`) — проверять ПОВЕДЕНИЕ точки входа, а не структуру кода

**Диагноз.** Два круга критика подряд отвергли набор по одной и той же причине, и обе мои
попытки были вариациями одного неверного приёма — **доказать структурное свойство грепом**:

- `C-048`: T5 грепал ИМЯ константы → обходится переименованием/инлайном;
- `C-049`: T5 грепал вызов `l2delta_event` внутри `l2delta_emission_for` → обходится
  переносом хардкод-гейта НА УРОВЕНЬ ВЫШЕ (`if symbol == "BTCUSDT" { … }` перед вызовом:
  вызовов `l2delta_event` по-прежнему один, slice-литерала нет, гейт зелёный, раскатка
  молча не работает никогда).

Урок общий: **гейт, проверяющий форму кода, всегда обходится сдвигом гейта на уровень выше.**
Сколько бы уровней я ни перечислил грепом, следующий останется непокрытым. Это ровно то, что
`.claude/rules/testing.md` называет типовым барьером в `RK-I-1`: «venue-адаптер принимает
ТОЛЬКО `RiskApproved<Order>`… **компилятор — часть теста**», и что `INTG-I-*` формулирует как
«тест подтверждает ОТСУТСТВИЕ альтернативного пути, а не наличие проверки».

**Решение.** Оракул обязан звать **реальную точку входа обработки WS-сообщения** и проверять
её ЭФФЕКТЫ. Тогда любой хардкод-гейт — на любом уровне внутри обработки — проявляется как
отсутствие ожидаемого эффекта, и обходить нечего: проверяется не текст кода, а поведение.

**Паттерн в проекте УЖЕ ЕСТЬ, изобретать не нужно** — `venue-binance-futures` построен именно
так (введено в TD-014):

```text
crates/venue-binance-futures/src/lib.rs:502  pub enum SessionEffect { Emit(MdEvent), FetchSnapshot{..} }
crates/venue-binance-futures/src/lib.rs:535  pub fn new(symbols: &[String]) -> Self   // symbol_set, upcased
crates/venue-binance-futures/src/lib.rs:549  pub fn on_ws_text(&mut self, text: &str) -> Vec<SessionEffect>
```

Док-комментарий этой машины прямо говорит: «Тестируемая sync-state-машина БЕЗ сети/каналов…
никогда не ходит в сеть и не шлёт в mpsc — только возвращает `Vec<SessionEffect>`».

**Что делает venue-dev:**
1. **`venue-binance-futures`** — добавить в `FuturesSession` второй набор (allow-list `L2Delta`,
   рядом с существующим `symbol_set`), задаваемый явным параметром конструктора. `on_ws_text`
   принимает решение об эмиссии `L2Delta` ТОЛЬКО по нему.
2. **`venue-binance` (спот)** — привести к ТОМУ ЖЕ паттерну: публичная sync-точка входа
   `on_ws_text(&mut self, text: &str) -> Vec<SessionEffect>` без сети и каналов; текущий
   `handle_text_message` (async, с `reqwest::Client` и `FuturesUnordered`) остаётся тонкой
   I/O-обёрткой, исполняющей эффекты. Это не расширение объёма ради красоты: без
   тестируемой точки входа поведение спота проверить нечем, и всё сводится обратно к грепу.
3. Хардкод-условия по символу на пути эмиссии `L2Delta` не остаётся ни на одном уровне.

**Что делает architect (я):** оракул `O-8` — вместо структурных проверок дёргает
`FuturesSession::on_ws_text` сырым wire-текстом и проверяет состав `Vec<SessionEffect>`.
Обход (A) из `C-049` §1.2 при этом падает автоматически: внешний `if symbol == "BTCUSDT"`
приводит к отсутствию `Emit` для разрешённого ETHUSDT — тест красный.

**Статус:** O-7 (через `l2delta_emission_for`) сохраняется как проверка чистого ядра, но
БОЛЬШЕ НЕ СЧИТАЕТСЯ достаточным; решающий — O-8. T5-грепы остаются как дешёвая
дополнительная канарейка, их зелёный ничего не доказывает сам по себе.

### API-контракт (задачи 1–3) — форма зафиксирована оракулом, не свободна

```rust
/// Разбор allow-list из СЫРОЙ строки конфигурации. ЧИСТАЯ функция.
pub fn parse_capture_symbols(raw: Option<&str>) -> Vec<String>;

/// Решение об эмиссии: wire-символ против разобранного списка.
pub fn should_capture_l2delta(symbols: &[String], symbol: &str) -> bool;

/// ЕДИНСТВЕННАЯ точка решения об эмиссии на реальном пути. Чистая: без I/O, без env,
/// без async. `Some(event)` ⇔ сообщение — валидный depth-diff И символ разрешён списком.
pub fn l2delta_emission_for(
    stream: &str,
    data: &serde_json::Value,
    symbols: &[String],
) -> Option<EventKind>;
```

**Третья функция появилась по вердикту `C-048` (REJECT) и является ГЛАВНОЙ.** Критик
предъявил реализацию, проходящую весь прежний набор и при этом нерабочую: dev выполняет
контракт двух чистых функций дословно, оставляет их экспортированными — и **не подключает к
реальной точке решения** (обработчик WS-сообщения), переименовав константу или заинлайнив
список литералом. Тогда:

- O-1..O-6 зелёные — они дёргают чистые функции напрямую, минуя обработчик;
- прежний T5 зелёный — греп искал БУКВАЛЬНОЕ имя `L2DELTA_CAPTURE_SYMBOLS`;
- §8 eyes-on зелёный — дефолт совпадает со старым поведением байт-в-байт.

Дефект всплыл бы **только после founder-подписи**, когда оператор выставит env — то есть
позже всех гейтов. Поэтому предмет проверки смещён с «существуют ли функции» на «проходит
ли реальное wire-сообщение через allow-list»: `l2delta_emission_for` покрывает весь путь
(разбор `stream`/`data` → символ → allow-list → событие), обработчик обязан ей
**делегировать**, а не дублировать сравнение символов у себя. Чтение `env` схлопывается в
однострочную обёртку на самом верху (`connect`/`main`), проверяемую глазами.

**Разбор обязан быть чистой функцией, а чтение `env` — тонкой обёрткой над ним.** Причина не
стилистическая: `env` — глобальное состояние процесса, а `cargo test` гоняет тесты
параллельно в потоках. Оракул, дёргающий `set_var`, стал бы гонкой и давал бы разный
результат при разном порядке запуска — прямое нарушение принципа «в доменном коде нет
недетерминизма» (`CLAUDE.md`). Поэтому оракулы бьют в чистое ядро.

Семантика, закреплённая оракулами (отклонение = красный гейт):
- `None` и пустая/вырожденная строка (`""`, `"   "`, `","`) → **дефолт `["BTCUSDT"]`**;
  ни «эмитить всё» (взрыв объёма + необъявленная эпоха), ни «не эмитить ничего»
  (тихая потеря forward-only данных);
- пустые элементы отбрасываются, пробелы обрезаются, порядок сохраняется;
- сравнение регистронезависимое, но **не подстрочное**: `BTC` и `BTCUSDT_PERP` не совпадают
  с `BTCUSDT`.

## 4. RED-оракулы — спецификация (architect пишет ДО кода)

Чек-лист `.claude/rules/testing.md` «фикстура счастливого пути — дефект оракула» пройден по всем
пяти пунктам; каждый оракул обязан ПАДАТЬ на заглушке.

**O-1 (множественность + позитив).** В одном такте приходят диффы по ДВУМ символам, оба в
allow-list → эмитятся ДВА `L2Delta`. Анти-плацебо: реализация, обрабатывающая только первый
символ такта, обязана упасть. Покрывает пункт «множественность».

**O-2 (негатив — главный анти-плацебо).** Символ ВНЕ allow-list → `L2Delta` НЕ эмитится, поток
`L2Snapshot` для него не меняется. Без этого оракула реализация «эмитить всегда» проходит O-1
зелёным. Тест обязан проверять ОТСУТСТВИЕ события, а не наличие проверки.

**O-3 (границы).** Три входа: (а) env не задан → дефолт ровно `["BTCUSDT"]`, поведение
байт-в-байт как до milestone'а; (б) env задан пустой строкой → трактуется как дефолт, НЕ как
«эмитить всё» и НЕ как «эмитить ничего» молча; (в) список с пробелами/пустыми элементами
(`"BTCUSDT, ,ETHUSDT"`) → разбирается предсказуемо, мусорный элемент не становится символом.
Покрывает «границы» и «отсутствие».

**O-4 (регистр — дефект-кандидат, не косметика).** Сегодня сравнение точное:
`L2DELTA_CAPTURE_SYMBOLS.contains(&symbol.as_str())`. Если оператор напишет env в нижнем
регистре (`btcusdt`), эмиссия **молча выключится для BTC** — тихая потеря данных, forward-only
и невосстановимая. Оракул: env `"btcusdt"` даёт эмиссию для символа, который приходит из wire
как `BTCUSDT`. Реализация без нормализации обязана упасть.

**O-5 (`DET-I-1` на смешанном потоке — закрытие R-019 F6).** Замер, а не предположение:

Форма — **класс 1** (`A-030` §1): ревизия названа, вывод неизменен по построению. Прежняя
редакция снимала тот же счёт с РАБОЧЕГО дерева и утверждала «ноль» в настоящем времени —
сегодня та же команда на дереве даёт `6`, потому что оракул O-5 написан и `T8` зелёный.
На ревизии `a1fc098` (до O-5) фикстур с `L2Delta` у `DET-I-1` было **ноль** — детерминизм на

**O-6 (детерминизм эмиссии).** Один и тот же wire-diff → бит-идентичный `Event`, независимо от

### 4bis.2 Снимок имеет ДВА источника, и это решает конструкцию

Профильная ФА (`docs/fa/venues.md:67,72` и `docs/fa/book.md:99-103`):

| источник снимка | зачем | можно ли разрежать |

ТОЛЬКО периодическую ветку, и разделение этих двух путей — обязательное требование к любому
варианту.

публикацию — то есть требование «ресинк-снимок эмитится НЕЗАВИСИМО от каденции» (§4bis.4) не
описывает существующее свойство, которое надо СОХРАНИТЬ, а задаёт работу, которую надо
СДЕЛАТЬ. Несущий вывод раздела это не ослабляет, а усиливает: разделять два пути придётся
явно, потому что сегодня они — один путь.

### 4bis.3 Варианты — с ценой, а не список

Обозначения: снимок ликвидного символа 20–31 КБ; дифф ~1.5 КБ/с; снимки — 96 % объёма
журнала (`DESIGN` §17, замер 2026-07-14).

| # | вариант | объём | цена перемотки | риск |
|---|---|---|---|---|
| **A** | оставить как есть (сегодня) | **+5-7 %** к нынешнему | не меняется | избыточность узаконена; §17 п.2 не исполнен |
| **B** | якорь раз в 10–30 с для символов С ДИФФАМИ; ресинк-путь эмиссии **создаётся** отдельным (сегодня его нет — §4bis.2) | **−60…−80 %** на такой символ `[verify-at-impl]` | читатель досчитывает от якоря до 30 с диффов | требует, чтобы диффы были ПОЛНЫ: пропуск дельты между якорями = дыра до следующего якоря; **и требует работы, а не сохранения** — цена варианта выше, чем читалось в прежней редакции |
| **C** | якорь по СОБЫТИЮ (после N дельт или при сдвиге mid > X %), а не по времени | ещё меньше на спокойном рынке | каденция недетерминирована по времени | ломает предсказуемость перемотки; сложнее оракул |
| **D** | снимок вообще убрать, оставить только ресинк-ответы | максимум экономии | старт читателя = проход от последнего ресинка (часы) | **отвергается**: `DET-I-1` и перемотка перестают работать в разумное время |

### 4bis.4 РЕКОМЕНДАЦИЯ — вариант B, и вот почему именно он

1. **Он прямо предписан** `DESIGN` §17 п.2, включая диапазон 10–30 с. Это не изобретение,
   а исполнение уже принятого;
2. **симметрия защиты:** якорь нужен ровно для того, для чего диффов недостаточно, —
   старта и перемотки. Ресинк-путь остаётся нетронутым, то есть восстановление после гэпа
   не деградирует ни на миллисекунду;
3. **обратимость:** каденция становится ручкой конфига, а не константой кода. Ошиблись в
   числе — правится переменной, а не пересборкой. Сегодня её нет вовсе, и это отдельный
   дефект наблюдаемости того же класса, что `L2DELTA_CAPTURE_SYMBOLS`;
4. **вариант C не отвергается навсегда** — он лучше по объёму, но его каденция
   недетерминирована по времени, а перемотка — продуктовое свойство. Событийный якорь
   имеет смысл ПОСЛЕ того, как временной измерен на проде.

**Что B требует предъявить оракулом, а не обещанием:**

| требование | почему |
|---|---|
| **создать** отдельный путь эмиссии ресинк-снимка, независимый от каденции якоря (сегодня его НЕТ — §4bis.2, замер) | иначе разрежение замедлит восстановление после гэпа — прямое нарушение `book.md` §6. Формулировка «эмитится независимо» из прежней редакции описывала свойство как СУЩЕСТВУЮЩЕЕ; это работа, а не сохранение |
| книга, собранная «якорь + диффы», бит-в-бит равна книге из частых снимков | `DET-I-1`; это и есть проверка полноты диффов |
| символ БЕЗ диффов сохраняет прежнюю каденцию | у него якорь — единственный источник, разрежение потеряет данные |
| каденция читается из конфига fail-closed | невалидное значение = отказ старта, не молчаливый дефолт (`PL-I-5`) |

### 4bis.5 Границы этого раздела

- **Каденция 10–30 с названа `DESIGN`, но КОНКРЕТНОЕ число — замер, а не выбор**: оно зависит
  от того, сколько дельт накапливается между якорями на ликвидном символе. `[verify-at-impl]`;
- **инверсия — ОТДЕЛЬНЫЙ МИЛЕСТОУН, а не задача этого.** `M-45` уже подписан, реализован и
  ждёт раскатки; втягивать в него правку эмиссии значит переоткрыть закрытый предмет и
  задержать захват данных на недели. Правильный порядок: раскатать `M-45` как есть, приняв
  рост объёма осознанно, и следом закрыть инверсию;
- **инверсия — РЕШЕНИЕ ГРАНИЦЫ C и требует подписи founder'а.** Прежняя редакция этого пункта
  утверждала обратное доводом «меняется ЧАСТОТА якоря, а не состав» — и это **зеркальная
  форма софизма**, снятого этой же веткой кругом раньше («меняется точность, а не состав»,
  `R-159` → `scope-check` §1.1). Оба довода делят один приём: назвать изменение записываемого
  свойством второго порядка и тем вывести его из-под границы. Разрежение якоря 1 с → 10-30 с
  означает, что состояний книги в журнале станет в 10-30 раз МЕНЬШЕ; полнота держится
  диффами, но это ДРУГАЯ гарантия, а не та же. Класс — `DESIGN` §6 и `gates.md` §0.1:
  «арбитр решает как ПРАВИЛЬНО, founder — чего мы ХОТИМ». Конструкция — инженерная и
  разобрана выше; РЕШЕНИЕ разредить — владельца.
