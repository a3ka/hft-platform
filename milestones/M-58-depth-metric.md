# M-58 — переспека метрики жизненного цикла уровня: учёт НА ЖИЗНЬ, не на цену

## Objective

`cancel_fraction` измеряет не то, что утверждает. Реализация M-32 фиксирует судьбу НА ЦЕНУ
на первом `size=0` (`depth_lifetime.rs:171`, `states` не очищается), поэтому считает **долю
distinct-цен, получивших хотя бы один `size=0` за окно**. Две беды, обе подтверждены замером:

1. **Смещение в сторону вывода.** Уровень «отменён однажды, дальше стоит вечно» — сигнатура
   фантома TD-016 — засчитывается как `cancelled`. Проба `R-031` §A.1: цена отменена,
   рождена снова, жива до конца окна → `born=1 cancelled=1 frozen=0`, `cancel_fraction=1.0`
   при честном ответе `frozen`.
2. **Насыщение.** Величина растёт с длиной окна и плотностью сетки. Проба арбитра `A-002`
   §0-3: `0.5 → 1.0` при ОДИНАКОВОЙ живости конца окна. Значит `NEAR 0.981` vs `FAR 0.805`
   и тренд M-33 `0.867→0.796→0.622` сравнивали насыщение, а не физику.

**Цель:** заменить величину на per-LIFE и переснять segment 78. Это снимает замок `A-002`
автоматически, если новые числа подтвердят живость (новой founder-подписи не требуется).

## Контракт метрики (спецификация для impl)

Единица учёта — **ЖИЗНЬ** уровня, не цена.

- жизнь НАЧИНАЕТСЯ: цена не жива и приходит `size>0` → `lives_born += 1`; полоса жизни — по
  mid ТОГО тика, в котором эта жизнь родилась (не первой жизни цены);
- жизнь КОНЧАЕТСЯ ровно одним из трёх: `size=0` при живой → `lives_cancelled`;
  sequence-gap при живой → `lives_censored`; конец окна при живой → `lives_frozen`;
- перерождение той же цены — НОВАЯ жизнь; предыдущая судьба не наследуется (в том числе
  `censored` — цензура одной жизни не запрещает следующую);
- `cancel_fraction = lives_cancelled / (lives_cancelled + lives_frozen)`; `censored` вне
  знаменателя (как в M-32); знаменатель 0 → `None`;
- **БАЛАНС:** `lives_born == lives_cancelled + lives_frozen + lives_censored` в каждой полосе;
- вывод детерминирован (BTreeMap-порядок, `bands` по `(side, lo_bps)`).

Поля `born/cancelled/frozen/censored` **переименовываются** в `lives_*`. Это намеренно:
старое имя означало другую величину, и молчаливая смена смысла под тем же именем — ровно тот
класс ошибки, ради которого этот milestone существует. Переименование заставляет пересмотреть
каждый call-site.

Инварианты DV-I-1..9 (M-32/M-33) остаются в силе и обязаны оставаться GREEN: gap-исчезновение
не есть отмена (DV-I-3), отсутствие в дельте не есть удаление (DV-I-4), детерминизм (DV-I-5),
границы ресурса на 120k/400k событий (DV-I-7/8).

## RED-тесты (написаны ДО impl, sacred)

`crates/research-cli/tests/red_depth_lifetime_perlife.rs` — DV-I-10..14:

| оракул | что давит | против фиктивной реализации |
|---|---|---|
| DV-I-10 | перерождение цены = новая жизнь; судьба не наследуется | `left 1 / right 2` (born) |
| DV-I-11 | величина не насыщается с длиной окна; живая на конце окна жизнь не исчезает | `left (1,1,0) / right (2,1,1)` |
| DV-I-12 | цензура одной жизни не отравляет последующие | `left 1 / right 2` (born) |
| DV-I-13 | баланс жизней + дегенерированный вход (асимметрия, множественность, отсутствие, границы) | `left (1,1) / right (2,2)` |
| DV-I-14 | полоса атрибутируется для КАЖДОЙ жизни по mid её рождения; детерминизм | `left 0 / right 1` (deeper) |

**Мутационный контроль выполнен и задокументирован.** Реализация была временно
переименована (`born → lives_born` и т.д.) БЕЗ смены семантики — фиктивная реализация,
проходящая по типам. Все пять оракулов провалились с ожидаемыми числами «на цену» против
«на жизнь». Найдено и исправлено по ходу два дефекта самих оракулов:

- фикстура стояла ровно на границе полосы (`5% = 500 bps`), f64-округление уводило уровень
  в `[300,500)`, и тест падал по НЕВЕРНОЙ причине → взят `6%`;
- DV-I-13 в первой редакции проверял только баланс и был **ЗЕЛЁНЫМ** против фиктивной
  реализации (баланс сходится и при учёте на цену) → добавлена дискриминирующая проверка
  «две полные жизни одной цены → (2,2)».
