**Причина 2: объём.** Минимальный протокол reviewer'а ≈ 1.05 MB, из них 88.6 % — два файла
(строка 3). Барьер без снижения объёма провоцирует карго-предъявление: строку впишут, не
читая. Снижение объёма — предмет **M-60c′** (ведёт другой клон); M-66 от него НЕ зависит
механически (цена честного эха — открыть ОДИН файл `docs/fa/<модуль>.md`, десятки KB, а не
мегабайт), но риск карго-эха до посадки M-60c′ выше и назван в §5.

M-66 лечит причину 1 — механическим предъявлением на входе в `main`.

## 2. Инвариант достаточности (формулировка от результата)

> Ни один проверяемый диапазон (push в `main` / PR в `main`), чей суммарный diff трогает
> `crates/**`, не проходит джоб `review-fa` без файла `research/reviews/R-*.md` —
> введённого этим диапазоном или названного ПОЛНЫМ ПУТЁМ в сообщении коммита диапазона и
> существующего на HEAD, — несущего хотя бы один инвариант-ID, ЖИВОЙ на HEAD в FA хотя бы
> одного тронутого крейта. Независимо от типа события и формы истории; любая форма
> недостоверной базы, незнакомого крейта или отсутствующего FA-файла — FAIL, не пропуск.

Два составляющих механизма (порядок существенен — B без D имеет пустой квантор):

**D (пререквизит — «диапазон с кодом несёт вердикт»).** Диапазон `BASE..HEAD`, чей
`git diff --name-only BASE HEAD` содержит пути `crates/**`, обязан предъявить непустое
множество S review-файлов: добавленные (status `A`) `research/reviews/R-*.md` в диапазоне ∪
файлы, названные полным путём (`research/reviews/R-…​.md`) в `%B` любого коммита диапазона
И существующие на HEAD. S = ∅ → FAIL. Это механизация `gates.md` §4 и `TD-105`.

**B («инвариант-эхо»).** Хотя бы один файл из S обязан содержать ≥1 ID из U — объединения
множеств ЖИВЫХ ID тронутых крейтов. Живое множество крейта = грепу по `docs/fa/<файл>.md`
на HEAD по СОБСТВЕННОМУ префиксу модуля из таблицы §3.2: `\b<PFX>-I-[0-9]+\b`. Не зашитый
список: FA растёт — множество растёт само (строка 12: на `710b1ad` это `JR-I-1..13`).

**Почему «собственный префикс», а не «любой ID, греппящийся в FA» — решено замером.**
`DET-I-1` цитируется в `docs/fa/journal.md` (строка 13), как и `RK-*`/`CT-*`: FA-доки
цитируют сквозные и соседские инварианты. При семантике «любой греппящийся» `R-053`
(несущий `DET-I-1`, строка 4) ПРОШЁЛ бы — а он обязан краснеть. Сквозной ID — не
свидетельство открытия FA тронутого модуля.

**Почему «объединение», а не «эхо на каждый крейт» — запиннено фикстурой.** Диапазон M-57
(строка 9) трогал `journal`+`gateway`, `R-040` несёт только `JR-I-*` (строка 7) — и обязан
ПРОХОДИТЬ. Per-crate требование дало бы ложное красное на эталонном (лучшем измеренном)
вердикте проекта. Per-crate эхо — кандидат на ужесточение (§6), не норма.

## 3. Механизм

### 3.1 `scripts/check_review_fa.sh` — барьер

Проводка базы — ДОСЛОВНО паттерн `check_docs_freeze.sh` (тот же fail-closed блок): `$1` либо
`EVENT_NAME` (`push`→`PUSH_BEFORE`, `pull_request`→`PR_BASE_SHA`, иначе FAIL); пустая база /
zero-SHA / отсутствует в истории / не предок HEAD → FAIL с называнием причины.

Отличие от docs-freeze, названное явно: семантика **per-range, а не per-commit**. Диф
берётся суммарно `BASE..HEAD`. Реверт-пара внутри диапазона (код внесён и снят) даёт чистый
net-diff → барьер молчит. Это правильно ПО ПРЕДМЕТУ: норма — «в `main` не входит код без
вердикта»; если код в `main` не вошёл, вердикт не нужен. У docs-freeze per-commit нормативен,
потому что там предмет — сам факт правки замка; здесь предмет — состояние `main`.

Шаги:
1. диф диапазона; путей `crates/**` нет → `SKIP (диапазон не трогает crates/**)`, exit 0;
2. каждый тронутый `crates/<name>` резолвится таблицей §3.2: FA-крейт / NO-FA / незнакомый
   → незнакомый = FAIL («крейт не в таблице маппинга — добавь строку §3.2 или FA»);
3. U := ∪ живых множеств FA-крейтов; FA-файл из таблицы отсутствует на HEAD → FAIL
   (отсутствие файла ≠ пустое множество — fail-closed);
4. S := введённые + названные review-файлы (определение в §2); S = ∅ → FAIL (механизм D);
5. U = ∅ (тронуты только NO-FA крейты) → `PASS (D выполнен; B вакуумен — тронуты только
   NO-FA крейты: <список>)`, печать обязательна — вакуумность видима, не молчалива;
6. иначе: ∃ f∈S, несущий ID∈U → PASS с печатью найденного эха (`файл: ID`); нет → FAIL с
   печатью U-выборки (первые N живых ID тронутых модулей — сообщение об ошибке само
   подсказывает, ЧТО надо было открыть).

Решения — по exit-коду (`gates.md` §3); `VERDICT: PASS/FAIL` последней строкой.

### 3.4 Отвергнутое и отложенное — с причинами

- **Вариант A** (вердикт называет ПУТЬ `docs/fa/<крейт>.md`): путь вписывается, не открыв
  файл; live-ID — нет (его надо ЗНАТЬ, а знать проще всего — открыв FA). Отвергнут.
- **Вариант C** (blob-хеш версии FA в шапке вердикта): пиннит ВЕРСИЮ прочитанного — сильнее
  B, но цена на каждый вердикт при редких правках FA. ОТЛОЖЕН, кандидат после наблюдения за
  B (совместим: C — надстройка над B, не замена).
- **Per-crate эхо** (ID на КАЖДЫЙ тронутый FA-крейт): опровергнуто фикстурой R-040 (§2).
  Кандидат на ужесточение, если карго-эхо станет измеримым.
- **Голый ID вместо полного пути в механизме D-naming**: subjects поминают `R-NNN`
  постоянно (сам merge M-62: «R-066 APPROVED, круг 3») — голый ID удовлетворял бы D
  СЛУЧАЙНО. Полный путь — намеренный акт. Самоавторизации нет: названный файл сам обязан
  нести живое эхо (это указатель, не токен), поэтому ищем по `%B` целиком, без
  body-only-оговорки docs-freeze.

## 4. Kill-set — оси и сценарии RED-пробы (нормативная таблица)

B4DEAD), `anymodule` (ID любой FA — B4FOREIGN), `nomap` (незнакомый крейт молчит —

`nobase` (база не проверяется — E5NONANC), `emptyfaok` (отсутствующий FA-файл = пустое
множество — F6NOFAFILE). Состав батареи сверяется с этим перечнем по именам.

**Мутационный контроль спеки (два вопроса `testing.md`):** (1) нейтрализация грепа живого

## 5. Пределы — названы честно, формулировки «гарантирует» запрещены

1. **Механизм подделываем** — как токен `FOUNDER-APPROVED` (§11): живой ID можно вписать,
   грепнув FA механически или скопировав из чужого вердикта, не читая ни строки. Механизм
   превращает «забыл» в «соврал явно» — другой режим отказа с видимым следом в артефакте
   гейта, но НЕ доказательство чтения.
2. **Предупреждающий, не блокирующий**: branch protection недоступен (403, private + free
   plan — `TD-124`). Красный джоб на `main` виден, но merge не остановлен. Обещания
   блокировки в этой спеке нет и не будет.
3. **Не проверяет, что прочитано ПРАВИЛЬНО** — только что живой ID тронутого модуля назван.
   `TD-138`-класс (FA лжёт о коде) барьер не ловит вовсе — это предмет `verify_design_claims`,
   не M-66.
4. **CI слеп к фичевым веткам** (замер §0 стр. 19: `on: push [main]` only) — эхо
   проверяется на ВХОДЕ в `main`, не в момент написания вердикта. Локальный прогон барьера
   перед merge — на совести цепочки (paste-ready строка — в §D handoff'ов).
5. **D удовлетворяется называнием СТАРОГО R-файла** — намеренно (иначе hot-fix/revert на
   `main` неисполним без нового круга ревью): указание пути — видимый аудит-след, и B всё
   равно требует от названного файла живого эха тронутых модулей.
6. **Риск карго-эха** до посадки M-60c′ (объём протокола) выше базового: строку могут
   вписывать ритуально. Замер эффекта — на close-out через N вердиктов (§7), не обещание.

Свойство, которое механизм ДАЁТ: непредъявленное эхо не проходит в `main` незамеченным CI.
Не больше.
