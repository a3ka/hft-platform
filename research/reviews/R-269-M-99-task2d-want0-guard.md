## §2. Блокеры

### Б-1 — индекс засчитывается в `checked`, даже если ни одна его форма не найдена в листинге

`deploy/bin/journal-restore-drill-cron.sh` (вершина `2d9c0002`):

```
:280  CHECKED=0
:281  for i in ${IDX}; do
:282    for f in "segment-${i}.jrnl" "segment-${i}.jrnl.zst"; do
:283      if grep -qx -- "$f" <<<"${LISTING}"; then
:284        fetch_one "$f" || { …transport-failed…; exit 5; }
:285        if [ ! -f "${RESTORE}/${f}" ]; then …transport-failed…; exit 5; fi
          …
:291    done
:292    # (б) Все перечисленные в листинге формы этого индекса доехали — засчитываем.
:293    CHECKED=$((CHECKED + 1))
:294  done
```

Если проверка членства на `:283` ложно отвечает «нет» для обеих форм, индекс засчитывается
без единой выборки — «все формы доехали» истинно пусто. Счётчиков «в листинге / доставлено» на
индекс (`want`/`got`) и условия `want=0 ⇒ transport-failed` в прод-обёртке нет. В эталонной
обёртке пробы они есть: `scripts/tests/red_restore_drill.sh:667-676`
(`if [ "${want}" -eq 0 ] || [ "${got}" -ne "${want}" ]; then … transport-failed …`).
Сообщение коммита `2d9c0002` объявляет (б)/(в) закрытыми.

**Достижимая причина ложного «нет» — не регресс кода, а среда.** Here-string больше буфера
канала bash (5.1+) пишет во временный файл в `$TMPDIR`/`/tmp`. Не удалось — `cannot create temp
file for here-document`, команда `grep` получает статус 1, и `if` читает это как «имени нет».
Порог снят замером — 64 КиБ, одинаково локально (bash 5.2.21) и на VPS (bash 5.3.9):

```
$ (листинг N имён, ulimit -f 16, SIGXFSZ проигнорирован; grep -qx <<<) локально | на VPS
bytes=38999  member=yes        | member=yes
bytes=62399  member=yes        | member=yes
bytes=67599  member=no         | member=no     (cannot create temp file for here-document: No space left on device)
bytes=103999 member=no         | member=no
```

**Воспроизведение на прод-обёртке `2d9c0002`** (транспорт `local`, копия из 6 000 имён
`segment-NNNNNNNN.jrnl.zst` = 156 КБ листинга + `journal.legacy.json`; читатель — заглушка,
печатающая полный протокол успеха, если в `--dir` есть хоть один файл, и `rc=5` на пустом).
Сбой `/tmp` смоделирован `RLIMIT_FSIZE` при проигнорированном `SIGXFSZ` (запись падает так же,
как при ENOSPC):

```
== контроль (без сбоя)
exit=0
state: {"ok":1,…,"checked":3,"events_read":1,"digest":"aaaa…","reason":""}
files delivered to restore: 4

== сбой /tmp на весь прогон
exit=5
state: {"ok":0,…,"checked":3,"events_read":0,"digest":"","reason":"reader-rc-5 (empty — копия не привезла событий)"}
files delivered to restore: 0

== сбой /tmp начинается ПОСЛЕ первой выборки (шим `cp`: настоящий cp, затем
   `prlimit --fsize=16384 --pid $PPID` на первом вызове), два прогона
exit=0
state: {"ok":1,…,"checked":3,"events_read":1,"digest":"aaaa…","reason":""}
files delivered to restore: 1        → segment-00000001.jrnl.zst
(повтор — то же)
```

**Тот же вход — на эталонной обёртке пробы** (`red_restore_drill.sh:595-710`, извлечена как есть):

```
== сбой после первой выборки
ALERT transport-failed (индекс 00003000: в листинге форм 0, доставлено 0)
exit=5
state: {"ok":0,…,"checked":1,"events_read":0,"digest":"","reason":"transport-failed"}
== контроль
exit=0  state: {"ok":1,…,"checked":3,…}
```

Итог: по форме спеки — `transport-failed`/5, `checked=1`; по прод-обёртке — **`ok=1`, `checked=3`,
`exit 0`, доставлен один индекс из трёх**. Это наблюдаемый класс `TD-260` («индекс засчитан без
доставки»), который задача 2d должна была закрыть. При сплошном сбое — `ok=0`, но с ложным
диагнозом («копия не привезла событий» — оператор пойдёт проверять коробку, а сломан локальный
`/tmp`) и `checked=3` при нуле доставленных.

**Когда достижимо на проде.** Листинг коробки сегодня (замер 2026-10-16T23:03Z, только чтение,
`ssh … -p 23 … ls journal`): **40 473 байта, 1 649 строк**, последний `segment-00001060.jrnl`.
Ниже порога — сегодня here-string идёт каналом, временного файла нет. Листинг растёт с копией;
после 64 КиБ каждый месячный прогон зависит от записи в `/tmp` (на VPS — tmpfs 3.8 ГБ, занято
1 %). Нужны оба условия: листинг > 64 КиБ И сбой записи во временный каталог во время прогона.
Вероятность низкая; последствие — ложное `ok=1` над историей, которая существует только в копии
(`M-99` §2 п.2).

**Почему блокер, а не долг.** (1) Это несоблюдение явной строки спеки, которую предмет закрывает,
а не новая интерпретация; эталон architect'а её исполняет, реализация — нет. (2) Исход — ровно
`TD-260` MAJOR. (3) `A-056` §2.3 / решение founder'а 2026-10-15 («через критика») — развилка о
классе «обещание без оракула» не моя; я описываю дефект, маршрут выбирает architect.

### Б-2 — спека объявляет страж `want=0` недостижимым; замер это опровергает

`milestones/M-99-restore-drill-automation.md` §11: «Страж `want=0` … без эксклюзивного члена …
при членстве без канала выбранный индекс всегда найден. Мера по построению на случай будущей
регрессии членства». §8, строка мутации «снят только страж `want=0`» — «PASS 41/41: эксклюзивного

Утверждение «при членстве без канала выбранный индекс всегда найден» ложно: членство без
канала (`<<<`) имеет собственный путь отказа — временный файл here-document (Б-1). Эксклюзивный
член есть: сбой записи во временный каталог после первой выборки — эталон краснеет только
благодаря `want=0`, прод-обёртка без него пишет `ok=1`. Следствие: у обещания §4 стр.12 (в)
нет оракула, и реализация, его не исполнившая, прошла пробу 43/43, гейт и тестера. Класс —
`testing.md` «Оракул обязан мерить то, что обещает» + «Целостность гейта» св. 3.

Граница reviewer↔architect (`gates.md` §4): форма оракула (инъекция сбоя here-string, шим
выборки, иное) и правка §8/§11 — зона architect'а; я предъявляю только воспроизведение.
