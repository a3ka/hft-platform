## Б-1 (БЛОКЕР) — `p12` зависит от скорости машины: в CI PR #310 не построился сценарий

**Что.** CI PR #310 (`fmt + clippy + test`, run `37227238562`, job `111509323767`) — красный:
```
test p12_known_non_candidate_position_blocks_younger ... FAILED
panicked at crates/journal/tests/red_m92_manifest_prune.rs:515:5:
SETUP НЕ СОСТОЯЛСЯ: segment-00000002.jrnl обязан быть в skipped плана, а кандидаты — по обе стороны:
{"segment-00000000.jrnl", "segment-00000001.jrnl", "segment-00000002.jrnl", "segment-00000003.jrnl"}
test result: FAILED. 20 passed; 1 failed
```
Упал СТРАЖ ПОДГОТОВКИ, а не утверждение об удалении: о реализации этот прогон ничего не говорит.
Страж сработал правильно (`testing.md` «Целостность гейта» п.3). Дефект — в построении сценария.

**Где.** `crates/journal/tests/red_m92_manifest_prune.rs:465-516`. Проход 1 узнаёт `first_seq`
сегмента 2, проход 2 пишет те же события заново и подменяет событие на этом индексе. Предполагается,
что разбиение по сегментам у двух проходов совпадает. Страж `:497-501` проверяет только ИМЕНА
сегментов, то есть их ЧИСЛО, а не границы.

**Почему разбиение не совпадает.** `Journal::append` (`crates/journal/src/lib.rs:206-218`) кладёт
в событие `ts_mono_ns`, время с момента открытия журнала, а postcard кодирует его как varint.
Длина кадра в байтах растёт с прошедшим временем, а ротация идёт по байтам (`max_segment_bytes = 8 KiB`).
Граница сегмента зависит от СКОРОСТИ записи, и у двух проходов на медленной машине она разная.
Оракул меряет окружение, а не свой инвариант (`testing.md` «Целостность гейта» п.2).

**Воспроизведение (моя проба: временный файл в `crates/journal/tests/`, удалён, в ветку не попал).**
Одинаковые 900 событий, `cfg()` теста, пауза каждые 50 событий:
```
пауза  0 мс → first_seq сегментов: [0, 173, 342, 511, 680, 849]
пауза  0 мс → first_seq сегментов: [0, 173, 342, 511, 680, 849]
пауза  1 мс → first_seq сегментов: [0, 173, 342, 511, 680, 849]
пауза  5 мс → first_seq сегментов: [0, 172, 341, 510, 679, 848]
пауза 20 мс → first_seq сегментов: [0, 172, 341, 509, 675, 841]
```
Число сегментов везде 6, поэтому страж `:497` проходит, а `first_seq` сдвинут. Локально `p12`
зелёный 6/6 и 12/12 под CPU-нагрузкой: на этой машине проход укладывается в одно окно varint.

**Почему не перезапуск и не merge.** Повторный прогон CI может оказаться зелёным, но тогда в `main`
уедет оракул, краснеющий случайно. Красный `main` замораживает деплой fail-closed (класс `TD-135`).
Решение по коду возврата чеков: `CHECKS=1` ⇒ не мержу (`gates.md` §8).

**Чего я НЕ проверял.** Другие оракулы файла, тоже строящие сценарий по позиции сегмента
(`p8`–`p11`, `c*`), этим прогоном не задеты (20 passed). Подвержены ли они тому же классу, я не
проверял. Это вопрос к architect'у вместе с выбором конструкции. Конструкцию фикса я не предлагаю
(`gates.md` §4, граница reviewer↔architect).
