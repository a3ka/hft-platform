## 2. Находки

### (i) БЛОКЕР — в push-диапазоне чужая задача, сама в зоне нормы

```
$ git log --oneline origin/main..main
a1d334f  docs(rules): §9 — уставная правка перепроверяется независимым Fable …
791df27  docs(M-64): П-012 + Н-7 …
$ git show --numstat --format='' 791df27
34  0  docs/PENDING-SIGNATURE.md
22  0  milestones/BACKLOG.md      ← оба пути В ЗОНЕ нормы
```

Норма гейтит push («правка → перепроверка → push»), а `791df27` этим прогоном не проверялся.
**Правка (процедурная):** перепроверить `791df27` отдельно либо получить явный ack founder'а на
совместный push; только затем `git push`.

### (ii-1) СУЩНОСТНОЕ — эскейп-хэтч «блок в отчёте» противоречит §4 того же файла

`gates.md:347` — «Вердикт — артефакт `research/reviews/R-NNN` **либо блок в отчёте** с сырым
выводом команд». §4 (строки 149–160) прямо противоположен: «вердикт, существующий только в
переписке, аудит-трейлом не является» (инцидент M-49, ~300k токенов). Норма разрешала ровно тот
отказ, против которого §4 написан, — и прогон его воспроизвёл.

**Готовая правка (дословно):**
> Вердикт — файл `research/reviews/R-NNN`, закоммиченный на ветку ДО push (§4: вердикт в
> переписке аудит-трейлом не является); блок с сырым выводом команд — содержимое файла, не
> замена ему.

### (ii-2) СУЩНОСТНОЕ — композиция с маршрутом §9 не названа

В §9 выше действует формула «критик при изменении ФОРМЫ; всё остальное — self-push автора».
Новая норма не говорит: (а) нужна ли перепроверка правке-«изложению» в зоне; (б) складывается
ли она с кругом критика на форме в ДВЕ обязательные цепочки. Противоречия нет — перепроверка
есть предпуш-условие, а не второй маршрут; есть неназванность, которую исполнитель заполнит
по-своему.

**Готовая правка (дословно):**
> Перепроверка идёт ПО ЗОНЕ (включая правки-«изложение») и НЕ заменяет критика по триггерам
> выше; вердикт критика на сильной модели со СВЕЖИМ контекстом, покрывший пункты (а)–(в),
> засчитывается как перепроверка — двух отдельных кругов не требуется.

### (iii-1) КОСМЕТИКА — глоб `docs/0N-*.md` механически вакуумен

```
$ git ls-files -- 'docs/0N-*.md'    → 0 файлов
$ ls docs/                          → 00-…09-*.md
```
Нотация домовая (та же в §9:312) и для `COGNITIVE-ONLY` терпима, но названный кандидат на
механизацию (`FABLE-RECHECKED`) с ней даст молчаливый no-op. **Правка:** `docs/0[0-9]-*.md`.

### (iii-2) КОСМЕТИКА — «самопроверка Fable'ом самого себя» двусмысленна

Читается и как «модель Fable не может проверять Fable» — невыполнимо: проверяющий обязан быть
Fable. **Правка (дословно):**
> перепроверка ТЕМ ЖЕ агентом (автором правки) правилом НЕ считается — нужен ВТОРОЙ агент со
> свежим контекстом; модель та же (Fable).
