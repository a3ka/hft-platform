## F-1 (MAJOR, блокер) — `TD-107` НЕ закрыт: на пути без mid память по-прежнему O(жизней), ×4.00

`crates/research-cli/src/depth_lifetime.rs:150-155` (doc-комментарий `SideBook`) утверждает:

> «Сейчас — `counts: BTreeMap<lo_bps, BandCounts>` размером с число полос (7) … **Память
> O(число полос), расход O(1) на завершённую жизнь**.»

Утверждение неверно для пути, где mid не появился. `attribute_newborns` вызывается только под
`if let Some(mid) = compute_mid(...)` (`:412`), а `unattributed` дренится ТОЛЬКО там. Пока mid
нет, каждое рождение пушит в `unattributed` (`:259`), и с M-59 **каждая отмена-до-атрибуции
пушит ВТОРОЙ раз** (`:227`, новый код). Очередь растёт линейно по жизням.

**Замер** (мой probe, `#[global_allocator]`-счётчик, тот же метод, что в DV-I-15; фикстура —
односторонний bid-поток, ask пуст, `cycles` = N и 4N, N=20 000):

```
ветка ca4319c : peak(N)= 787096 B  peak(4N)=3146392 B  рост ×4.00
origin/main   : peak(N)=1442456 B  peak(4N)=5767832 B  рост ×4.00
```

То есть класс расхода на этом пути **не изменился** — изменилась только константа (вдвое).
Против этой конфигурации DV-I-15 не краснеет, потому что его фикстура засевает ОБЕ стороны
на первом тике (`cycles_window` → `ticks.push(tick(1, sb, sa))`), и mid известен с самого начала.

**Почему это блокер, а не примечание.** Это буквально предмет милестоуна: единственная
Objective M-59 — граница памяти. И слепота оракула здесь ТОЙ ЖЕ природы, что породила сам
`TD-107`: `DV-I-7` не ловил дефект, потому что в его фикстуре `finished` оставался пуст;
`DV-I-15` не ловит остаток, потому что в его фикстуре `unattributed` дренится каждый тик.
Милестоун цитирует этот урок в собственной шапке (строки 20-23) — и воспроизводит его этажом
ниже. `testing.md`, «оракул обязан мерить ТО, ЧТО ОБЕЩАЕТ» + «целостность гейта», свойство 3.

Приемлемых исходов два, выбор — не моя зона (`gates.md` §4, граница reviewer↔architect):
либо путь без mid тоже сворачивается в агрегаты, либо ограничение НАЗЫВАЕТСЯ — правится
doc-комментарий (сейчас он лжёт), заводится TD-запись и оракул фиксирует границу применимости.
Чего нельзя — оставить в файле утверждение «Память O(число полос)» без квалификатора: его
прочитают как истину при расширении на несколько символов, ровно тогда, когда это будет дорого.

**Воспроизведение:** probe-крейт с зависимостью `research-cli` по path, глобальный аллокатор-
счётчик, `analyze(&no_mid_window(N))` vs `analyze(&no_mid_window(4N))`, где `no_mid_window`
чередует `bid size=5` / `bid size=0` на одной цене и НИКОГДА не даёт ask-уровня.

## F-2 (MAJOR, блокер) — молчаливая потеря завершённой жизни; §Forbidden милестоуна нарушен

`depth_lifetime.rs:238-258`. При новом рождении цены, чья предыдущая жизнь завершилась ДО
атрибуции:

```rust
if let Some(old) = self.states.remove(&l.price) {
    if let Some(lo) = old.born_band_lo_bps {
        bump_finished_fate(self, lo, old.fate);
    } else {
        self.states.insert(l.price, old);        // :249 — вернули старую жизнь
    }
}
self.states.insert(                              // :252 — и тут же ЗАТЁРЛИ её новой
    l.price,
    LevelState { born_band_lo_bps: None, fate: Fate::Alive },
);
```

Ветка `else` возвращает старый `LevelState` в `states` под тем же ключом-ценой, а следующая
строка безусловно перезаписывает его состоянием новорождённого. Старая жизнь не попала ни в
`counts`, ни в `states` — она **исчезает бесследно**. Прежняя реализация в этом месте делала
`finished.push((old.born_band_lo_bps, old.fate))`, то есть жизнь учитывалась (в первой полосе
по `unwrap_or`).

**Замер** (probe, тот же вход в обе реализации, суммы по всем полосам):

| сценарий | `origin/main` (контракт M-58) | ветка `ca4319c` | расхождение |
|---|---|---|---|
| A: `born, cancel, born` одной цены **внутри одного тика**, mid известен | born=4 cancelled=1 frozen=3 | **born=3 cancelled=0** frozen=3 | −1 born, −1 cancelled |
| B: то же по тикам, но mid **не появляется** (односторонний поток) | born=2 cancelled=1 frozen=1 | **born=1 cancelled=0** frozen=1 | −1 born, −1 cancelled |
| C: контроль — цикл по отдельным тикам, mid известен | born=4 cancelled=1 frozen=3 | идентично | — |

Баланс `born == cancelled + frozen + censored` при этом ОСТАЁТСЯ верным (уменьшились оба
слагаемых) — поэтому ни один существующий ассерт, включая балансный в DV-I-15, не краснеет.
Потеря именно ОТМЕНЁННЫХ жизней смещает `cancel_fraction` ВНИЗ — то есть ту самую величину,
которая лежит под founder-решением П-011 и под вердиктом `depth-verdict.md`.

**Почему блокер.** §Forbidden милестоуна (`M-59-lifetime-memory.md:38-40`) прямо запрещает
«менять семантику жизни (рождение/отмена/цензура/заморозка) — это контракт M-58», а §Tasks #2
формулирует обещание «рефакторинг не меняет результат». Результат изменён — измеримо. Проверка
Task #2 выполнена на ОДНОМ датасете (segment 78), где случай не возникает, и потому зелёная:
это ровно «фикстура счастливого пути» из `testing.md`. Класс входа, который она не покрывает, —
пункт 2 обязательного чек-листа деградированного входа: «несколько ЖИЗНЕЙ одной сущности».

**Честно о наблюдаемости сегодня.** Сценарий A требует, чтобы одна цена трижды встретилась в
`bids` ОДНОГО тика; `examples/depth_lifetime.rs` строит `DeltaTick` один-к-одному из
`MdPayload::L2Delta`, где биржа повторов цены в одном сообщении не даёт, — на segment 78
эффект нулевой, и T5 это подтверждает. Сценарий B достижим всегда: окно между первым тиком и
первым двусторонним mid. Величина на реальных данных мала — но она не ноль, не ограничена
конструкцией и ничем не наблюдаема.
