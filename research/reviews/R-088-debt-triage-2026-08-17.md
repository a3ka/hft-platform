## §1 — методологическая находка: гипотезу нельзя было принять на слово

Первая же проверка вернула ЛОЖНЫЙ отрицательный результат, и разбор этого важнее самого
триажа.

```
$ git merge-base --is-ancestor 955f409 main && echo ЕСТЬ || echo НЕТ
НЕТ
$ grep -n 'static CUR' crates/gateway/tests/red_snapshot_noclone.rs
38:static CUR: AtomicUsize = AtomicUsize::new(0);
```

Читалось это как «фикс, на котором стоит удаление `TD-098`/`TD-129`, не влит; глобальный
счётчик жив; гипотеза неверна». Причина оказалась другой:

```
$ git log --oneline main..origin/main | wc -l
9
```

**Локальный `main` общего чекаута отставал от `origin/main` на 9 коммитов** — включая
`955f409` (PR #15). Проверка была перенесена в worktree на `origin/main`, и там:

```
$ grep -n 'thread_local\|fn o1_' crates/gateway/tests/red_snapshot_noclone.rs

226:fn o1_snapshot_allocation_does_not_grow_with_state() {
```

**Урок, который стоит дороже триажа:** утверждение о коде обязано называть РЕВИЗИЮ, на
которой оно снято. Гипотеза architect'а была снята на `9ba9798`, моя первая проверка — на
устаревшем локальном `main`, и они дали противоположные ответы об одном файле. Все
последующие проверки выполнены в worktree на `10439cd` и ревизия названа в архивном файле.
