## Содержательная проверка фикса (не только цвет гейта)

Milestone примечателен тем, что **предыдущий набор оракулов был зелёным при мёртвом проде**.
Поэтому я перепроверял не «12/12 PASS», а то, на что оракулы реально давят.

**1. `LiveReducer::pump` больше не тавтологичен — подтверждено чтением кода.**
`frames_since` внутри `pump` не вызывается (`crates/gateway/src/lib.rs`, тело `pump`): один
проход `journal::stream_from(self.cursor)`, кадр строится на свежем `Reducer`, чей vwap-
аккумулятор засеян из персистентного `self.vwap` (O(1)). `ReadStats` берутся с ЭТОГО ЖЕ
прохода — то есть меряют всю работу тика, а не половину (task #2b закрыт по существу).

**2. Эталон в оракуле действительно независим.**
`td083_pumped_frames_fold_into_full_replay_snapshot`: `snapshot(START)` + свёртка кадров
`pump` ≡ `snapshot(LATEST)`. Это свойство **невозможно удовлетворить, вернув чужой результат** —
оно связывает кадры с независимо посчитанным состоянием журнала. Прежняя проверка
(`pump` vs `frames_since`, где `pump` возвращал `frames_since`) сравнивала функцию сама с собой.

**3. Персистентно переносится ТОЛЬКО `VwapAcc.sum_pv`/`sum_v`** — и это корректно ровно
потому, что `frames_since` тоже стартует со свежего редьюсера и сеет через `seed_vwap`
только vwap. Остальные ряды дельта-only по построению. Байт-идентичность доказана и парным
сравнением, и независимой свёрткой — двумя разными способами.

**4. Живость (O-3) — фикстура честно названа ограниченной.**
`red_ws_liveness_under_load.rs` работает на `#[tokio::test]` (current_thread — форма прода) и
проверяет три независимых свойства, включая **деградированный вход** (грубый обрыв без
close-handshake — именно тот случай, у которого не было ветки выхода). Ограничение названо в
шапке файла прямым текстом: на тестовом журнале тик дёшев, прод-зависание фикстура НЕ
воспроизводит; цена тика меряется отдельными оракулами. Это правильная честность, а не дыра.

**5. Владение `LiveReducer` через `spawn_blocking` разобрано корректно.** `live` передаётся во
владение задаче и возвращается в ОБЕИХ ветках `pump` (Ok и Err); единственный невосстановимый
путь — паника blocking-таска — закрывает соединение явно, а не продолжает с потерянным
состоянием. Ветка `stream.next()` поллится на каждой итерации `select!` независимо от
`pending_read` — уход клиента детектируется без кадров (task #4 закрыт по существу).

### 2. Барьер `protected-artifacts` даёт ЛОЖНОЕ срабатывание на rename через merge → `TD-092`

Мой merge-push уронил CI на job `Protected artifacts (gate trail)`:

```
FAIL  milestones/M-47-td083-push-seek.md: артефакт ИСЧЕЗ с HEAD, и ни один коммит его не удалял
      (значит его выбросил MERGE — evil merge / -s ours / rename внутри мержа)
```

**Дефекта в коммитах нет.** `ec1095f` legitimно ПЕРЕИМЕНОВАЛ milestone (номер M-47 был занят):
`R095 milestones/M-47-td083-push-seek.md → milestones/M-53-td083-push-seek.md`. У барьера ЕСТЬ
ровно этот carve-out (`scripts/check_protected_artifacts.sh:129-137` — «переехал в защищённый
путь»), но он **недостижим через merge-коммит**: строка 124 зовёт
`git log --diff-filter=DR -M "${base}..HEAD" -- "${path}"` **без `--full-history`**, а
history-simplification не спускается в side-ветку, если путь TREESAME по первому родителю.
Воспроизведено локально:

```
$ git log --diff-filter=DR -M 09e5cb6..HEAD -- milestones/M-47-td083-push-seek.md
(пусто)
$ git log --full-history --diff-filter=DR -M 09e5cb6..HEAD -- milestones/M-47-td083-push-seek.md
ec1095f test(M-53): нетавтологичные оракулы TD-083 … номер M-47 был занят — переименовано замером
```

С `--full-history` барьер нашёл бы rename и выдал `NOTE … переехал … (остался под защитой)`.
Это **ровно тот класс, который барьер и создавался ловить, но с обратным знаком**: гейт
объявляет evil merge там, где его нет. Цена — красный `main` и заблокированный Deploy P0-фикса.
Зона правки — architect (`scripts/` sacred), заведено **`TD-092`**.

### 4. `td083_tick_wallclock_does_not_grow_with_history` меряет wall-clock — принятый риск

Оракул O-B сознательно нарушает урок TD-078 («оракул не должен мерить CI-машину»), и
обоснование в шапке теста корректное: `stats` самого `pump` — именно то, что оказалось

Риск флаки на нагруженном раннере остаётся ненулевым. Отдельного долга не завожу — при первой
же флаке это повод для architect'а переехать на счётчик работы.

### 5. `resume()` без чекпоинта делает лишний полный проход журнала

`LiveReducer::resume` при отсутствии чекпоинта декодирует ВЕСЬ журнал только ради честного
`ReadStats.events_decoded` (форсинг оракула `resume_without_checkpoint_reports_full_replay`),
после чего первый `pump()` проходит те же события ЕЩЁ РАЗ. На проде чекпоинт есть, путь не
исполняется; при потере чекпоинта коннект станет вдвое дороже. Не блокирую — фиксирую вместе
с §10.2 milestone'а (двойная стоимость на connect) в `TECH-DEBT` под `TD-093`.
