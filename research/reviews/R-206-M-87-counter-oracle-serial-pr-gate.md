Равенство счётчиков — необходимое, но не достаточное условие: блокировка, взятая в середине

## §7 — Находки

Блокеров нет. Две находки уровня NOTE; обе переведены в долг, ни одна не задерживает merge
— пока `#229` не влит, `main` остаётся под случайным красным, а это дороже.

### Н-1 (NOTE → `TD-224`, зона engine-dev) — корневая причина осталась

Лечение симптоматическое, и architect это называет сам. Процессный счётчик в оракулах
означает, что оракулы ОБЯЗАНЫ идти по очереди — требование к порядку исполнения, которого
у правильного оракула быть не должно (`testing.md`: «меряет СВОЙ инвариант, а не
окружение»). Корневое лечение — счётчик ЭКЗЕМПЛЯРА сервера по образцу
`Server::slots_handle` (спека `M-87` §14.1ter уже провела этот перевод для СЛОТОВ, для
байтов не провела). Тогда блокировка становится ненужной, а не «нужной, но терпимой».

### Н-2 (NOTE → `TD-225`, зона architect) — у правки нет механического сторожа

Правка вводит **обязывающее требование к будущим правкам файла**: «каждый новый
асинхронный тест берёт `SERIAL` первой строкой». Носитель требования — комментарий в
файле. Пятнадцатый асинхронный тест, добавленный без блокировки, вернёт класс МОЛЧА, и
вернёт его в худшей форме: ложный ЗЕЛЁНЫЙ у `c6`/`u1`-позитива (§5(1)) не виден никаким
прогоном. Механизм при этом дешёвый и стоит одной строки в уже существующем гейте:

```
# scripts/verify_M-87.sh — зона architect'а
a=$(grep -cE '^#\[tokio::test' crates/gateway-serve/tests/red_m87_entrypoint.rs)
b=$(grep -c 'SERIAL.lock().await' crates/gateway-serve/tests/red_m87_entrypoint.rs)
[ "$a" = "$b" ] || fail "…: асинхронных тестов $a, блокировок $b — новый тест не сериализован"
```

Это ровно та проверка, которую мандат просил выполнить меня руками (пункт 3). Проверка,
которую ревьюер делает руками каждый круг, обязана стать строкой гейта — иначе она
исполняется, пока о ней помнят. Правило «обязывающее живёт вместе с механизмом»
(`gates.md` §11, профиль reviewer'а) для `crates/**/tests/**` формально не действует — зона
не та, — но основание правила действует в полном объёме, и бэкстоп ревьюера механизмом не
считается по той же норме.

**Почему это NOTE, а не блокер.** Механизм лежит в `scripts/verify_*.sh` — sacred-зоне
architect'а, то есть в файле, которого этот PR не касается; требовать его здесь значит
расширять предмет PR'а вместо того, чтобы снять красный `main`. Карточка `TD-225` и есть
носитель требования.

барьер `check_review_fa.sh` строит U по префиксу `GS`, а по существу предмет описывает
`VB-I-10`.

**Барьер на этом диапазоне даёт `SKIP`, и это названо, а не выдано за проверку:**
`check_review_fa.sh:95-100` исключает `crates/*/tests/**` как не входящее в прод-образ
(`C-115` B-1) — диапазон трогает только тесты, значит требование FA здесь КОГНИТИВНОЕ.
`FA-WAIVER` не требуется: `gateway-serve` — крейт с живой FA, не NO-FA.
