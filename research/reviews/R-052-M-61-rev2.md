## Б-4 — БЛОКЕР: мутант `quotedname` красен НЕ ПО СВОЕЙ ПРИЧИНЕ — батарея сертифицирует ложно

**Это ровно условие 4 `R-046` и открытый вопрос самого architect'а** (`806470e`: «мутант,
красный не по своей причине, — плацебо самого себя. Проверить до close-out»). Вопрос не был
закрыт ни dev'ом, ни тестером — тестер напечатал `quotedname → FAIL (12)` как достижение
(«самая жирная дыра»), не заметив, что двенадцать — это ВСЕ блокирующие сценарии набора.

**Замер 1 — профиль отказов по каждому мутанту** (`BARRIER=<мутант> red_artifact_ids.sh`):

|---|---|---|---|---|

Восемь мутантов из девяти падают ровно на сценариях своей оси. `quotedname` падает на всём,
включая `B1R` — коллизию двух файлов с **чисто ASCII** именами `R-200-alpha.md` /
`R-200-beta.md`, где квотирования нет вовсе.

**Замер 2 — изоляция.** Отдельная фикстура, только ASCII, ничего кириллического:

```
$ EVENT_NAME=push PUSH_BEFORE=$B bash /tmp/rev2-batt/ref-check.sh        ; echo exit=$?
exit=1        ← эталон коллизию видит
$ EVENT_NAME=push PUSH_BEFORE=$B bash /tmp/rev2-batt/quotedname-check.sh ; echo exit=$?
exit=0        ← мутант не видит НИКАКОЙ коллизии
```

**Замер 3 — корень, диф эталон↔мутант:**

```
$ diff ref-check.sh quotedname-check.sh
40c40   <     while IFS= read -r -d '' f;        >     while IFS= read -r f;
44c44   <     git ls-tree -r --name-only -z      >     git ls-tree -r --name-only
55c55   <     while IFS= read -r -d '' f;        >     while IFS= read -r f;
59c59   <     git show ... -z --format=          >     git show ... --format=
67c67   < [ -z "$IN" ] && exit 0                 > [ "$IN" ] && exit 0          ← ⚠
69c69   <   [ -z "${cls:-}" ] && continue        >   [ "${cls:-}" ] && continue ← ⚠
```

Мутант строится сплошной подстановкой `BODY_QUOTEDNAME="${BODY_CHECK//-z /}"`
(`mk_ref_artifact_ids.sh:151`). Шаблон `-z ` совпал не только с флагом git, но и с
**оператором shell-теста** `[ -z … ]` — в двух местах:

- `[ -z "$IN" ] && exit 0` → `[ "$IN" ] && exit 0` — «если диапазон что-то ввёл, немедленно
  выйти УСПЕХОМ». Сравнение не выполняется никогда;
- `[ -z "${cls:-}" ] && continue` → `[ "${cls:-}" ] && continue` — пропустить каждую
  непустую строку.

То есть мутант — не «слепой к квотированию барьер», а **барьер, пропускающий всё по
построению**. Он краснеет против пробы по причине, не имеющей отношения к оси 4.

**Почему это блокер, а не примечание.**

1. Это дословно невыполненное условие 4 `R-046`, принятое как условие APPROVED и никем не
   оспоренное.
2. Единственный страж генератора — `cmp -s ref-check.sh $m-check.sh` («мутант не совпал с
   эталоном»). Он проверяет, что мутант ОТЛИЧАЕТСЯ, и не проверяет, что он отличается
   ЗАЯВЛЕННЫМ свойством. Профиль выше показывает, что этого достаточно для восьми мутантов
   и недостаточно для девятого — то есть страж не ловит именно тот класс, ради которого
   поставлен.
3. Цена ошибки асимметрична в ту же сторону, что и весь milestone: `B4Q` — сценарий, из-за
   которого потребовался круг 2 (ОБЕ независимые реализации прошли 25/25, будучи слепыми).
   Мутант, который обязан навсегда закрепить эту находку в репозитории, сегодня доказывает
   не её. Гарантия держится историей вердикта, а не механизмом.
4. `testing.md` «Целостность гейта», свойство 3: «Стаб не смеет подменять проверяемый
   контракт»; `A-005` §6.5 — причина, по которой батарея вообще лежит в репозитории.

**Условие приёмки** (дизайн — architect, `gates.md` §4 граница reviewer↔architect):
мутант, объявленный для оси/значения X, обязан падать на сценариях X и **зеленеть на
остальных**; несоответствие — отказ батареи, а не строка в логе. Проверяемо тем же
профилем, что снят выше.
