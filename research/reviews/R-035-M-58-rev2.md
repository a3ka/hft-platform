## Мутационный контроль — прогнан reviewer'ом независимо (мандат, п.2)

Спека (`M-58-depth-metric.md:89-98`) заявляет: реализация была подменена фиктивной
(переименование полей БЕЗ смены семантики), и «все пять оракулов провалились с ожидаемыми
числами». Проверил сам, двумя разными мутациями.

### Мутация 1 (узкая) — возврат предиката рождения

```rust
- let new_birth = self.states.get(&l.price).is_none_or(|s| s.fate != Fate::Alive);
+ let new_birth = !self.states.contains_key(&l.price);        // семантика M-32
```
Результат: **упал только DV-I-13** (`left (1,1) / right (2,2)`), четыре оракула зелёные.

**Это не дефект оракулов, и я проверил почему.** Предикат — не единственный носитель
семантики: в текущем коде отмена УДАЛЯЕТ запись из `states` (`depth_lifetime.rs:164`), поэтому
`!contains_key` после отмены снова истинно и перерождение всё равно засчитывается. Мутация
меняет поведение лишь там, где состояние остаётся неатрибутированным — две полные жизни
одной цены ВНУТРИ одного тика. Ровно этот случай и держит DV-I-13. Гранулярность верная.

### Мутация 2 (заявленная спекой) — фиктивная реализация M-32 + переименование полей

Взял `crates/research-cli/src/depth_lifetime.rs` из `origin/main` (учёт НА ЦЕНУ) и переименовал
`born/cancelled/frozen/censored → lives_*`. Публичный API совпадает (проверено дифом
сигнатур), сборка проходит по типам — то есть это именно «фиктивная реализация», описанная
