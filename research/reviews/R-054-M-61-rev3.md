## Б-6 — БЛОКЕР: `introduced()` роняет TD-запись, чей слаг содержит ERE-метасимвол → настоящая коллизия проходит с affirmative-«OK»

**Что сделано в `76f9402` (строки 155-162 `scripts/check_artifact_ids.sh`).** TD-кандидат,
извлечённый из диффа коммита, засчитывается, только если он НАЙДЕН в `HEAD:TECH-DEBT.md`, а
поиск сделан так:

```bash
| while read -r tcls tnum tsubj; do
    git show "HEAD:TECH-DEBT.md" 2>/dev/null \
      | grep -qE "^- \*\*TD-0*${tnum}\*\* \`${tsubj}\`" && printf '%s %s %s\n' "$tcls" "$tnum" "$tsubj"
  done
```

`${tsubj}` — ДАННЫЕ (слаг долга) — подставляются в ERE как ШАБЛОН. Слаг с метасимволом
регулярного выражения перестаёт совпадать сам с собой, `grep` возвращает не-0, `&&` не
срабатывает, кандидат МОЛЧА выпадает из `IN` — и барьер печатает «ни один новый артефакт не
введён», exit 0. Направление отказа выбрано ровно противоположно смыслу барьера, вся ценность
которого в fail-closed.

**Это не гипотетическая форма данных.** Замер по `TECH-DEBT.md` в `origin/main` — **6 слагов из
111 (5.4 %) уже содержат ERE-метасимволы**:

```
$ git show origin/main:TECH-DEBT.md | sed -nE 's/^- \*\*TD-0*([0-9]+)\*\* `([^`]+)`.*/\1 \2/p' \
    | grep -nE '[][(){}+*?^$.|\\]'
120 метаданные-путь-O(число-сегментов)-на-тик-остаточный-рост-x4.7-6.5
100 цена-сессии-9.8-MiB-получена-вычитанием-не-той-величины-покоя
86  deploy.yml-без-concurrency-и-с-триггером-по-тестам
76  recover()-не-покрыт-guard-ом-монотонности
3   [verify-at-impl]
47  v7-wire-форма-в-docs/fa/viz-backend.md-не-упоминает-vp_session_max_time_s
```

### Почему проба этого не ловит и не поймает

`red_artifact_ids.sh` сценарий `B1TD` (единственный, покрывающий ось 2 / `запись в TECH-DEBT.md`)
использует слаг `совсем-другой-предмет` — форма «счастливого пути» без единого метасимвола
(`testing.md`: «Дегенерированный вход обязателен — фикстура счастливого пути есть дефект
оракула», пункт 4 «Границы»). Хуже: **эталон батареи несёт ТОТ ЖЕ дефект** — блок
`introduced()` в `scripts/tests/mk_ref_artifact_ids.sh` (строки 109-114) содержит побайтово ту
же конструкцию с `grep -qE "…${tsubj}…"`. Прогон эталона на фикстуре воспроизведения 1:

```
$ EVENT_NAME=push PUSH_BEFORE=$BASE bash /tmp/rev-ref-batt/ref-check.sh; echo exit=$?

```

Это ровно «зависимый эталон» из `testing.md`: оракул `прод == эталон` невалиден на свойстве, где
эталон делит с прод-кодом дефект. Ни один из 15 мутантов такого класса не моделирует, поэтому
`35/35` и `17/17` останутся зелёными и после починки одной только пробы.

### Почему это блокер, а не долг класса `TD-127`

`TD-127` (§6.2 спеки) принят долгом с явным обоснованием: «в штатном CI недостижимо
(`actions/checkout@v4`, `fetch-depth: 0`)» — его триггер требует порчи object store. Триггер
`Б-6` — **обычный текст слага в обычном CI**: ни особых прав, ни поломанного репозитория, ни
редкой конфигурации. Механизм, который в 5.4 % существующего корпуса печатает affirmative-«OK»
на нарушении, своей заявленной работы не делает, а `M-61` вводится именно как fail-closed-барьер.

## Н-8 — фикс усиливает `Н-4` из `R-052`: правка шапки в том же диапазоне теперь ПЕРЕНАПРАВЛЯЕТ предмет

Предмет введённого артефакта теперь читается из `HEAD`, а не из коммита-источника. Следствие,
названное явно, потому что оно не подразумевается: последовательность «ввести файл под занятым
номером → в следующем коммите того же диапазона переписать его шапку `**Предмет:**` на предмет
занявшего» теперь даёт ЗЕЛЁНОЕ, тогда как до фикса давала красное (введённый предмет брался
на момент введения). По букве спеки это законно — совпавший предмет и есть критерий
множественности (§3.1 правило 1), — но цена «инварианта от результата» названа: **барьер верит
шапке в её финальной редакции**. Оракула на этот сценарий в наборе нет. NOTE, категория (iii);
кандидат в `TD` при close-out, решение — architect'у.
