# НАХОДКИ

## Б-1 (БЛОКЕР) — единственный страж разрушительного пути fail-OPEN на опечатке порога
`scripts/gc_worktrees.sh:63` (страж) · `:35` (разбор) · `:25` (шапка, где написано `[Ч]`)

`IDLE_H` не валидируется. При нечисловом значении `[ "$idle_h" -lt "$IDLE_H" ]` возвращает
НЕ-НОЛЬ (ошибка `[`), ветка KEEP-CACHE не берётся, и управление уходит прямо в `rm -rf`
(`:70`). То есть страж, ради которого режим и вводился, при негодном аргументе не
ужесточается, а ОТКЛЮЧАЕТСЯ — включая деревья, где сборка шла минуту назад.

Правдоподобность опечатки высокая: **шапка Usage сама печатает параметр как `[Ч]`** —
кириллическую «Ч» от «часов». Оба естественных написания ломают страж:

```
$ bash gc.sh --reclaim 3ч     # mtime wt-active/target = ТОЛЬКО ЧТО
gc.sh: line 63: [: 3ч: integer expression expected
RECLAIMED  wt-active — 1MB (кэш; cargo пересоберёт)      <-- кэш активной сборки уничтожен
$ bash gc.sh --reclaim 3h
gc.sh: line 63: [: 3h: integer expression expected
RECLAIMED  wt-active — 1MB
```

Тот же исход даёт отрицательное число. Цена — не потеря данных, а ровно то, что шапка
`:46-47` обещает предотвратить: «прогон упадёт, и причину будут искать в коде», только теперь
у ЧУЖОЙ роли и без всякого сообщения об отказе.

**Условие снятия:** валидировать порог до цикла и падать, а не молча сносить, например
```bash
case "$IDLE_H" in ''|*[!0-9]*) echo "ОТКАЗ: порог '$IDLE_H' — не целое число часов"; exit 1 ;; esac
```
и убрать из шапки кириллическое `[Ч]` в пользу `<часов>`/`<N>`.

## Б-2 (БЛОКЕР) — команда, рекомендованная новым правилом, в его же случае не убирает НИЧЕГО
`.claude/rules/branch-hygiene.md:66-69`

Правило: «Запушил, пишешь Handoff — снеси `target/` своего worktree (`rm -rf <свой
worktree>/target` **либо** `bash scripts/gc_worktrees.sh --reclaim`)». Две команды поданы как
равнозначные, но по конструкции они противоположны в точности в НАЗВАННЫЙ правилом момент:
агент, который только что собирал, имеет свежий `target/`, а `--reclaim` (порог 2ч) свежие
кэши по определению НЕ трогает.

```
$ bash gc.sh --reclaim          # «агент только что собрал и отдаёт работу»
KEEP-CACHE  wt-active — молчит 0ч (порог 2ч), 1MB     <-- СВОЁ оставил
RECLAIMED  wt-idle-clean — 1MB                         <-- ЧУЖОЕ снёс
RECLAIMED  wt-merged2 — 1MB
   свой кэш после прогона: НА МЕСТЕ — команда правила не убрала ничего
```

Итог ровно обратный норме «убери за собой»: своё остаётся, чужое забирается. Обходного пути
правило не называет, а очевидный (`--reclaim 0`) хуже:
```
$ bash gc.sh --reclaim 0
RECLAIMED  wt-active — 1MB
   чужой кэш, тронутый 5 минут назад: СНЕСЁН — порог 0 не различает своё и чужое
```
Плюс третий исход: при чужой живой сборке `--reclaim` отказывает целиком (A.2, exit=1) —
на этом хосте это норма, а не редкость (в момент проверки шли три `cargo`). Агент, выбравший
«официальную» вторую форму, получит KEEP-CACHE либо ОТКАЗ и честно отчитается, что убрал.

**Условие снятия:** в п.3 назвать формы НЕравнозначными: для своего дерева — `rm -rf <свой
worktree>/target` (единственная форма, работающая в момент передачи); `gc_worktrees.sh
--reclaim` — общая уборка чужих молчащих деревьев, не замена первой.

## N-1 — неизвестный флаг молча становится РЕАЛЬНЫМ прогоном
