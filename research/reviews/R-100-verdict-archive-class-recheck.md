## Находки

### F-1 (блокер): наблюдатель-константа проходит всю пробу

Мутация MC1 — в `check_verdict_class` перед печатью INFO вставлено `n_dead = 2`
(канонический стаб по `testing.md` §«Мутационный контроль»: «замени на константу»).

- Проба: **64 PASS / 0 FAIL, exit=0** — V-1…V-4 и все остальные сценарии зелёные.
- Реальное дерево: `INFO [V-АРХИВ] … мёртвых ссылок … : 2` при истинных **84**; `VERDICT: PASS`.

Причина: V-4 (`scripts/tests/red_verify_design_claims.sh:670-688`) — единственная счётная
точка наблюдателя, и она равна 2. Любой стаб, печатающий 2, неотличим от рабочего счёта.
Автор сам мутировал только «всегда 0» (M3) — эта мутация падает, константа, совпавшая с
фикстурой, нет. Комментарий наблюдателя (`scripts/verify_design_claims.sh:917-921`)
обещает: «класс НАЗЫВАЕТСЯ числом… исключение без наблюдения — то самое ложное зелёное».
Стаб MC1 возвращает ровно это ложное зелёное, и проба его не видит.

Воспроизведение:
```
cp scripts/verify_design_claims.sh /tmp/mc1.sh   # + n_dead = 2 перед 'if not present:'
BARRIER=/tmp/mc1.sh bash scripts/tests/red_verify_design_claims.sh   # → 0 FAIL
bash /tmp/mc1.sh .   # → INFO … мёртвых ссылок …: 2 (истина: 84), VERDICT: PASS
```

### F-2 (блокер): выпадение `research/critiques/` из кортежа проходит всю пробу

Мутация MC2 — `VERDICT_CLASS_DIRS = ("research/reviews/", "research/arbitration/")`
(реалистичный регресс: опечатка/рефакторинг кортежа, треть класса выпала).

- Проба: **0 FAIL** — все четыре V-сценария зелёные.
- Реальное дерево: `VERDICT: PASS`, INFO лишь молча сжимается до `104 вердиктов / 61 ссылка`
  (94 файла critiques выпали и из исключения, и из счёта — кортеж общий).

Причина — незакрытая матрица покрытия. Класс = 3 каталога × 2 проверки, но каталоги
запиннены не в тех ячейках, куда проверки реально доходят:

| каталог | check3 (доходит: обходит весь root) | check4 (не доходит: только `docs/`) | наблюдатель |
|---|---|---|---|
| `research/reviews/` | **V-2 ✓** | — | — |
| `research/critiques/` | **не запиннен** | V-1 (вакуумен сегодня, см. F-4) | — |
| `research/arbitration/` | **не запиннен** | — | V-4 ✓ |

Единственная проверка, которая СЕГОДНЯ реально судит research/ — check3, — запиннена
только для `reviews/`. Выпадение `critiques/` (или `arbitration/`) из кортежа возвращает
класс `TD-064` для этого каталога, причём невидимо даже прогоном на реальном дереве:
сегодня в critiques нет битых `§`-ссылок, гейт остаётся зелёным, и регресс обнаружится
только следующим красным на аудит-артефакте — ровно тот отложенный взрыв, который правка
объявила устранённым.

Воспроизведение:
```
cp scripts/verify_design_claims.sh /tmp/mc2.sh   # кортеж без "research/critiques/"
BARRIER=/tmp/mc2.sh bash scripts/tests/red_verify_design_claims.sh   # → 0 FAIL
bash /tmp/mc2.sh .   # → VERDICT: PASS; INFO: 104/61 вместо 198/84
```
