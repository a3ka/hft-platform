## §0 — Почему этот файл существует

`gates.md` §9 такие правки автор приземляет сам. Отдельный вердикт заведён не ради

в переписке она бы не пережила сессию (`gates.md` §4).

## §2 — Замер, которым это снято (ДЕРЕВО СЛИЯНИЯ, не ветка)

`gates.md` §8 требует проверять утверждения документа о коде на merge-preview, а не на
ветке. Проверено после merge'а #185, `origin/main` = `1e7f879`:

```
$ git merge origin/docs/M-70-rev2          # в чистом дереве origin/main
$ git diff --name-only --diff-filter=U     # пусто — слияние ЧИСТОЕ, конфликтов НЕТ

$ cargo test -p gateway --test red_depth_provenance_by_reach \
      gw_i_4_holds_when_the_tail_frame_is_delta_only
test result: FAILED. 0 passed; 1 failed; 0 ignored; 8 filtered out
```

Сообщение оракула:

> «GW-I-4/VB-I-2 НАРУШЕН на метке при DELTA-ONLY хвосте … Реплей: [4 точки];
> собранное клиентом: [3 точки]. Причина расхождения всегда одна — метка снимается НЕ
> там, где считаются числа полосы: живая книга видна только полному реплею,
> дельта-кадр строк depth не несёт вовсе.»

**Оба утверждения прежней редакции неверны:** конфликт не «ровно один», а ноль; красное
не «чужое и снятое», а живое и слиянием не снимается.

## §3 — Почему `M-77` его не снимает (механизм, а не мнение)

```
$ git grep -c 'book_series_in' origin/main -- crates/gateway/src/lib.rs

```

Но все реальные call-site'ы стоят внутри `pump` (`:4501`, `:4571`). Код объявляет
границу сам — `:1764-1765`:

> «Свежие batch'и в `pump` и Reducer'ы в snapshot/checkpoint/replay НЕ включают: для них
> `book_series_in` не зовётся».

Красный оракул идёт `frames_since` → `frames_since_with_stats` → `reduce_event_stream`,
и там `let mut reducer = Reducer::new(selector);` (`:2233`) — книга пустая. `M-77`
чинил класс ТОЛЬКО на пути `pump`.
