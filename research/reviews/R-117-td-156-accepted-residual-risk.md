### 1.4 УТОЧНЕНИЕ Н-1 — «предсуществующие пары CI не красят» верно, но основание НЕ «возраст»

Формулировка мандата «предсуществующие пары CI не красят и **никогда не красили**» верна для
проводки CI, но её основание названо неточно, и неточность стоит зафиксировать: невидимость
пары держится на ДОСТИЖИМОСТИ обоих носителей из базы события, а НЕ на том, что пара старше
барьера. Контрпример на искусственной базе:

```
$ EVENT_NAME=push PUSH_BEFORE=76d7365 bash scripts/check_artifact_ids.sh; echo "exit=$?"
FAIL  R-35: второй носитель «research/reviews/R-035-M-57.md» под идентификатором,
      занятым «research/reviews/R-035-M-58-rev2.md»
exit=1
```

`76d7365` — сам коммит-барьер (2026-08-09), то есть база СТАРШЕ обоих носителей по дате
(оба созданы 2026-08-05). Барьер тем не менее краснеет. Причина установлена:

```
$ git merge-base --is-ancestor d4fd45e 76d7365 || echo "d4fd45e НЕ предок 76d7365"
d4fd45e НЕ предок 76d7365          # d4fd45e = коммит, добавивший R-035-M-57.md
$ git merge-base --is-ancestor 0761a20 76d7365 && echo "0761a20 предок"
0761a20 предок                     # 0761a20 = коммит, добавивший R-035-M-58-rev2.md
```

`76d7365` сидит на ветке `feat/M-61`, отпочкованной от более раннего `main`, поэтому
`d4fd45e` в неё не входит и попадает в `rev-list 76d7365..HEAD` как ВВЕДЁННЫЙ.

**Почему это не отменяет вывод.** CI подставляет базу из СОБЫТИЯ
(`check_artifact_ids.sh:122-125`): `push` → `PUSH_BEFORE` (прежняя вершина `main`),
`pull_request` → `PR_BASE_SHA` (вершина `main`). Обе — потомки всех пяти пар, значит ни один
из десяти носителей не попадает в `introduced()`, и цикл `introduced × universe`
(`:215-226`) до них не доходит. Красное 1.4 достижимо только ручным вызовом с базой
бокового ответвления — то есть это не поведение CI.

**Формулировка, которая переживает будущее:** предсуществующие пары невидимы барьеру,
**пока обе стороны достижимы из базы события**. Это и есть названный предел барьера
(он судит ВВОДИМОЕ, а не универсум), а не его поломка.
