нормы три пробела. Каждый предъявлен командой; **ни один не является поводом отказаться от
Р-2 — все три чинятся одной-двумя строками в §6.**

### §4.1. `ALLOW-ARTIFACT-DELETE` не назван, а без него коммит НЕ ПРОЙДЁТ CI

Норма Р-2 §6 требует от коммита переезда единственный токен — `ARCHIVED-VERDICT:`. Но
переезжает **пара** «гейт + спека», а `milestones/*.md` — защищённый путь:

```
$ sed -n '68,74p' scripts/check_protected_artifacts.sh
is_protected() {
  case "$1" in
    research/critiques/*.md|research/reviews/*.md|research/arbitration/*.md) return 0 ;;
    milestones/*.md|docs/rfc/*|docs/contract-rfc/*) return 0 ;;
    *) return 1 ;;
  esac
}
```

`docs/archive/*` в списке НЕТ. Барьер засчитывает переезд только «в ДРУГОЙ защищённый путь»
(`:172-178`); иначе требуется `ALLOW-ARTIFACT-DELETE:` в теле ТОГО ЖЕ коммита (`:180-183`),
а без него — `FAIL`, и джоб `Protected artifacts` входит в агрегат `All checks passed`.

**Прецедент `4693688` этого не проверяет и проверить не мог** — его собственное тело
говорит прямо:

> Два пути ждали founder-решения и **не существовали на main**:
>   `milestones/M-60-mechanisms.md` → `docs/archive/…`, `scripts/verify_M-60.sh` → `docs/archive/…`

Файлов на `main` не было ⇒ удалять было нечего ⇒ барьер не срабатывал. То же верно для
второго, не названного в Р-2 прецедента — `31c2626` (`docs/archive/M-10-obi-killscreen-retired-2026-07/`),
там материал тоже пришёл с мёртвой ветки. **Прецедент есть у формы врезки, но не у
прохождения гейтов.** Строка §6 обязана назвать оба токена.

### §4.2. Вынос спеки СОКРАЩАЕТ универсум аллокатора номеров — это регресс живого барьера

`check_artifact_ids.sh` и `next_artifact_id.sh` считают занятость по БЕЛОМУ СПИСКУ путей:

```

`docs/archive/**` в белом списке отсутствует. Значит **30 вынесенных спек перестают
занимать свои номера**: барьер больше не покраснеет на новом `milestones/M-45-*.md`, а
`next_artifact_id.sh M` (max+1) перестанет их видеть. Сегодня ущерб нулевой — максимум

УНИКАЛЕН», и вынос его молча ослабляет. Развязка дешёвая: добавить `docs/archive/M-*.md` в

### §4.3. «Прочие упоминания безвредны» (Р-2 §3.2) — **неверно**: греп шёл не по тем путям

Р-2 §3.2 объявил единственной живой связью `check_context_budgets.sh:19` → `M-60b`.

```

**Из 30 кандидатов на вынос ссылки несут восемь:** `M-17`, `M-22`, `M-35`, `M-45`, `M-48`,
`M-49`, `M-50`, `M-62`. Это не исполняемые зависимости (комментарии), поэтому вынос ничего
не сломает — но каждая ссылка ОБЪЯВЛЯЕТ гейт названным сторожем инварианта, и после

входа. Вынести его в архив, оставив строку как есть, — это «built-not-wired» наоборот:
контракт заявлен, проверяющего нет.

**Что это меняет в списке:** ничего — все восемь остаются в ВЫНОСИТЬ. Но норма §6 обязана
требовать, чтобы коммит переезда **в том же диапазоне** переписал ссылку (на архивный путь
либо на живой оракул), а не оставлял висеть. Иначе Р-2 своими руками производит ровно тот
дефект, который `TD-138` описывает для `docs/fa/journal.md`: документ обосновывает
инвариант механизмом, которого больше нет.
