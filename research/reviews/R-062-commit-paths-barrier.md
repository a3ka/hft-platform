## §3 Сценарий 8 (анти-плацебо) — не декоративен

Читается прямо: строка 197 `rm -f "$S/hooks/pre-commit"` снимает хук, ассерт требует
`RC=0 && HEAD сдвинулся && файлов=3`. Проверено, что он ловит молчаливо несостоявшийся setup:
в копии пробы нейтрализован `dirty_index` (return 0 первой строкой) —

```
PASS  NOPATHS: `git commit` без путей отвергнут (exit=1) …   ← зелен ПО ЧУЖОЙ ПРИЧИНЕ
                                                                (nothing to commit)
FAIL  NOHOOK: exit=1 … Если без хука форма НЕ проходит, сценарий 1 зелен по чужой причине
VERDICT: FAIL (3 нарушений из 8 сценариев)   exit=1
```

Ровно заявленный механизм: сценарий 1 остаётся «зелёным» на пустом индексе, и единственный,
кто это ловит, — сценарий 8.

## §4 Формы вызова — своя песочница, наблюдение `GIT_INDEX_FILE` логирующей обёрткой

| форма | rc | HEAD | файлов | GIT_INDEX_FILE (basename) |
|---|---|---|---|---|
| `git commit` (грязный индекс) | 1 | на месте | — | `index` |
| `git commit -- tracked.txt` | 0 | сдвинулся | 1 | `next-index-<pid>.lock` |
| `git add new.md && git commit -- new.md` | 0 | сдвинулся | 1 | `next-index-<pid>.lock` |
| `git commit -a` | 1 | на месте | — | `index.lock` |
| `git commit --amend -m` (staged пуст) | 0 | сдвинулся | — | `index` (ранний выход по пустому staged) |
| merge `--no-ff` | 0 | сдвинулся | — | хук не вызывается |
| `git commit -- 'has space.txt'` | 0 | сдвинулся | 1 | `next-index-*.lock` |
| из подкаталога без путей | 1 | на месте | — | `index` |
| из подкаталога `-- inner.txt` | 0 | сдвинулся | 1 | `next-index-*.lock` |
| `git commit --only tracked.txt` | 0 | сдвинулся | 1 | `next-index-*.lock` |
| `git commit --include tracked.txt` | 1 | на месте | — | `index.lock` — отвергнут, и это ВЕРНО: `--include` берёт весь индекс плюс названное |

Белый список `next-index*` подтверждён УЗКИМ: `commit -a` идёт под `index.lock` и отвергается;
`--include` — тоже `index.lock`, отвергается. Утверждение правки «`commit -- <новый>` без
`add` падает» проверено: `error: pathspec … did not match any file(s) known to git`, rc=1.

Состояния sequencer'а (защита строк 24-26 хука): cherry-pick с конфликтом → разрешение →
голый `git commit` rc=0 (CHERRY_PICK_HEAD); `git revert --continue` rc=0; `git rebase
--continue` rc=0. Всё проходит.

## §5 Адверсарное расширение (обязанность по A-008 §3) — найдено

1. **`git commit -- .` ПРОХОДИТ и берёт весь индекс** (rc=0, оба грязных файла в коммите;
   `next-index-*.lock`). То же — `git commit -- '*'` и `git commit -- ':/'`. Формально это
   «явный путь», фактически — весь индекс одним символом: тривиальный обход ДУХА барьера при
   соблюдении буквы. Отличие от `--no-verify`: `--no-verify` — осознанное имя обхода,
   `-- .` выглядит невинно. Нигде не назван: ни в хуке, ни в правке правил, ни в сообщении
   коммита. → **NOTE-1**, см. ниже.
2. **`git merge --squash` + `git commit` ОТВЕРГАЕТСЯ** (rc=1): `--squash` не создаёт
   `MERGE_HEAD`, защита слияний не срабатывает, а staged — весь squash-набор. Ложноположительный
   на легитимной (в этом репо нештатной — reviewer мержит `--no-ff`) операции; лекарство
   существует (`--no-verify` осознанно). → **NOTE-2**.
3. **`GIT_INDEX_FILE=…/next-index-evil.lock git commit`** — обходит (rc=0, 5 файлов).
   Класс осознанного обхода, тот же, что `--no-verify`; контур объявлен предупреждающим —
   приемлемо, фиксирую для полноты.
4. `git commit --amend` при НЕПУСТОМ staged — отвергается (`index`, rc=1). Это ПО ДЕЛУ:
   staged вливается в переписанный коммит — та же опасность; лекарство работает:
   `git commit --amend -- <путь>` прошёл (rc=0, `next-index-*`).

Не найдено ни одного входа, где барьер молча ПРОПУСКАЕТ случайную (не требующую намеренного
набора) опасную форму — дыры пп.1 и 3 требуют нетипичного набора, п.2 — ложное срабатывание,
не пропуск.

- **NOTE-3:** заголовок раздела остался «Запрет `commit -a` / `add -A` **в общем чекауте**»,

  `MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD`/`REBASE_HEAD` (строки 24-26). Код прав,
