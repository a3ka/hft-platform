## §2. В-1 — `C-320` Б-1 верна по факту

Стенд (`§6`, скрипт в scratchpad, в коммит не входит): копия формы `PS` — индексы 1…3001, `.zst` у
1…1650, `.jrnl` у 26…3001, два sidecar'а (`journal.legacy.json`, `journal.replay-digest.json`);
листинг **108 419 байт**, за буфером канала. Кандидат — копия `deploy/bin/journal-restore-drill-cron.sh`
с вершины плюс РОВНО страж `want=0` (7 строк диффа) — то, что `C-320` называл conforming-копией.
Подменный `cp`: настоящая копия, на 4-м вызове (последняя сегментная форма — `segment-00003001.jrnl`)
накладывает `prlimit --fsize=16384 --pid $PPID`; `SIGXFSZ` проигнорирован (`trap '' XFSZ`), как в `MF`.
Читатель — заглушка, записывающая содержимое `--dir`.

```text
listing_bytes=108419 names=4628
wrapper_rc=0
state={"ok":1,…,"checked":3,"events_read":7,"digest":"0123…cdef","reason":""}
restore_segments=4  restore_sidecars=0
reader_called=yes
stderr: cand-want0.sh: line 284: cannot create temp file for here-document: No space left on device | … line 306 …
limiter=applied cp_calls=4
```

Сегменты доставлены все четыре, sidecar'ы — ни один, `ok=1`, `checked=3`, читатель вызван. Это
нарушение `M-99` §4(2) («каждый sidecar корня копии восстанавливается побайтно») и `A-055` §5.2
(неполная доставка не есть `ok=1`). Текущая реализация (M1b) — тот же исход; контроль без
ограничителя (M1c) — `restore_sidecars=2`. **Б-1 подтверждена, стенд `C-320` воспроизводим независимо.**

Второй факт, решающий для §3: провал here-string **неотличим по статусу** от честного «нет совпадения»:

```text
grep -qx -- '<имя>' <<<"${big}"   (155 999 байт, ulimit -f 16)  → member_status=1
x="$(grep -E '^[^/]+\.json$' <<<"${big}")"                        → subst_status=1 subst_len=0
grep -qx -- 'absent-name' <<<"abc"  (честное «нет»)               → honest_no_match_status=1
grep -qx -- 'x' /nonexistent        (ошибка самого grep)          → grep_error_status=2
```

bash отдаёт `1`, а не `2`: проверить `$?` после here-string недостаточно — никакая правка ветвления
вокруг `<<<"${LISTING}"` класс не закроет. Это и есть основание требовать смену механизма (N1), а не
третий страж.

## §3. В-2 — класс K и его полный состав в обёртке (вершина `48812a69`)

### 3.1. Определение

**K — «пустота производного множества благоприятна».** Обёртка выводит из внешнего механизма
производное множество или наблюдение (членство имени, список sidecar'ов, пустота каталога, список
индексов) и ветвится так, что ПУСТОЙ результат ведёт в благоприятную ветку — пропуск, «нечего
делать», засчёт, продолжение к читателю, — при этом отказ механизма даёт тот же пустой результат.
Architect назвал класс как «потребитель `LISTING` через механизм, чей отказ неотличим от пустого» —
верно, но узко: клетка K3 не читает `LISTING` вовсе, а в класс входит по тому же признаку.

### 3.2. Состав — замером, каждая клетка строкой обёртки

| клетка | строка | механизм | отказ → | исход на вершине | замер |
|---|---|---|---|---|---|
| **K1** членство формы в листинге | `:283` `grep -qx -- "$f" <<<"${LISTING}"` | here-string → временный файл | статус 1 = «имени нет» → форма не выбирается | без стража `want=0`: индекс засчитан, `ok=1` (`R-269` Б-1) | `MF` красный на вершине (§6); M2 |
| **K2** перечисление sidecar'ов | `:301-304` `done <<<"$(grep -E '^[^/]+\.json$' <<<"${LISTING}")"` | два here-string | пустой список → цикл не исполняется ни разу | `ok=1`, `checked=3`, sidecar'ов 0, читатель вызван | **M1/M1b** |
| **K3** наблюдение пустоты `RESTORE` | `:223` `[ -n "$(ls -A "${RESTORE}" 2>/dev/null)" ]` | подстановка `ls -A`, stderr глушится, статус не проверяется | пустой вывод = «каталог пуст» → проверка (д) пройдена | при неочищенном `RESTORE` (как в `SR`) + транспорт без байт: `ok=1`, `checked=3` на байтах прошлого прогона | **M4** (`ls -A` → exit 2 без вывода; `rm` без эффекта; `cp` без байт) |
| **K4** доставка sidecar'а | `:303` `fetch_one "${_sc_name}" \|\| {…}` без `[ -f ]` | декларация транспорта | «успех» без байт не замечен | `ok=1`, `checked=3`, `journal.legacy.json` в `RESTORE` нет | **M3** (подменный `cp` → 0 без копирования на одном sidecar'е); кандидат `want=0` — тот же исход |

K4 — не here-string, а «верим коду возврата выборки» — тот самый запрет §7 («судить доставку по коду
возврата выборки без наличия файла»), который для СЕГМЕНТОВ закрыт `DV`, а для sidecar'ов не исполнен
ни реализацией, ни эталоном пробы (`:681-683`, M7b). Включаю её в условие круга, потому что исход тот же
(`ok=1` без байт этого прогона), и потому что `C-320` п.3 условия («перечисление ИЛИ доставка хотя бы
одного sidecar'а не состоялась») её уже назвал.

**Эталонная обёртка пробы** (`make_reference_wrapper`): K1 — here-string `:669`, но под стражем `want=0`
(fail-closed); K2 — перечисление `for side in $(printf … | grep -E …)` `:681` конвейером без раннего
выхода — отказ даёт пустой список молча (под ограничителем M7 она прошла честно, потому что конвейер
временного файла не создаёт — это удача механизма, не норма); K3 — `:629` та же подстановка `ls -A`;
K4 — `:682` без `[ -f ]` → **M7b: `ok=1` при одном sidecar'е из двух.** Эталон нормы не исполняет и
обязан быть приведён к ней (`A-056` §4.2 п.5 — прецедент: эталон, проваливающий новый мир, делает пробу
несамосогласованной).

## §4. В-3 — норма, закрывающая K за один круг, и минимальный оракульный состав

### 4.1. Норма (ОТ РЕЗУЛЬТАТА; форма реализации — за architect'ом/engine-dev)

**N1. Механизм с отличимым отказом, статус проверяется.** Любое решение обёртки, производное от
`LISTING` (членство, список sidecar'ов, индексы) или от наблюдения каталога (`RESTORE` пуст),
принимается механизмом, у которого отказ даёт результат, ОТЛИЧИМЫЙ от пустого (ненулевой статус,
отличный от «не найдено»; либо встроенный в оболочку, без внешнего процесса и временного файла), и
статус этого механизма проверяется явно: отказ ⇒ `alert`, `write_state 0 0 "" "transport-failed"
<checked>`, `exit 5`, читатель не вызван. **Here-string и here-doc над `LISTING` (`<<<`, `<<`)
запрещены** — строкой §7 рядом с запретом конвейера: M2 показал, что их провал неотличим по статусу.
Допустимые формы (примеры, НЕ предписание): одно чтение `LISTING` в массив через подстановку
процесса или канал с `lastpipe` и проверкой статуса `mapfile`/`read`, дальше — `case`/`[[ ]]`
по массиву без внешних процессов; наблюдение каталога — `ls -A` с проверкой `$?` (пустой вывод при
статусе 0 — пусто; статус ≠ 0 — отказ, не пустота).

**N2. Пустота производного множества не благоприятна без положительного установления.**
(а) выбранный индекс с нулём форм — `transport-failed` (уже есть, `MF`); (б) число sidecar'ов,
полученное основным механизмом, сверяется с НЕЗАВИСИМЫМ счётом `.json`-имён в `LISTING` вторым
механизмом (например, конвейер без раннего выхода, печатающий число — `grep -c` печатает `0`, а при
отказе не печатает ничего: пустой вывод ≠ «0»); расхождение или нечисловой результат ⇒ `transport-failed`/5.
**Ноль sidecar'ов — законный мир ТОЛЬКО когда оба механизма независимо дали 0.** Основание: `M-74`
`:564` «берётся то, что в копии ЕСТЬ» наследуется (`M-99` §3); §4(2) усиливает только побайтность
каждого присутствующего, не вводит минимум. Поимённый минимум («`journal.legacy.json` обязан быть»)
НЕ вводится: он привязал бы drill к составу offsite-выгрузки — это состав данных, граница C, и
прод-читатель на пустом манифесте читает (`C-219` B-2, `M-74` `:170-175`). Прод-форма (две
записи — `M-99` §2 п.1, `R-268` §3) живёт в ФИКСТУРЕ пробы, а не в коде обёртки.
(в) пустота `RESTORE` — только при статусе 0 наблюдателя (N1).

**N3. Каждый доставляемый файл судится наличием.** Для sidecar'а — то же, что §4 стр.12 (в) для
