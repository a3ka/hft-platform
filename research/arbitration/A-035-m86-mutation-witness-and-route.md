## §2. ВОПРОС 2 — КЛАСС ДЕФЕКТА: КОНСТРУКЦИОННЫЙ

### 2.1. Диагноз

Класс — **PASS, произведённый свидетелем, который наступает и без выполнения условия.**
Три экземпляра `M-86` — две его формы:

| форма | экземпляры | почему свидетель неспецифичен |
|---|---|---|
| **инвертированная полярность** — успех шага выводится из СИГНАЛА ОТКАЗА | `! grep -qE …` (круг 2, шаг F); `cargo test` exit≠0 в мутанте (круг 3, H/H2; корпус — `M-68:94`, `M-71:219-221`) | отказ имеет МНОГО причин (нет строки / нет файла / не собралось / упал чужой ассерт), а сигнал один — Ф-3: `101 == 101` |
| **слабый позитивный свидетель** — присутствие признака, не привязанного к предмету | `grep -q 'диапазон'` (круг 2, шаг G) | признак встречается у другого предмета в том же файле |

Это КОНСТРУКЦИЯ, а не дисциплина, по четырём основаниям: (а) Ф-4 — та же форма у трёх
скриптов и разных дат; (б) Ф-3 — инструмент не даёт различающего кода, то есть «внимательный
автор» не имел бы, что читать; (в) Ф-5 — helper'а нет, каждый пишет заново; (г) Ф-6 — автор,
ловящий два экземпляра сам, воспроизводит третий: внимание класс не закрывает.

### 2.2. Противоречат ли `gates.md` §3 и `testing.md` св. 3 — НЕТ по существу, ДА по букве

`gates.md` §3 («решение по КОДУ ВОЗВРАТА, а не по тексту вывода») написан против одной
опасности: текст МАСКИРУЕТ отказ (`cmd && echo PASS || echo FAIL`, `gate | grep PASS`).
Это норма ПРЯМОЙ полярности: ненулевой код обязан ОСТАНОВИТЬ. В мутационном шаге полярность
обратная — ненулевой код есть ЖЕЛАЕМЫЙ исход, и норма §3, применённая буквально, делает код
возврата ПОЗИТИВНЫМ доказательством, которым он быть не способен (Ф-3). `testing.md` св. 3
(«падает против сломанного И против несостоявшегося setup — setup-guard на каждый сценарий»)
говорит ровно об этом и ничего не отменяет в §3.

**Развязка (BINDING для сторон, проверяема прогоном, а не советом):**

> Код возврата решает ОТКАЗ гейта. УСПЕХ инвертированной проверки доказывается ДВУМЯ
> свидетелями в ОДНОМ мутантном дереве: **W1 — мутант СОБРАЛСЯ** (`cargo test --no-run`
> exit=0, либо названный тест-сосед в мутанте ЗЕЛЁН); **W2 — именованный тест упал СВОИМ
> диагнозом** (`test result: FAILED` + строка диагноза оракула, напр. `V1 НАРУШЕН (\`VB-I-10\`)`).
> Плюс **W0 — базовая линия**: тот же тест на НЕМУТИРОВАННОМ дереве в том же прогоне ЗЕЛЁН.
> Отсутствие любого из трёх — FAIL с названием отсутствующего: «baseline RED — мутация не
> судима», «мутант не собрался», «упал, но не своим диагнозом».

Сверка W2 по тексту — НЕ то, что запрещает §3: там текст ЗАМЕНЯЛ код и мог спрятать
отказ; здесь текст — ДОПОЛНИТЕЛЬНОЕ необходимое условие поверх кода, и решение остаётся
fail-closed (все три обязаны сойтись). Следующему критику это названо здесь, чтобы ремонт
не был отклонён под §3.

Условие снятия `C-231` этим принято целиком и уточнено: для H — W2 отдельно для `V1`
(`red_vp_bin_width_size`) и для оракулов сетки (`V2`/`V2-b` по диагнозу, не «весь бинарь»),
плюс `v6_grid_aligned_input_passes_through_unchanged` ЗЕЛЁН в мутанте (он же — W1);
для H2 — диагноз `V1 НАРУШЕН (\`VB-I-10\`): в кадре 2 строк`. На plan-time RED-head оба
шага обязаны печатать FAIL «baseline RED — мутация не судима» — это честный ожидаемый RED.

### 2.3. Механизм, закрывающий КЛАСС (три слоя, по убыванию обязательности)

**M1 — helper, обязателен (architect, зона `scripts/lib/**`).** `scripts/lib/mutation_gate.sh`
с функцией вида `mutant_must_fail <mut-dir> <pkg> <test-bin> <test-name> <diag-regex>
[<must-stay-green>…]`, исполняющей W0→W1→W2 и печатающей все три свидетеля сырыми строками.
Форма `if (cd MUT && cargo test …); then FAIL else PASS` в `verify_*.sh` с этого решения
**запрещена** — только через helper. `verify_M-86.sh` H/H2 переводятся на него в шаге 2 §1;
`verify_M-68.sh:94` — ретрофит харнесс-треком, не блокируя `M-86`; `verify_M-71.sh` по
существу соответствует (W1 через `MUT_E=0`), мигрирует при ближайшем касании. Помещение в
`scripts/lib/` — не оформление: helper есть единственное место, где класс закрывается ОДИН
раз, а не в каждом скрипте заново (Ф-5).

**M2 — lint-барьер, харнесс-трек (кандидат, не изображается сделанным).**
`scripts/check_verify_form.sh` + проба `scripts/tests/red_verify_form.sh` + джоб в агрегате:
в `scripts/verify_*.sh` краснеет (а) `cargo test` внутри `if (`/`elif (`/`|| VAR=1` вне
helper'а; (б) `! grep -q` на пути к `PASS`; (в) PASS-ветка в `else` условия с `cargo test`.
**Предел назван:** это эвристика по НАШИМ идиомам, ловит три известных формы, ложноотрицательна
к новым; барьер — трипвайр, не доказательство. Форма (`grep -q '<одно слово>'`, шаг G) лintom
не ловится — там закрывает только правило «якорь = идентификатор предмета», уже исполненное.
Маршрут — `harness-track.md` §3 с адверсарием.

**M3 — текст норм (рекомендация founder'у; зона §11, `FOUNDER-APPROVED` обязателен).**
