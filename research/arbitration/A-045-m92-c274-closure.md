## 3. Вопрос 2 — `I-2bis` обоснована; замер подтверждён и расширен

**Замер (временный тест в своём дереве, удалён; Done Block §7):** журнал фикстуры — шесть
сегментов `[0..5]`, 900 событий; удалены `segment-00000001`/`-00000002` (старейший оставлен):

```
PROBE stream(): events=562 seq_gaps=1 at=[(172, 511)] item_errs=0
PROBE read_all(): Ok, events=562
PROBE recover(): Ok, events=562
```

Утверждение architect'а («562 события, один разрыв, без ошибки») воспроизведено ТОЧНО. Но оно
было заявлено только про `stream`; на деле `read_all` и `recover` ведут себя так же — **ни
один публичный читатель журнала не замечает дыру между сегментами**. `JR-I-2` обещает «разрыв
при чтении → abort»; `JR-I-11` проверяет МОНОТОННОСТЬ порядка `first_seq`, а не СПЛОШНОСТЬ.
Это пред-существующий пробел FA/оракулов вне периметра M-92 — NOTE reviewer'у (§6 N-1), не
блокер: M-92 не создаёт дыру, а правкой `I-2bis` впервые гарантирует, что уборщик её не
создаст.

**Почему правка обоснована, а не косметика.** Прежний `I-2` («совпавшие старше несовпавшего
удаляются») при испорченной копии СТАРЕЙШЕГО кандидата оставлял его и удалял младших —
ровно каталог из замера. Раз читатели дыру глотают, единственная защита — не создавать её:
удаление ПРЕФИКСОМ по возрастанию индекса с обрывом на первом неподтверждённом. Это
удаляет ПОДМНОЖЕСТВО того, что позволял `I-2`, — строго консервативнее для данных.

**Не ослабляет `A-044`:** O-1/O-2/O-3 не тронуты (ассерты `c1`/`c4`/`c5` на месте и
расширены); сдвиг жертвы на САМОГО МОЛОДОГО кандидата (`p2`/`p3` `next_back()`, `b2`
`max()`, `c1`/`c4` `next_back()`) сохраняет смысл сценариев (все прочие удалены, жертва
удержана, `exit 2`) и предпосылку O-2 «после первого прогона остаётся только несовпавший» —
подтверждено прогоном `c4` (§2). `p8`/`p9` закрывают оси «старейший» и «средний»;
`assert_contiguous` — наблюдение инварианта, а не форма реализации.

**Не противоречит §4 п.4:** строка `kept <имя> blocked-by <имя>` имеет непустую причину;
формат «одна строка на имя» выдерживается — младшие за обрывом получают СВОЮ строку. На
уровне `c*` форма `blocked-by` в отчёте скрипта не наблюдается (в `c1`/`c4` жертва младшая —
обрыва нет); она закреплена на уровне библиотеки `p8` (`why.contains("blocked-by")`) —
названный предел, не требование.

**Названный предел (операционный, не дефект):** одна испорченная СТАРАЯ копия блокирует
ВСЁ удаление до починки — fail-closed с тревогой (`exit 2`). Оператору нужна процедура
«перезалить названный файл на коробку» (`rsync --checksum` по имени; обычный `rsync` не
перезальёт файл той же длины и mtime). Место — `deploy/README.md` (зона dev задачи 3, рядом с
`A-044` L-9).

Коммит engine-dev `6003fe3` (не предмет): сортировка по `SegmentInfo.index`, обрыв по
четырём исходам, `blocked-by` и в `DryRun`; `p1`–`p9`, `b1`–`b2` зелены (§7). Судит tester →
reviewer по §12 спеки.
