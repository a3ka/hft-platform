## §4. В-2 — что обязан покрыть набор

### 4.1. Что обёртка ОБЯЗАНА делать — по спеке, не по вкусу

Из уже объявленного: (а) `M-74` §«Сигнатура читателя»: «stdout при успехе — ОДНА строка JSON»
с шестью полями, `digest` 64 hex; код `0` = «открыт, прочитано ≥ `--min-events`, непрерывность
внутри сегментов держится»; (б) T2: `digest` обязателен при `ok=1`, `reason` обязателен при
`ok=0`, «классы причин обязаны РАЗЛИЧАТЬСЯ»; (в) `M-74` §«Контракт обёртки», обязанность 3:
«взять `events_read` и класс отказа ИЗ ВЫВОДА и КОДА читателя, а не сочинить»; (г) `M-99` §7:
«писать `ok=1` без `digest`» запрещено; (д) `M-99` §5: потребитель отвергает `ok=1` без 64
строчных hex.

Следствие, которое спека уже содержит, но не произносит: **`ok=1` пишется ТОЛЬКО при `rc=0` И
полном протоколе успеха** — `digest` ровно 64 строчных hex, `events_read` ≥ 1 (число, поле есть),
`intra_segment_continuous` = `true` (поле есть). Любое иное при `rc=0` — ПРОТИВОРЕЧИЕ ЧИТАТЕЛЯ
(код говорит «успех», вывод его не подтверждает): обёртка не вправе сочинить ни успех (`ok=1`),
ни чужой класс (`reader-rc-4`, `intra-segment-gap` — читатель этого не говорил). Пишется `ok=0`,
`digest=""`, `reason` НОВОГО класса — «читатель нарушил протокол успеха», — `exit ≠ 0`.
`intra_segment_continuous=false` при `rc=0` остаётся отдельным классом `intra-segment-gap`
(`M-74` «Дополнительный fail-closed»): там читатель дыру НАШЁЛ.

Чего спека НЕ называет и что architect обязан ОБЪЯВИТЬ (строка 11 таблицы §4 `M-99` — «было:
`ok=1` при `rc=0` независимо от полноты вывода / стало / почему: `R-266` Б-1, `A-056` §3»):
литерал `reason` нового класса и код выхода обёртки. Код — архитекторский выбор; условие одно:
объявлен И судится оракулом (`A-055` §5.1: `T` не судил причину и код — и мутант «cold-empty/7»
проходил). Рекомендация, не условие: не переиспользовать `4`/`5`, уже означающие «читатель
вернул Err» и «пустота/транспорт».

### 4.2. Оракул — требования от результата

1. **Новый сценарий пробы (семейство `RP`) с ЗАГЛУШКОЙ читателя через шов `JOURNAL_DRILL_READER`.**
   Это не противоречит `M-74` «проба подставляет прямой прод-читатель, не заглушку»: та норма
   держит доказательство ЧТЕНИЯ (`H`/`D`/`R`), а `RP` судит ОБЁРТКУ на выводе, которого
   прод-читатель не производит никогда (`format!("{:x}")` → всегда 64 строчных hex). Сценарии с
   прод-читателем не меняются. Setup-guard: заглушка ВЫЗВАНА (маркер, который кладёт сама
   заглушка) — иначе `SETUP`, не `PASS`.
2. **Формы входа — все семь строк §3** (пустой / 63 / заглавные / не-hex `digest`; нет
   `intra_segment_continuous`; stdout не JSON и stdout пуст; `events_read=0` и поле отсутствует).
   Для каждой: `ok=0`, `digest=""`, `reason` = объявленный литерал, `rc` = объявленный код,
   состояние ЗАПИСАНО (не отсутствие файла — `T-M` «состояние-не-записано» образец).
3. **Позитивный контроль ТОЙ ЖЕ заглушкой:** полный протокол с заглушечным `digest` ⇒ `ok=1`,
   `digest` побайтно = заглушечному, `rc=0`. Без него пойманные мутанты ничего не значат
   (`RW-M SETUP`-образец) — и он же доказывает, что `digest` берётся У ЧИТАТЕЛЯ.
4. **Один судья** (`rp_judge`, по образцу `t_judge`) и **самопроверка `RP-M`** на синтетических
   кортежах — на каждом прогоне, не однажды.
5. **Эталонная обёртка пробы `make_reference_wrapper` приводится к §4.1.** Сегодня она проваливает
   все семь форм (§3) — то есть позитивный контроль пробы сам нарушает T2-писателя; на дереве без
   прод-обёртки `RP` краснел бы на эталоне. Эталон обязан проходить `RP`, иначе проба
   несамосогласована (`M-74` §«Эталонная обёртка»: «если эталон проходит все сценарии, а атаки
   краснеют, значит различающая сила есть»).

**Мутанты, каждый пойман НАЗВАННЫМ признаком (таблица §8 `M-99`, прогоном):**

| мутант | ловит |
|---|---|
| сегодняшняя прод-обёртка (`ok=1`, `digest=""`, `reason=missing-digest-on-success`, `rc=4`) | `ok=1` |
| сегодняшний эталон пробы (`ok=1`, `reason=""`, `rc=0`) | `ok=1` |
| `ok=0`, но `reason=reader-rc-4 …` или `intra-segment-gap` при отсутствующем поле | литерал причины |
| `ok=0`, верная причина, `exit 0` | код |
| `ok=0`, верная причина, но `digest` пробросан из неверного вывода (заглавный) | `digest=""` |
| `ok=1` при `events_read=0` / без поля при `rc=0` | `ok=1` |
| состояние не записано (обёртка упала до `write_state`) | состояние записано |
| заглушка не вызвана (прод-читатель подставлен обратно) | SETUP-guard |
