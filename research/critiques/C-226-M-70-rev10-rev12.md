# C-226 — M-70 rev10–rev12: `task #7` does not enforce the narrow default

## Verdict: REJECT

The three revisions are audited as one subject: `af16be5` (rev10), `c8e9f4a`
(rev11), and `e6f2e73` (rev12). The verdict blocks merge only until the
rev12 change to task #7 is made internally consistent and its acceptance
guard measures the new requirement.

## B-1 — `task #7` accepts a wide production default while claiming it is narrow

**Requirement.** Rev12 redefines task #7: the production default must remain
exactly narrow (`0.001`) in both compose consumers; any wider set is deferred
until the hollow-window measurement. This is explicit in
`milestones/M-70-depth-bands-enablement.md:793` and `:1003-1018`.

**Defect.** The guard checks only that `0.001` is present and that none of the
*seven canonical* values is present. It does not parse the default nor require
that it contain one value. Thus `${GATEWAY_BANDS:-0.001,0.02,0.04}` passes:
it enables two deep, non-canonical bands now, before the measurement, while
the gate prints `прод-дефолт узкий`.

- `scripts/verify_M-70.sh:358-374` implements that incomplete predicate.
- `scripts/verify_M-70.sh:310-326` correctly names the new subject, but the
  declared A-031 header is still the superseded subject — “canonical set
  reached the service”, YAML plus seven values — at `:40`.
- The synthetic `DB-I-7` tests only prove that an explicitly supplied
  canonical environment reaches the selector/wire; they do not bind the real
  compose default to `[0.001]` (`crates/gateway-serve/tests/red_depth_bands_delivery.rs:81-89`).
- The unmarked carrier in the milestone's A-031 table still says task #7 is
  “canonical composition reached the service” and requires seven values
  (`milestones/M-70-depth-bands-enablement.md:895-900`). A second carrier
  states that the checkpoint default is canonical (`:951-956`), contradicting
  rev12's current `${GATEWAY_BANDS:-0.001}`. These are exactly the prior
  “correct the named occurrence, leave the class” failure mode.

**Reproduction.** Applying only the above default mutation in memory to the
predicate copied verbatim from `verify_M-70.sh:343-374` returned PASS:

```text
task-7 predicate: PASS
      GATEWAY_BANDS: ${GATEWAY_BANDS:-0.001,0.02,0.04}
```

The current three historical mutations establish that the former guard was
weaker than the old requirement, but do not cover the new rev12 failure mode:
`0.001` plus arbitrary deep bands. `DB-I-7` remains a valid delivery oracle;
it is not a substitute for an oracle/guard of the actual compose default.

**Condition to clear.** Have the architect make the task #7 requirement,
A-031/header/table, and acceptance predicate agree. The predicate must reject
any default other than the sole narrow band, and must demonstrate that mutation
alongside its existing positive control. Preserve the superseded historical
claims as explicitly marked history rather than silently deleting them.
