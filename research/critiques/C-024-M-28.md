## Blocking Findings

### B1 — `Cargo.lock` is missing from the committed artifact set

`crates/gateway-serve/Cargo.toml` adds a new workspace crate and the new dependency `jsonwebtoken`, but
`Cargo.lock` is not committed in the branch diff. On a clean checkout, locked metadata fails:

```text
cargo metadata --locked --format-version 1
error: cannot update the lock file .../Cargo.lock because --locked was passed to prevent this
exit=101
```

`cargo test -p gateway-serve --tests --no-run` mutates `Cargo.lock` by adding `gateway-serve`,
`jsonwebtoken`, and its transitive dependencies. Because `Cargo.lock` is tracked, the plan artifact set is
not reproducible as committed.

### B2 — Task #4 WS server has no RED/acceptance surface

M-28 objective and §Tasks include a real transport server:

- `milestones/M-28-gateway-serve.md:23` says the crate includes `Bin gateway-serve + lib`.
- `milestones/M-28-gateway-serve.md:71` assigns task #4: WS server
  `accept→verify JWT→snapshot+incremental+replay`.
- `milestones/M-28-gateway-serve.md:72` assigns task #5: integration WS handshake smoke.

But the committed artifacts contain only:

```text
crates/gateway-serve/src/lib.rs
crates/gateway-serve/tests/red_jwt_verify.rs
crates/gateway-serve/tests/red_serve_passthrough.rs
```

There is no bin/server skeleton, no WS-facing API under test, and `verify_M-28.sh` only prints a note that
WS server + smoke are integration work. That leaves task #4 without a failing specification and leaves the
acceptance script without a real check for the primary milestone behavior.

This violates RED-first and the acceptance-script rule that the milestone gate has at least one check per
task class before dispatch.

### B3 — Engine-dev ownership for `crates/gateway-serve` conflicts with binding scope tables

The milestone grants engine-dev implementation rights to `crates/gateway-serve/src/**`:

- `milestones/M-28-gateway-serve.md:57-59`

The binding scope sources do not grant that path:

- `.claude/rules/scope-guard.md:12` lists engine-dev crates through `gateway`, but not `gateway-serve`, and
  forbids other crates outside the list.
- `docs/04-workflow.md:21` lists engine-dev crates and also does not include `gateway` or `gateway-serve`.

Dispatching engine-dev to M-28 tasks 2-4 as written would create a scope-guard conflict before code work
starts.
