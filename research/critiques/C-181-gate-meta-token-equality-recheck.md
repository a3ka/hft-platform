# C-181 — адверсарий, круг 2: фикс `C-180` Б-1 (`token_line_matches`, равенство первого поля)

**Предмет:** дельта `cc0472e..3b3cdb0` (один коммит `3b3cdb0`) на
`feat/gate-meta-terminal-token`: общий разбор `token_line_matches` для обоих пофайловых
токенов, сценарии `GM-48`/`GM-49`, правка чисел прозы. Круг 1 — `C-180` (REJECT, Б-1).

**Вердикт: NOTE — блокеров нет.** Б-1 закрыт по существу и предъявлен исполнением: оба моих
воспроизведения теперь красные, живые токены истории не сломаны, все оси разбора из п.3
мандата fail-closed. Две находки уровня N: проза `GM-49` приписывает красное не тому
механизму (N-1 — носитель ответа на п.4), и предел «путь с пробелом не открываем токеном
никогда» не назван (N-2, опционально).

---

## §1. Пять вопросов мандата — ответы исполнением

**1. Д-1 и Д-2 на `3b3cdb0` — моими командами.** Обе фикстуры пересобраны с нуля тем же
скриптом, что в `C-180`:
- Д-1 (путь соседа в ПРИЧИНЕ): `FAIL research/arbitration/A-018-m68.md … НЕ предок HEAD`,
  `NOTE research/critiques/C-100-a.md`, `VERDICT: FAIL (1)`, **exit=1**. Ложного аудит-следа
  для неназванного файла больше нет.
- Д-2 (два пути, причины ноль): `FAIL research/reviews/R-200-b.md`, `VERDICT: FAIL (1)`,
  **exit=1**. Существенная деталь — см. N-1: названный файл `C-100-a.md` при этом
  ОТКРЫВАЕТСЯ (`NOTE`), красное даёт только неназванный сосед.

**2. `ARCHIVED-VERDICT` не сломан.**
- Замер совместимости перепроверен НЕЗАВИСИМО: `git log origin/main --format='%B' | grep
  '^ARCHIVED-VERDICT: '` даёт ровно ДЕВЯТЬ уникальных строк; живой `token_line_matches`
  (извлечён `sed -n '/^token_line_matches()/,/^}/p'` из барьера `3b3cdb0`) совпадает на
  **9/9** — у каждого путь первым полем, порог причины проходится. Несущее утверждение
  автора подтверждено.
- Пиннинг сценариев жив и стал ОБЩИМ через разделённый парсер: мутация «порог снят»
  (MUT-B) роняет `GM-31` (archived) И `GM-43` (terminal); мутация «равенство снято»
  (MUT-C) роняет `GM-29` (archived) И `GM-44`+`GM-48` (terminal). `GM-28`/`GM-30` зелёные
  в baseline 56/56.

**3. Новая невыписанная группа в `token_line_matches` — НЕ НАЙДЕНА.** Юнит-пробы живого
кода (все — «как ожидалось», сырой вывод в Done Block):
- путь с ПРОБЕЛОМ: `p` режется на первом `[[:space:]]` ⇒ такой путь не совпадёт НИКОГДА —
  ложно-негативное направление (файл остаётся заблокирован), не дыра; см. N-2;
- ТАБ вместо пробела — работает (`[[:space:]]` покрывает); CRLF-хвост — работает (`\r`
  тоже `[[:space:]]`);
- путь в кавычках / с приклеенной запятой / лидирующий лишний пробел / пустой остаток
  после префикса — всё «не совпало», fail-closed;
- glob-символы в пути безопасны: все раскрытия закавычены (`"${p}"`, `"${want}"`),
  сравнение `[ = ]` литеральное.
Каждая расходящаяся ось закрыта В СТОРОНУ ЛОЖНОГО КРАСНОГО — правильная сторона ошибки.

**4. Причина из повторов ЧУЖОГО пути — ГРАНИЦА, не дыра.** Прямой ответ на вопрос автора,
с обоснованием в три шага:
1. Машинное свойство, ради которого чинили Б-1, — пофайловость — ДЕРЖИТСЯ: строка
   `ТОКЕН: A.md B.md B.md B.md` открывает ТОЛЬКО `A.md`; для `B.md` первое поле не
   совпадает (проба: rc=1). Один-строка-много-файлов и ложный аудит-след — ушли.
2. Порог никогда не проверял ИСТИННОСТЬ причины: 12 точек проходят его сегодня (проба:
   rc=0 — совпадает) — тот же принятый класс, что у `FOUNDER-APPROVED` («токен-ритуал…»,
   подделываемость названа). Чужой путь как причина не слабее этого базлайна.
3. Более того, чужой путь в причине — ЕСТЕСТВЕННАЯ честная форма: «терминальна по решению
   research/arbitration/A-018-*.md» — это ровно та причина, которую подсказка барьера и
   просит. Запрещать её значило бы красить честный токен.
**Но граница легитимна, только пока она НАЗВАНА, а сейчас проза утверждает обратное** —
это N-1 ниже. Условие: назвать границу строкой в комменте `token_line_matches` (сейчас
назван только повтор СВОЕГО пути) и убрать ложное утверждение из `GM-49`. Отдельной
проверки НЕ требуется — расширение поверхности здесь купило бы ложные красные на честной
форме причины.

**5. `GM-48`/`GM-49` — не вакуумны, но пиннят НЕ ТО, что говорят (GM-49).** Карта, снятая
тремя мутациями живого парсера (полный прогон пробы на каждую):

| мутация | упавшие сценарии |
|---|---|
| MUT-A: возврат подстроки+вычитания (исторический дефект) | GM-48, GM-49 |
| MUT-B: порог снят | GM-31, GM-43 — GM-49 ЗЕЛЁНЫЙ |
| MUT-C: равенство снято | GM-29, GM-44, GM-48 — GM-49 ЗЕЛЁНЫЙ |

`GM-48` пиннит равенство первого поля (падает под MUT-A и MUT-C) — честный анти-бланкет.
`GM-49` падает ТОЛЬКО под MUT-A: его красное производится тем же равенством на
неназванном соседе, к порогу оно отношения не имеет (MUT-B это доказывает). Как
regression-replay Д-2 он законен; как пин отдельного свойства — дубль GM-48 с неверной
атрибуцией. Это не блокер (сценарий различает исторический дефект), но проза — см. N-1.

## N-1. Проза `GM-49` и pass-сообщение утверждают свойство, которого у барьера НЕТ

**Где:** `scripts/tests/red_gate_meta.sh:1101-1103` (коммент «строка из ДВУХ путей без
причины не проходит порог») и `:1113` (pass-текст «два пути без причины порог не проходят:
повторы и соседние пути причиной не считаются»).

**Факт исполнением:** в фикстуре самого GM-49 (и в моём Д-2) названный файл
`C-100-a.md` ПРОХОДИТ порог — причиной служит путь соседа — и открывается (`NOTE`);
красное даёт исключительно пофайловость на `R-200-b.md`. «Соседние пути причиной не
считаются» — ложь: считаются (см. §1 п.4, это осознанная граница). Под MUT-B (порог
снят целиком) GM-49 остаётся зелёным — порог он не пиннит.

**Почему это стоит чинить:** ровно класс моих N-1/N-2 круга 1 — литерал/проза, живущие
отдельно от механизма. Следующий читатель возьмёт из pass-текста гарантию «нулевая
причина невозможна» и построит на ней рассуждение; граница из §1 п.4 при этом
задокументирована ложно — в обратную сторону.

**Условие снятия:** проза GM-49 (коммент + оба текста) говорит то, что происходит:
«токен открывает ТОЛЬКО названный файл; сосед остаётся красным; путь соседа при этом
служит причиной для названного — принятая граница (см. token_line_matches)»; в комменте
`token_line_matches` строка о границе «чужой путь в причине проходит порог — namеренно:
это честная форма цитаты решения» (формулировка автора). Сценарий менять не требуется.

## N-2 (опционально). Предел «путь с пробелом» не назван

`p="${rest%%[[:space:]]*}"` делает файл, чей путь содержит пробел, НЕОТКРЫВАЕМЫМ ни одним
токеном (ложно-негативное направление). В репозитории таких путей нет, конвенция их не
порождает; строка-оговорка в комменте функции достаточна, сценария не требую.
