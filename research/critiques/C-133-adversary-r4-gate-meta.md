## Б-1 (БЛОКЕР, гейт трека §5.2). `EXCL_MAIN=("^HEAD^1")` — несущий и НЕ запиннен: мутант выживает 44/44, на прод-форме даёт ложный КРАСНЫЙ

Изменение несущее — предъявлено исполнением на минимальной боевой форме. Все элементы
формы названы рутиной самим предметом: sync-merge — «рутина долгоживущего PR»
(`check_gate_meta.sh` §2bis), устаревшая база — замер `C-128` Б-1 (PR #56/#60):

```
фикстура fx-sync: B0 → ветка (работа, вердикт APPROVE ah=вершина) → main: чужой PR правит
  scripts/check_m99.sh → ветка: git merge main (штатный sync) → merge-ref; база события = B0
$ честный 1edd91e:  VERDICT: PASS — вердиктов проверено: 1;  exit=0     ← корректно
$ mutEXCL:          FAIL C-999-test.md: subject-lock — тронут класс «гейт»: scripts/check_m99.sh
                    VERDICT: FAIL (1);  exit=1                          ← ложный КРАСНЫЙ
```

**Почему существующие сценарии слепы.** `GM-16d` (устаревшая база) не содержит sync-merge:
main-сторона недостижима из `HEAD^2`, и при `TOUCH_TIP="HEAD^2"` исключение `^HEAD^1` там
не несёт нагрузки — сценарий зелен при любой его редакции. `GM-16g` содержит sync-merge, но
гоняется БЕЗ `mergeref` (якорь выключен по условию предмета). Ни одна фикстура не совмещает
устаревшую базу с main-контентом, достижимым из `HEAD^2`, — а ровно эта комбинация и есть
прод-форма `C-128` Б-1, ради которой якорь вводился.

   `own_bodies`. Форма решения (две фикстуры, одна параметризованная, или иной структурный
   сторож) — выбор architect'а, не мой.
2. Направления предъявлены сырым выводом в теле коммита: каждый мутант — какой сценарий

3. Согласованность `declared/executed` при изменении счёта (сторож работает, проверено
   ниже — п. 2 разбора).
