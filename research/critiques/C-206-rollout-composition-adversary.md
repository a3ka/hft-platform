## Б-1 (блокер). Джоб в `needs`, но НЕ в решении агрегата — красный барьер merge не держит

Шаг `status-check` работает под `if: always()`: он запускается независимо от исхода `needs`
и проваливается ТОЛЬКО если один из перечисленных в его теле `needs.*.result` не `success`.
`rollout-composition` в `needs` добавлен, в тело проверки — нет:

```
$ grep -c 'needs.rollout-composition.result' .github/workflows/ci.yml
0        # grep exit=1 — ноль совпадений; команда показана вместе с формой вывода (R-097 N-7)
$ grep -o 'needs\.[a-z-]*\.result' .github/workflows/ci.yml | sort -u | wc -l
14       # все остальные 14 джобов агрегата проверяются; rollout-composition — единственный, кто нет
```

Следствие: барьер красный → джоб failed → `status-check` всё равно печатает «All checks
passed» и выходит 0 → required check зелёный → merge проходит. Ровно класс «built-not-wired»,
против которого барьер написан, и ровно мандатный вопрос «зелёный агрегат при красном барьере
невозможен?» — ВОЗМОЖЕН. Утверждение тела `8bcfbd6` «включён в агрегат — значит расхождение
физически держит merge» ложно в решающей половине. Фикс — добавить
`needs.rollout-composition.result` в условие шага (одна строка).

## Б-2 (блокер). Декларация обещает то, чего механизм не держит: смена состава при ПРЕЖНЕЙ эпохе и ПРЕЖНЕЙ подписи — зелёная

Стаб S5 — compose и декларация синхронно расширены (один коммит правит оба места), эпоха и
подпись не тронуты:

```
compose:     L2DELTA_CAPTURE_SYMBOLS: BTCUSDT,ETHUSDT,SOLUSDT / EPOCH_ID: own-2026-09-m45-ethusdt
декларация:  l2delta_symbols: BTCUSDT,ETHUSDT,SOLUSDT / epoch_id: own-2026-09-m45-ethusdt / signature: П-026
```

Расхождения с обещаниями — три, все текстом самого предмета:

1. `docs/data-epochs.md` (текст под блоком): «сменить состав, не тронув эту декларацию,
   невозможно — а тронув, ты обязан назвать НОВУЮ эпоху и ПОДПИСЬ, КОТОРАЯ СОСТАВ РАЗРЕШИЛА».
   Механизм требует лишь РАВЕНСТВА эпох compose↔декларация и СУЩЕСТВОВАНИЯ названной подписи.
   Ни новизна эпохи, ни связь подписи с составом не проверяются нигде.
2. Комментарий проверки 2 барьера ссылается на E-001 («состав, сменившийся без смены эпохи»);
   S5 — буквально этот случай, и он зелёный. Проверка 2 ловит только разъезд двух файлов,
   не разъезд состава с эпохой во времени.
3. Автор назвал пределом «барьер не судит содержание подписи — только что ссылка не висячая».
   Предел назван УЖЕ, чем дыра: умолчана механизуемая половина — diff-связка
   «`l2delta_symbols` изменился против merge-base ⇒ `epoch_id` и `signature` обязаны
   измениться тоже». Она не требует зашитых символов (решение «без констант» не задевает) и
   строится на проводке, которая в том же workflow уже есть: `PR_BASE_SHA` использует
   `check_context_budgets.sh`. Семантику текста подписи механизм судить действительно не
   может — но заставить назвать НОВУЮ подпись может, и это разница между «аудит-след есть» и
   «аудит-следа нет вовсе».

Развязка — одна из двух, выбор architect'а: достроить diff-связку (тогда декларация говорит
правду), либо переписать текст декларации и комментарии барьера под реально держимое и
записать остаток риска явно. Сам состав записи и достаточность конструкции для границы C —

## Б-3 (блокер). Разбор декларации не fail-closed — один класс, три стаба

Контракт кодов в шапке барьера: «нет/дублируется блок декларации … → 2». Три мира, где
предмет НЕ установлен достоверно, а барьер отдаёт 0:

**S1 — блок не закрыт `-->`.** `awk` молча берёт всё до EOF (вся проза файла оказалась
внутри HTML-комментария — в рендере документ исчез), поля находятся, барьер зелёный:

```
epochs.md: <!-- ACTIVE-COMPOSITION … signature: П-026 … (закрывающего --> НЕТ)
→ PASS×3, exit=0        # ожидание по собственному контракту: setup_fail, exit=2
```

**S2 — дубль поля внутри блока.** `decl_field` берёт `head -1`; собственная философия
барьера («два = неизвестно, какой действует. Оба случая — отказ, а не выбор первого
попавшегося») применена к БЛОКАМ и не применена к ПОЛЯМ:

```
signature: П-026        ← судится этот, существует
signature: П-999        ← видимый человеку низ блока, НЕ существует
→ PASS×3, exit=0
```

**S3 — регексп-инъекция в сверку подписи.** `D_SIGN` интерполируется в ERE неэкранированным
(`grep -qE "^## ${D_SIGN}([^0-9]|$)"`); декларация, не называющая НИ ОДНОЙ подписи,
проходит на любом файле подписей с любым `## `-заголовком:

```
signature: .*   +   подписи: «## П-777 — подпись СОВСЕМ ДРУГОГО предмета»
→ «PASS  подпись .* существует в signatures.md», exit=0
```

Класс закрывается одним проходом: страж закрытия блока; страж единственности КАЖДОГО поля;
пин ФОРМЫ ссылки (`^П-[0-9]+$`) ДО подстановки в grep — он же убивает инъекцию. По Р-3
(`docs/workflow/oracle-blindness-class-2026-08-28.md` §5) каждый новый страж — со своей
фикстурой в пробе и мутацией, роняющей ровно его; иначе три новые проверки повторят судьбу
M6 (§5 ниже).

## Н — не блокеры

- **Н-1. CRLF — ложное красное с врущей диагностикой.** Честная декларация с CRLF → exit 1
  и «'BTCUSDT,ETHUSDT' НЕ РАВЕН объявленному ('BTCUSDT,ETHUSDT')» — значения визуально
  идентичны, различие — невидимый `\r` в хвосте (sed-паттерн ест whitespace после двоеточия,
  но не в конце значения). Ложное красное — находка не меньше пропуска (`testing.md`).
  Фикс: `tr -d '\r'` при извлечении `DECL`.
- **Н-2. Ветки `<ОТСУТСТВУЕТ>` (`:78`, `:90`) не запиннены ничем.** Мутация M6 (обе →
  `false`) оставляет пробу зелёной 15/15: их случаи ловит соседняя сверка равенства с ТЕМ ЖЕ
  exit-кодом. Дыры нет — исход эквивалентен, декларация не может честно объявить сентинель, —
  но это буквально класс из контекста трека («проверка, чьё снятие проба не замечает, потому
  что её случаи ловит соседняя»). Либо различить сценарии по СООБЩЕНИЮ, либо признать
  избыточность комментарием в коде — молчание оставляет мину следующему редактору.
- **Н-3. Мёртвая передача `COMPOSE_PATH="$COMPOSE"`** при вызове `--extract`: CLI переменную
  не читает (`grep -c COMPOSE_PATH scripts/lib/rollout_symbols_check.py` → `0`, exit=1 —
  единственное вхождение имени живёт в вызывающей строке барьера). Изображает контракт,
  которого нет.
- **Н-4. Будущий fenced-пример блока в `data-epochs.md`** даст `OPEN_N=2` → exit 2 —
  ложное, но ГРОМКОЕ красное (fail-closed). Приемлемая цена; стоит одной строки комментария
  у стража единственности.
- **Честно работающее — названо, чтобы фиксы не задели:** passthrough-ключ list-формы
  (`- L2DELTA_CAPTURE_SYMBOLS` без `=`, значение с хоста) краснит как отсутствие ключа
  (стаб S6, exit=1); `env_file` перекрыть literal-ключ `environment` не может по приоритету
  compose; YAML-anchors/merge-ключи разбираются честно (стаб A1, exit=0); два сервиса с
  одним `container_name` → exit 2 (стаб A2); обе формы подстановки и различающий сценарий
  равенства запиннены.

## N-5 — НОВОЕ (в изменённых строках): checkout джоба без `fetch-depth: 0` — связка умрёт setup'ом на КАЖДОМ PR

Дифф добавил джобу `env: PR_BASE_SHA`, но НЕ добавил `fetch-depth: 0` его checkout'у.
`actions/checkout@v4` по умолчанию даёт depth=1: на pull_request-событии в клоне есть только
merge-коммит, а `github.event.pull_request.base.sha` в объектах ОТСУТСТВУЕТ. Барьер теперь
делает `git rev-parse --verify "$BASE_SHA^{commit}"` → отказ → `setup_fail`, exit=2 → джоб
красный → (после фикса Б-1) агрегат красный. Исполняемое доказательство:

```
$ git clone --depth 1 file://<фикстура> shallow && PR_BASE_SHA=<база> bash барьер (в клоне)
rev-parse в shallow: exit=1
VERDICT: FAIL (setup)
exit=2
```

Соседи, читающие `PR_BASE_SHA` из того же workflow (`docs-freeze`, `gate-meta`), несут
`fetch-depth: 0` с комментарием ровно об этом классе («по умолчанию checkout даёт depth=1 …
гейт закроется»). Проба этот мир не ловит и не может: она гоняет полные локальные репозитории,
а дефект живёт в форме checkout'а CI (`testing.md` св. 1 — прод-форма; здесь прод-форма
шага воспроизводима только самим CI).

**Почему это НЕ повторный REJECT** (`harness-track.md` §5): дефект fail-closed — худший исход
«работа встала», не «дефект проехал»; границу C он не ослабляет ни в одном мире; и он
САМОБЛОКИРУЮЩИЙСЯ — PR этой же ветки первым и покраснеет, влить его в `main` незамеченным
физически нельзя. Фикс — две строки (`with: fetch-depth: 0`) до merge; правится тем же
треком без нового круга: механика скопирована с соседних джобов дословно.

Мелочь того же диапазона, кандидаты в косметику (не находки): (а) страж единственности
полей — групповой цикл по выписанному массиву; фикстура пиннит только члена `signature`
(снятие члена `epoch_id` из цикла проба не заметит — но дубль эпохи всё равно красный через
многострочное значение и сверку равенства, теряется лишь код 2 против 1); (б) `link_world`
пробы использует `git add -A` в порождённой фикстуре — буква `branch-hygiene.md` («в ЛЮБОМ
дереве») задета, дух нет: содержимое фикстуры полностью определено скриптом, хука там нет.
