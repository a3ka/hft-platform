## Findings

### C1 — FA promises OPS-I-5 parity, but its own matrix references a non-existent metric

`docs/fa/ops.md` §3 lists the exported metrics at lines 58-72. That list does not include
`backup_restore_drill_ok`. The §7.1 incident matrix then makes `OPS-BKP` a P0 rule backed by
`backup_restore_drill_ok` at line 168. This directly contradicts OPS-I-5 at lines 143-144 and
the parity rule at lines 170-172: every P0/P1 rule must reference an existing metric.

This is not cosmetic. `milestones/M-09-data-safety-net.md` task 4 and Acceptance item 4 both turn
that FA parity into CI (`lines 56, 67-68`). As written, the future gate must either fail forever
against the source document or be weakened into a decorative check. Fix the source FA before RED:
define the restore-drill metric in §3 and include it in the grep/parity surface, or change the
matrix to a named observable that actually exists.

While fixing this, close the same taxonomy gap for P1 rules in §7: `gap-доля за сутки > 1%` has no
metric in §3, and `частые ресинки` has `book_resync_total` in §3 but no stable §7.1 incident row.
Do not leave P1 rules outside the promised two-way parity surface.

### C2 — FA reintroduces TD-021's false RSS measurement class

`docs/fa/ops.md` defines `recorder_rss_bytes` as the TD-016 leak metric at line 60 and uses it for
the TD-016 P1 rule at line 165. It never says this is `RssAnon` from `/proc/<pid>/status`.

That is a known foot-gun in this repo. `gates.md` §8 says RSS must be measured only as `RssAnon`
and that `docker stats` / cgroup memory include journal page cache; `testing.md` lines 137-153 make
the same rule part of oracle integrity. A generic `rss` metric can recreate the exact TD-021 false
guarantee: alerting on page cache or host accounting instead of recorder heap growth.

Fix the FA before RED by pinning the metric source and semantics. Acceptable direction: define the
exported metric as `RssAnon` bytes from `/proc/<pid>/status` or rename it so the invariant is
unambiguous. Keep the book-level convergence question separate from process heap RSS.

### C3 — M-09 is not dispatchable: `ops` has no write zone or agent profile

The plan allows a new `crates/ops/**` crate and `deploy/**` work at
`milestones/M-09-data-safety-net.md` lines 36-43, then assigns core tasks to `ops` at lines 54-56.
Current workflow roles do not define an `ops` or `ops-dev` agent. `docs/04-workflow.md` lines 17-28
list architect, critic, engine-dev, venue-dev, signal-engineer, research-dev, risk-critic,
reviewer, tester, and founder only. `scope-guard.md` lines 10-18 likewise gives no role permission
to write `crates/ops/**` or broad `deploy/**`.

So the plan cannot be executed without a scope violation: architect may not write impl code,
engine-dev is limited to existing engine crates, venue-dev is limited to `venue-*`, and research-dev
is limited to `crates/research-cli/src` plus report artifacts. Before dispatch, either introduce the
ops role/profile and matching scope-guard entry through the doc gate, or assign the work to existing
roles with explicit, narrow carve-outs.

### C4 — Plan omits the `research/data-quality/` artifact path promised by the FA

`docs/fa/ops.md` §4 says the recon divergence counter is written to `research/data-quality/` next to
gap statistics (line 84). The M-09 Allowed paths list does not include `research/data-quality/`
(`milestones/M-09-data-safety-net.md` lines 36-43), and current `scope-guard.md` grants
`research-dev` `research/reports/` but not `research/data-quality/` by default.

This leaves a choice between violating scope and silently dropping part of OPS-I-1. The plan must
either allocate the artifact path and owner, or remove/defer that FA obligation explicitly.

- **OPS-I-9 direction:** the required behavior names `Retry-After`, 418/429 cooldown, exponential

  configured budget, but the invariant is the right one.
- **CT-RFC-03 trigger:** the plan correctly treats the recon audit event as a blocking T1 change and
  requires the full contract-RFC package.
- **Risk boundary:** the plan forbids `risk|killswitch|oms` and order-egress; the MD-only venue
  carve-out matches `gates.md` §5.
- **Storage Box dependency:** the plan honestly names the founder-owned Storage Box dependency and
  states which tasks are blocked by it.

  errors and failed setup, with a concrete shared budget in the test fixture.
