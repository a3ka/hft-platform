## Findings

### CRITICAL @ HIGH-confidence

**C1 — ST-I-8b does not independently verify `StrategyBacktest` delivers fills to the strategy.**

- Evidence: `crates/sim/tests/red_strategy_backtest.rs:160-184` claims to verify strategy
  position equals net fills, but it compares `strat_pos` only to `report.positions.get(&btc())`
  and then asserts the final strategy position is zero. The test never independently computes
  signed net fills.
- Evidence: `crates/sim/src/types.rs:53-62` shows `SimFill` has `order_id`, `price`, `qty`,
  `maker`, `fee_e8`, `seq`, `ts_mono_ns`, but no `side` or `instrument`. The bridge metadata
  needed to sign fills is internal to `StrategyBacktest` (`crates/sim/src/strategy_backtest.rs:42-48`).
- Why this is anti-placebo failure: a flawed `StrategyBacktest::run` can submit intents and return
  non-empty fills, skip `strategy.on_fill(...)`, and set `BacktestReport.positions` from the
  unchanged strategy position (or from a fabricated zero map). ST-I-8a still passes on non-empty
  fills; ST-I-8b can pass because both `strat_pos` and reported position are zero; the actual
  invariant "fills were reported back to strategy" is not proven.
- Required fix: add an independent oracle before dev dispatch. Acceptable shapes:
  1. a spy `Strategy` in `crates/sim/tests/red_strategy_backtest.rs` that records every
     `FillReport` passed to `on_fill` and fails if `StrategyBacktest::run` skips or mis-signs
     fill delivery; or
  2. a signed fill/position trace in `BacktestReport` derived from `order_meta`, with the test
     deriving net position from that trace rather than trusting `report.positions`.
  The fixed test must fail if `run()` omits `strategy.on_fill(...)`.

**C2 — Task 6 grid migration is grep-gated and lacks RED coverage for D7/D8 semantics.**

- Evidence: the milestone makes D7/D8 binding decisions for grid metrics and cell compatibility:
  `BacktestReport` equity/positions/turnover and returns via `capital_ref_e8`
  (`milestones/M-07-strategy-brain.md:53`), plus an optional `strategy` block with defaults in
  grid cells and changed `params_hash` (`milestones/M-07-strategy-brain.md:54`).
- Evidence: Task 6 requires `research-cli/grid.rs` to remove the ad-hoc harness and move to
  `sim::StrategyBacktest` + strategy pipeline (`milestones/M-07-strategy-brain.md:75`).
- Evidence: the verify script checks Task 6 mainly by grepping text:
  `scripts/verify_M-07.sh:58-60` rejects `OpenPosition|Action`, then accepts any occurrence of
  `StrategyBacktest` and `DirectionalStrategy|dyn Strategy` anywhere under `crates/research-cli/src`.
  These greps include comments and unused textual references.
- Evidence: `cargo test -p research-cli` already passes in the current RED state while
  `crates/research-cli/src/grid.rs` still contains the old ad-hoc harness
  (`crates/research-cli/src/grid.rs:73-103`, `:117-315`). There is no new M-07 RED test that
  fails specifically because D7/D8 are missing.
- Why this blocks dev dispatch: research-dev could satisfy T9 by deleting the old type names and
  adding textual or shallow references to `StrategyBacktest`, while leaving returns, `params_hash`,
  strategy defaults, or report semantics wrong. That would defeat M-07's central objective:
  replacing the backtest-only decision logic with the same strategy pipeline live will use.
- Required fix: architect adds sacred RED coverage for Task 6 before dev dispatch. Minimum useful
  tests:
  - `run_grid` on a synthetic cell produces results via the `StrategyBacktest` path, not the old
    `OpenPosition`/horizon harness.
  - absent `strategy` block uses the documented defaults; present `strategy` block changes
    behavior and `params_hash`.
  - returns are derived from `BacktestReport.equity_curve_e8` / `capital_ref_e8` per D7, not from
    the old entry/exit notional formula.
  - a placebo implementation that only mentions `StrategyBacktest` in comments or dead code fails.

### MAJOR

**M1 — ST-I-5's "no-lookahead" claim is overstated; the current test proves prefix stability,
not future-blindness.**

- Evidence: `crates/strategy/tests/red_strategy.rs:226-252` runs two independent strategies,
  one on events `1..=30` and one on `1..=12`, then compares the shorter output to the full output
  prefix. `DirectionalStrategy::on_event` receives only `&Event` (`crates/strategy/src/lib.rs:28-31`);
  the test never gives the strategy a full future stream to misuse.
- Assessment: this is not as severe as C1 because the single-event API and the `StrategyBacktest`
  event order (`crates/sim/src/strategy_backtest.rs:7-11`) structurally reduce lookahead surface.
  But the oracle should be described honestly as prefix stability / replay determinism, or replaced
  with a harness-level test that can actually catch future-dependent behavior.
- Required fix: either rename/scope ST-I-5 in docs and test comments, or add a targeted test using
  a component that could plausibly see future data and must not affect prefix decisions.
