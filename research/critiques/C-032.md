### MAJOR

**M1 - The TD-030 clause is documented but not tested: a `header.first_seq` implementation can pass.**

Evidence:
- M-48 explicitly requires `history_start_seq` from the first actually folded event, not segment header metadata: `milestones/M-48-checkpoint-bootstrap-and-ops.md:47-51`, `docs/fa/viz-backend.md:112`.
- The new helper computes expected `earliest` from `journal::stream(...).next().seq`, but the fixture is built only from normal v2 segments via `Journal::open_with` and physical prefix deletion: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:95-135`.
- The assertion text forbids `header.first_seq`, but no fixture creates a first-visible legacy/headerless segment whose `SegmentHeader.first_seq` is synthesized as 0 while the first event seq is nonzero: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:197-209`.
- The journal implementation confirms this is a real known trap: `crates/journal/src/segments.rs:509-512`.

Impact: an implementation that sets `history_start_seq = first_visible_seq(dir)` from `SegmentHeader.first_seq` passes the committed M-48 fixture for v2 segments but violates the stated TD-030/VB-I-11 rule on legacy-layout data.

Suggested fix: add a RED case that constructs a declared headerless legacy first-visible segment with first event seq > 0, then asserts `history_start_seq` equals the streamed event seq, not synthetic header 0. Reuse/duplicate the fixture pattern from `crates/journal/tests/red_stream_from.rs` rather than comments.

**M2 - The gap fail-loud test does not prove "nothing written" and does not re-pin D2 non-regression.**

Evidence:
- M-48 says the remaining fail-loud case is `Err`, nothing written: `milestones/M-48-checkpoint-bootstrap-and-ops.md:55-63`, task #3 at `milestones/M-48-checkpoint-bootstrap-and-ops.md:113`.
- The RED only checks `res.is_err()` after creating the gap: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:279-288`.
- The existing implementation currently has a separate non-regression guard for `ckpt_cursor > upto`: `crates/gateway/src/lib.rs:2163-2174`, but the regression suite included by M-48 does not assert `checkpoint::advance_to` returns `Err` and preserves the checkpoint file byte-for-byte when asked to regress coverage.

Impact: a buggy implementation can write a truncated/rebased checkpoint and then return `Err`; the test still passes while the cache is corrupted. A second buggy implementation can weaken the old D2 non-monotonic protection while satisfying the new gap test.

Suggested fix: in `gap_between_checkpoint_and_journal_is_loud`, read the checkpoint file bytes before the failing call and assert they are unchanged afterward. Add a paired regression test: create checkpoint at high cursor, call `advance_to(..., lower_cursor)`, assert `Err`, and assert the checkpoint file bytes are unchanged.

**M3 - Ops canaries still do not execute the caller argv contract.**

Evidence:
- M-48 names the previous defect as a grep-green caller problem and requires checking the caller and arguments: `milestones/M-48-checkpoint-bootstrap-and-ops.md:76-88`, tasks #5/#6 at `milestones/M-48-checkpoint-bootstrap-and-ops.md:115-116`.
- The verify script checks executable existence plus cron-file grep for the checkpoint wrapper: `scripts/verify_M-48.sh:29-31`.
- The retention check greps uncommented text for `--checkpoint-coverage`, but does not run the wrapper's own `RETENTION_PRINT_ARGV=1` contract: `scripts/verify_M-48.sh:33-35`; the existing wrapper already exposes that argv seam at `deploy/bin/journal-retention-cron.sh:67-73`.

Impact: `engine-dev` can satisfy task #5 with an executable no-op wrapper and a cron line. It can satisfy task #6 with a dead branch or malformed argv containing the flag text. That is still close to the grep-green artifact class M-48 is meant to stop.

Suggested fix: make the gate execute caller-print modes, not just grep files. For example:
- `bash -n deploy/bin/gateway-checkpoint-cron.sh deploy/bin/journal-retention-cron.sh`.
- `GATEWAY_CHECKPOINT_PRINT_ARGV=1 deploy/bin/gateway-checkpoint-cron.sh` must print `gateway-checkpoint`, `--dir /journal`, `--ckpt-dir /ckpt`, and `--coverage-out /ckpt/covered_through_seq` or the exact configured equivalent.
- `RETENTION_PRINT_ARGV=1 deploy/bin/journal-retention-cron.sh` must print `--checkpoint-coverage /ckpt/covered_through_seq`.
- If `crontab` exists in CI, run `crontab -n deploy/cron.d/<file>`; otherwise document the reviewer §8 parse check explicitly.

### MINOR

**N1 - The accepted semantics are correct, but the milestone should state the consumer obligation as a follow-up, not as already guaranteed.**

The backend fields and schema bump are sufficient to stop the gateway from lying on the wire. They do not by themselves prove cockpit/AI display behavior unless the consumer gates `schema_version == 8` and renders/uses `history_start_seq`/`history_truncated`. M-48 is backend/ops scope, so this is not a blocker, but the close-out should leave a follow-up if the frontend/AI consumer is outside this milestone.

## Direct answers to architect

1. **Semantics:** accepted. "All-time from earliest available seq" plus explicit provenance is the right side of the choice. Refusing both read and checkpoint paths would break the cockpit without restoring deleted history.
2. **Honesty fields:** `history_start_seq` + `history_truncated` are enough for the backend wire contract. No explicit consumer opt-in is needed at this layer if consumers gate schema version 8; consumer display/use remains a downstream responsibility.
3. **Narrowed fail-loud:** conceptually correct. It must be strengthened in RED: prove no write on gap, and re-pin non-monotonic `advance_to` no-write behavior.
4. **Bump 7 -> 8:** justified. The fields are additive structurally, but the consumer meaning changes: "all-time" may now be explicitly truncated. T-designate governance allows this without a contract-RFC, but the schema epoch must bump.
5. **Oracle sufficiency:** not sufficient yet. A header-first implementation can pass the current v2-only fixture, and the gap oracle can pass after corrupting the checkpoint before returning `Err`.
6. **Ops canaries:** not sufficient yet. They check closer to the caller than M-38b did, but still do not execute and inspect the caller argv contract.
