## Checks Requested By Founder

### 1. `red_vwap` anti-placebo

PASS. `vwap_cumulative_across_midnight` is not a decorative oracle. I confirmed it fails
against the current M-20 session-reset implementation:

```text
left: 20000000000
right: 15000000000
exit=101
```

The fixture directly pressures the all-time invariant with a cross-midnight 100/200
two-trade blend (`crates/gateway/tests/red_vwap.rs:123-161`). It also covers:

- exact weighted math, non-integer division (`vwap_exact`);
- i128 production-scale multiplication (`vwap_i128_prod_scale`);
- cross-venue exclusion (`vwap_per_venue`);
- deterministic repeat output.

It is sufficiently non-ideal for M-36. No extra VWAP oracle is required before engine-dev.

### 2. Irreversible prod-purge runbook and `red_seg0_removed`

PASS with one non-blocking strengthening note.

The runbook order is operationally coherent for the founder decision:

- baseline recorder health / disk / legacy manifest presence (`milestones/M-36-gateway-snapshot-prod.md:76-77`);
- backup manifest, not the intentionally discarded 15GB legacy segment (`:78-79`);
- remove legacy declaration before removing the file (`:80-84`);
- re-probe the remaining journal for other corruption using both `read_all` and `stream(OwnCaptureOnly)` (`:85-88`);
- restart only `gateway-serve`, not recorder (`:89`);
- require snapshot Ok, `schema_version=6`, and latency measurement before close-out (`:90-95`).

`red_seg0_removed` is adequate for the post-purge state the runbook creates: after both
manifest entry and file are removed, there is no headerless legacy file left, so the
undeclared-legacy path is not the target state. A legacy-headerless+manifest fixture would
be needed only if M-36 intended to tolerate a dangling manifest or a missing declared
legacy file as a supported steady state. It does not.

Non-blocking strengthening while architect is already revising: the guard says the surviving
events must be "in order" (`crates/journal/tests/red_seg0_removed.rs:14-16`) but only asserts
counts (`:84-102`). Add cheap assertions that `read_all` seqs are strictly increasing and
that `stream` yields exactly the same seq list as `read_all`. This would make the
seq-continuity/meta promise mechanically explicit.

### 3. VB-I-6 consistency and live == replay

PASS. The VB-I-6 rewrite is consistent with VB-I-1/VB-I-2:

- VB-I-1 still requires pure deterministic reducers (`docs/fa/viz-backend.md:103`);
- VB-I-2 still requires live == replay (`:104`);
- VB-I-6 now explicitly declares per-series anchors: VWAP journal-cumulative, SVP/CVD session-anchored (`:108`).

`red_gateway_live_eq_replay` compares `json(&acc.series)` to `json(&full.series)`, so `SeriesBundle.vwap`
is included in the byte-identity check (`crates/gateway/tests/red_gateway_live_eq_replay.rs:201-205`,
`:223-227`). Its fixture cuts the cursor before later trades at different prices (`:91-99`, `:216-223`),
so an implementation that fails to carry VWAP running sums into `frames_since` should drift. The
oracle is not cross-midnight, but it does not need to be: `red_vwap` covers the anchor inversion,
and `red_gateway_live_eq_replay` covers snapshot/frame merge equivalence.
