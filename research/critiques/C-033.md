## Findings

### CRITICAL

**C1 - R1 is incomplete: `verify_M-38b.sh` still pins schema version 7.**

Evidence:
- M-48 task #4 requires the public gateway schema bump to 8: `milestones/M-48-checkpoint-bootstrap-and-ops.md:114`.
- The renamed version oracle now correctly pins the current expected version through `EXPECTED_SCHEMA_VERSION: u32 = 8`: `crates/gateway/tests/red_gateway_schema_version.rs:27-30`.
- But the historical M-38b gate still says the schema must not move and greps the production constant as exactly 7: `scripts/verify_M-38b.sh:105-107`.
- The current production constant is the exact line dev must change to 8: `crates/gateway/src/lib.rs:55`.

Impact: a correct M-48 implementation can make `scripts/verify_M-48.sh` green, but it cannot keep the historical M-38b gate green without changing an architect-owned verify script. This is the same process class as C-032 C1, only moved from a sacred test filename to a sacred verify canary.

Required fix: update the M-38b schema canary so it no longer asserts "schema stays 7" after the M-48 contract bump. Preserve the M-38b intent by checking checkpoint schema independence, not a stale public wire version literal.

### MAJOR

**M1 - R3 only partially re-pins D2: lower-cursor `advance_to` overwrite remains untested.**

Evidence:
- The implementation currently has the old non-monotonic guard: if an existing checkpoint cursor `c` is greater than requested `upto`, `advance_to` returns `Err`: `crates/gateway/src/lib.rs:2163-2172`.
- The rev2 covered-prune test is useful, but it calls `advance_to` once up to `cut_first - 1`, then calls `advance` after a legal prune and asserts `history_start_seq` stays 0: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:492-542`.
- No rev2 test calls `gateway::checkpoint::advance_to(..., lower_cursor)` after a higher checkpoint and asserts both `Err` and no checkpoint byte change.

Impact: an implementation can remove the explicit `c > u` refusal, still resume correctly after covered prune, and pass the rev2 M-48 oracles. That would re-open the old "checkpoint can be overwritten with less coverage" protection that R3 says is pinned.

Required fix: add the paired regression originally requested in C-032: create a checkpoint at a higher cursor, fingerprint the checkpoint directory, call `advance_to` with a lower cursor, assert `Err`, and assert the fingerprint is unchanged.

## Closed items

**R2 - Legacy/header trap is now adequate.**

The new fixture writes a declared headerless `segment-00000000.jrnl` with real events at seq 500+, sets `journal.meta`, and then appends v2 segments: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:363-407`. The anti-placebo asserts the segment is legacy/pre-header and that `header.first_seq == 0`: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:414-422`. The actual oracle requires `history_start_seq == 500` and `history_truncated == true`: `crates/gateway/tests/red_checkpoint_bootstrap_truncated.rs:433-442`.

The fixture is constructed rather than prod-captured, but that is acceptable here: the stated source A vs source B rule is exactly what must diverge, and this fixture forces the divergence explicitly.

**R4 - Ops canaries are strong enough for plan-time.**

The M-48 gate now executes wrapper print mode instead of grepping implementation text: `scripts/verify_M-48.sh:35-45`. It also checks composition between checkpoint `--coverage-out` and retention `--checkpoint-coverage`: `scripts/verify_M-48.sh:50-56`. The milestone contract says the print path must print the argv it would execute and must have no side effects: `milestones/M-48-checkpoint-bootstrap-and-ops.md:115-116`.

This cannot prove against a deliberately lying wrapper, but that is not the right bar for a plan-time shell canary. The implementation should build one `ARGV` array and use it for both print and exec, matching the existing retention wrapper pattern at `deploy/bin/journal-retention-cron.sh:56-78`. Reviewer §8 remains the decisive real-run check.
