## 3. Находки

### F-1 · REJECT — требование `A-010` §H «проверка SHA механикой check6» НЕ исполнено; захват в регэкспе — мёртвый код

`scripts/verify_design_claims.sh:620` — `FACTS_MARKER_RE` захватывает
`audited_head=([0-9a-fA-F]{7,40})`, но группа не потребляется НИГДЕ: `_has_facts_marker`
(`:625`) использует только truthiness `search()`. `check6` сканирует ТОЛЬКО
`docs/DESIGN.md + docs/rfc/**.md` (функции `check6`/`rfc_md_files`), то есть SHA маркера в
`docs/plans/**` не судится ни одной проверкой. Решение арбитра (`A-010` §H, «РЕШЕНИЕ»):
«плюс проверка SHA той же механикой, что check6 (существует, предок `HEAD`)» — обязательно
к исполнению; в теле коммитов `4b6cba8`/`83699ff` отклонение не названо и не waiver'нуто.

Дегенерированные входы (прогон честного детектора, `testing.md` §«Дегенерированный вход»):

```
OPT-IN   ВЫДУМАННЫЙ SHA 1111111111111111111111111111111111111111 (нет в истории) — судим никем
OPT-IN   SHA 41 hex (невалидный: {7,40} матчит первые 40, хвост съедает .*?)
OPT-IN   SHA не-hex после 7 hex (audited_head=0123456ZZZZZ)
ignored  SHA 6 hex — МОЛЧАЛИВЫЙ даунгрейд: автор думает «фактура под гейтом», гейт молчит
ignored  FACTS без audited_head — тоже молча
ignored  маркер, разорванный на 2 строки — тоже молча
OPT-IN   маркер на строке 5;  ignored — на строке 6 (норма же говорит «первой строкой»)
OPT-IN   BOM, CRLF, два маркера — корректно
```

Молчаливый даунгрейд — отдельная половина находки: строка `FACTS:` в голове, которая НЕ
распарсилась (опечатка, короткий SHA), не даёт ни FAIL, ни NOTE, ни INFO — «наблюдение
отсутствия» (`testing.md`, целостность гейта, свойство 4) не построено. Документ, объявивший
себя фактурой с опечаткой в маркере, невидимо выпадает из гейта.

**Условие снятия:** для каждого опт-ин файла валидировать `audited_head` механикой check6
(`git_commit_exists` + `git_commit_is_ancestor_of_any` / `canonical_refs`); строка с `FACTS:`
в голове, не прошедшая парс, — явный FAIL (или, минимум, NOTE). Сценарии пробы: выдуманный
SHA → FAIL; орфан → FAIL; валидный → PASS; малформ → не-молчание. Фикстурам H-FACTS
понадобится `git init` + коммит (образец — сценарии `RFC-SHA-real/fake/orphan` той же пробы).

### F-2 · REJECT — стаб S4 (маркер где угодно) проходит пробу: сценарий H-FACTS-3 вакуумен

(S4 = `10**9`) не роняет ничего — «МАРКЕР ЗАСЧИТЫВАЕТСЯ ТОЛЬКО В ГОЛОВЕ ФАЙЛА» не запиннен.

**Условие снятия:** в H-FACTS-3 (или отдельном сценарии) прозный маркер с РЕАЛЬНЫМ hex-SHA

матчится и наивным детектором). Наблюдение: S11 (`FACTS_HEAD_LINES = 1`) тоже проходит пробу —
константа не запиннена ни в одну сторону; направление S11 безопасно (строже нормы), опасное —
