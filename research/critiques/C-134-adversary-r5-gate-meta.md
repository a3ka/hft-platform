все exit=0; числа тела коммита сходятся (одно — с оговоркой формы, N-1).

Но заголовок коммита «ПОЛНЫЙ МУТАЦИОННЫЙ КОНТРОЛЬ ПО ВСЕМ ЧЕТЫРЁМ КОМПОНЕНТАМ» опровергается
исполнением. Условие снятия `C-133` п.1: «КАЖДЫЙ компонент диапазонного выражения (`BASE..`,
`TOUCH_TIP`, `EXCL_MAIN`, `^ah`) — и в `own_touched`, И в `own_bodies` — накрыт фикстурой,
в которой он НЕСУЩИЙ». Авторская таблица четырёх мутантов покрывает `EXCL_MAIN` (оба
потребителя), `TOUCH_TIP` (own_touched), own_bodies целиком (mutBODIES) и фильтр вердиктов
(mutFILTER — вообще не компонент диапазона). Компоненты `BASE..` и `^ah` в таблице
ОТСУТСТВУЮТ. Проверка по клеткам матрицы: `^ah`×own_touched запиннен (случайно, GM-37 —
мой mutAHT красен); `^ah`×own_bodies — мутант ВЫЖИВАЕТ 46/46; `BASE..` в `own_rev_args`
(теперь одна точка на оба потребителя) — мутант ВЫЖИВАЕТ 46/46. Оба несущие, предъявлено
исполнением на рутинных формах (§Б-1/Б-2). Это ШЕСТОЕ и СЕДЬМОЕ воспроизведение класса
«незапиннутый компонент диапазона» на одном PR — рамка мандата круга 5 предписывает блокировать
ровно этот случай: незапиннутый компонент, несущий на прод-форме.

Сужение поверхности к `own_rev_args()` — правильный ход, и он работает там, куда попал:

условие `C-133` требовало запиннить СУЩЕСТВУЮЩИЕ.

## Б-1 (БЛОКЕР, гейт трека §5.2; направление — ложное ЗЕЛЁНОЕ). `^ah` в `own_bodies` не запиннен: токен из ДО-вердиктного собственного коммита открывает лок

**Где:** `scripts/check_gate_meta.sh:393` — `own_bodies "^${ah}"`; исключение `^ah` доезжает
до `git log` через `own_rev_args "$1"`, но ни одна фикстура не делает его несущим: GM-39
guard (b) прямо требует, чтобы собственных токенов у ветки не было НИГДЕ, GM-16e держит
токен на чужой стороне.

**Мутант mutAHB** — `own_bodies` зовёт `own_rev_args ""` вместо `own_rev_args "${1:-}"`
(одна строка, правдоподобный дрейф подводки):

```
$ BARRIER=/tmp/adv-c134/mut/mutAHB.sh bash scripts/tests/red_gate_meta.sh; exit=0
VERDICT: PASS (46/46)                          ← мутация ВЫЖИЛА
```

Несущесть — исполнением, прод-форма рутинная (многокруговой PR: круг 1 после NOTE-вердикта
законно нёс `ALLOW-SUBJECT-CHANGE`; круг 2 — APPROVE, затем нарушение БЕЗ токена):

```
фикстура: B0 → коммит-1 (гейт-правка, тело несёт законный ALLOW-SUBJECT-CHANGE круга 1)
  → вердикт APPROVE (audited_head = коммит-1) → нарушение: гейт-правка ПОСЛЕ APPROVE, токена НЕТ
$ честный 539085f:  VERDICT: FAIL (1); exit=1              ← корректный красный
$ mutAHB:           NOTE ... subject-lock открыт явным ALLOW-SUBJECT-CHANGE ...
                    VERDICT: PASS; exit=0                  ← ЛОЖНОЕ ЗЕЛЁНОЕ
```

Токен, потраченный ДО вердикта, не смеет открывать лок ПОСЛЕ него — иначе любой
многокруговой PR с хоть одним историческим токеном (в живой истории они есть: `893ead1`)
получает вечный ключ от своего же будущего замка.

## Б-2 (БЛОКЕР, гейт трека §5.2; направление — ложный КРАСНЫЙ). `BASE..` в `own_rev_args` не запиннен: без него push-в-main после merge краснеет на чужой истории

**Где:** `scripts/check_gate_meta.sh:219` — `printf '%s\n' "${BASE}..${TOUCH_TIP}"`.

**Мутант mutBASE** — строка 219 → `printf '%s\n' "${TOUCH_TIP}"` (нижняя граница потеряна):

```
$ BARRIER=/tmp/adv-c134/mut/mutBASE.sh bash scripts/tests/red_gate_meta.sh; exit=0
VERDICT: PASS (46/46)                          ← мутация ВЫЖИЛА
```

Несущесть — исполнением, форма — КАЖДЫЙ push-в-main после merge ветки, чей форк старше
последней чужой правки гейт-класса в main (джоб `gate-meta` гоняется и на push,
`ci.yml:285`, якорь там выключен и `BASE..` — единственный ограничитель):

```
фикстура: B0 → ветка (вердикт APPROVE, гейт не трогала) → main: чужой влитый PR правит
  scripts/check_m99.sh → merge ветки в main; событие push, PUSH_BEFORE = вершина main до merge
$ честный 539085f:  VERDICT: PASS — вердиктов проверено: 1; exit=0    ← корректно
$ mutBASE:          FAIL ... subject-lock — тронут класс «гейт» ...
                    VERDICT: FAIL (1); exit=1                          ← ложный КРАСНЫЙ
```

Почему фикстуры слепы: в сценариях с якорем `^HEAD^1` поглощает `^BASE` (база — предок
main-стороны), а во всех push-сценариях `audited_head` совпадает с базой фикстуры и `^ah`
маскирует нижнюю границу. Ни одна фикстура не разводит `BASE` и `ah` по разным линиям истории.

**Условие снятия Б-1/Б-2 — общее:** мутанты `mutAHB` (подводка `^ah` у `own_bodies`) и
`mutBASE` (`BASE..` внутри `own_rev_args`) роняют хотя бы по одному сценарию каждый;
направления предъявлены сырым выводом (честный/мутант) в теле коммита; прежние 46 не
сломаны. Форма решения (две фикстуры, параметризация существующих, иное) — выбор
architect'а, не мой. После этого матрица «4 компонента × 2 потребителя» закрыта вся:
остальные шесть клеток запиннены уже сейчас (см. батарею ниже).
