## Notes

### N1 — recorder tokio feature wording is narrower than implementation need

The RED test and prototype need `tokio` features `net` + `io-util` for `TcpListener`, `TcpStream`, `AsyncReadExt`, and `AsyncWriteExt`. The milestone allowed-path text names recorder Cargo +`net` only at `milestones/M-09-data-safety-net.md:53-55` and `:212-215`, while the test header correctly says `net` + `io-util`.

This is non-blocking because the user handoff and RED test identify both features, and adding module-local Cargo features is within engine-dev's build-config scope. Reviewer should accept `net` + `io-util` as the intended task-4 Cargo delta and reject broader feature/dependency creep.

### N2 — `deploy/alerts/ops.rules.yml` materialization is not separately pinned

The RED set pins `to_prometheus_rules()` content, not the physical deploy file. The milestone says `deploy/alerts/ops.rules.yml = output of to_prometheus_rules()`. Because live Alertmanager is deferred, this is not blocking for task-4 plan approval, but engine-dev should still add the deploy artifact and reviewer should check it is derived from the renderer, not hand-written drift.
