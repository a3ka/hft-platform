## §3 — Findings

### MAJOR @ HIGH — M1: rev2 test file is clippy-red after task 1

`scripts/verify_M-57.sh` makes `cargo clippy --workspace --all-targets -- -D warnings` a
mandatory acceptance gate (`scripts/verify_M-57.sh:38-43`), matching CI (`.github/workflows/ci.yml:16-19`)
and `.claude/rules/gates.md` §3 lines 128-132.

When `events_scanned` exists, clippy reaches `crates/journal/tests/red_tail_scan_bounded.rs`
and fails on architect-authored loops:

```text
error: this loop could be written as a `for` loop
  --> crates/journal/tests/red_tail_scan_bounded.rs:95:5
error: this loop could be written as a `for` loop
   --> crates/journal/tests/red_tail_scan_bounded.rs:108:5
error: this loop could be written as a `for` loop
   --> crates/journal/tests/red_tail_scan_bounded.rs:251:5
error: this loop could be written as a `for` loop
   --> crates/journal/tests/red_tail_scan_bounded.rs:293:5
error: this loop could be written as a `for` loop
   --> crates/journal/tests/red_tail_scan_bounded.rs:300:5
```

Why this blocks: before task 1, compile-RED hides these lint errors. After task 1, a correct
dev implementation will still fail T2 before reaching the intended RED/GREEN semantics.
Tests are sacred (`.claude/rules/scope-guard.md`): `engine-dev` cannot repair
`crates/journal/tests/red_tail_scan_bounded.rs`.

Suggested architect fix: rewrite the five `while let Some(r) = iterator.next()` loops as
`for r in iterator` / `for r in iterator.by_ref()` as clippy suggests, or add a narrow
`#[allow(clippy::while_let_on_iterator)]` only if retaining post-iteration access makes the
loop form necessary. Here the straightforward `for` rewrite appears sufficient.

### MINOR @ MEDIUM — N1: O-3 should assert two-tick identity, not only count

O-3 is no longer self-broken and should not block dev on the C-059 off-by-one issue. But its
current assertion is weaker than its prose: `y1 + y2 == total` detects count loss/duplication,
while the duplicate check is performed on the independent full pass, not on the two-tick path.

Suggested fix while touching the file for M1: have `tick` optionally return `Vec<u64>` or add
a local O-3 stream collector, then assert the sorted concatenation of tick seqs equals the
full-pass seq list exactly. This turns the existing count-level oracle into the property it
names.

### Open question (not scored in this C-060 verdict)

C-059 §4's mechanism question is not closed by `c8e0a6d`: the milestone still says
`EventStream`/`LiveReducer` "remembers offset" (`milestones/M-57-tail-follower.md:109-117`),

(`red_tail_scan_bounded.rs:92-101`, `199-209`). I did not use this as the C-060 blocker because

whether that C-059 §4 issue is blocking, `.claude/rules/gates.md` §0 says the next step is an
arbiter, not a third critic loop on the same point.
