- **K2 closed.** `windowed_live_eq_replay` now emits 180 one-second buckets under a 60s window
  (`crates/gateway/tests/red_gateway_window.rs:162-199`), so the oracle really crosses an
  eviction boundary and a correct implementation can satisfy `full.series.ohlcv.len() < 180`.
- **K3 remains open.** The new depth assertion checks the wrong level of the data structure:

```rust
assert!(snap_many.series.depth_series.len() <= window_buckets)
```

`SeriesBundle.depth_series` is `Vec<DepthRow>`, where each `DepthRow` owns the bucket time
series in `row.series: Vec<(time_s, depth)>` (`crates/gateway/src/lib.rs:148-156`). With one
band, `depth_series.len()` is normally `2` (bid/ask), so this assertion is green even if
`depth.values` keeps all 20,000 historical buckets. That is exactly one of the unbounded
sources named in VB-I-10 / task #2: `depth.values`.

There is a second, smaller oracle weakness in the same block: `volume_bubbles.len() <=
window_buckets` does not require bubbles to be non-empty, so a broken windowed implementation
that drops all bubbles could pass this specific guard. The mixed Trade fixture makes bubbles
reachable, but the assertion does not prove they survived.

Required fix before dispatch:

1. Replace the outer `depth_series.len()` check with assertions over every `DepthRow.series`:
   non-empty and `row.series.len() <= window_buckets`, ideally with explicit `time_s >= cutoff_s`
   / `time_s <= at_s` bounds.
2. Strengthen `volume_bubbles` to require non-empty retained bubbles plus explicit window time
   bounds, not only an upper length bound.
3. Re-confirm compile-RED remains only the three `Selector.window_ms` E0560 errors.

## K1 — `red_gateway_bounded` will fail on a correct implementation

`build_buckets` writes only `L2Snapshot` events (`crates/gateway/tests/red_gateway_bounded.rs:175-190`).
`crates/gateway/src/lib.rs:571-590` builds `ohlcv` only from `MdPayload::Trade`, while `L2Snapshot`
updates book/heatmap/depth (`crates/gateway/src/lib.rs:591-618`).

But the new bounded-memory test requires:

```rust
!snap_many.series.ohlcv.is_empty() && !snap_many.series.heatmap.is_empty()
```

at `crates/gateway/tests/red_gateway_bounded.rs:222-226`.

Therefore, after `engine-dev` adds `Selector.window_ms` and implements correct bucket eviction, this
oracle still fails because its fixture cannot produce OHLCV. Compile-RED currently masks that fixture
defect.

Required fix:

- add at least one `Trade` per retained bucket if the test intends to assert OHLCV windowing; or
- remove the OHLCV non-empty assertion from the L2-only fixture and add a separate Trade fixture for
  `ohlcv` / `bubbles` eviction.

Also fix the comment at `crates/gateway/tests/red_gateway_bounded.rs:173`: `20_000` one-second buckets
is about 5.6 hours, not "many UTC days". The milestone requires multi-day pressure
(`milestones/M-37-bounded-snapshot.md:77-80`).

## K2 — `windowed_live_eq_replay` does not actually cross the 60s window

`WINDOW_MS` is 60s (`crates/gateway/tests/red_gateway_window.rs:19`). The live==replay fixture emits
30 one-second buckets (`crates/gateway/tests/red_gateway_window.rs:160-164`), so the entire history
fits inside the window.

The test then asserts:

```rust
full.series.ohlcv.len() < 30
```

at `crates/gateway/tests/red_gateway_window.rs:193-198`. A correct windowed implementation should retain
all 30 buckets because the window is 60s wide. This assertion is impossible for the stated fixture and
will fail after the compile-RED is fixed.

Required fix:

- make the fixture longer than the window, e.g. 120 one-second buckets with `WINDOW_MS=60_000`; and
- choose the mid-stream cursor so `snapshot(C) + frames_since(C..)` crosses an actual eviction boundary.

Until then this oracle does not prove windowed live==replay under eviction.

## K3 — Split-retention coverage is incomplete for the full bounded-state list

The design lists bucket-window state as `heatmap/ohlcv/bucket_delta/bubbles/depth.values`
(`milestones/M-37-bounded-snapshot.md:71`; `docs/fa/viz-backend.md:112`).

Coverage present:

- heatmap/depth memory pressure is indirectly exercised by the L2 fixture;
- CVD running-base is directly checked (`red_gateway_window.rs:70-99`);
- VP whole-current-session retention is directly checked (`red_gateway_window.rs:101-155`);
- live==replay byte equality is intended but currently invalid because K2.

Coverage missing or too indirect:

- `bubbles` eviction is not directly asserted; the bounded memory fixture has no Trade events;
- `ohlcv` eviction is asserted against an L2-only fixture, which is invalid (K1);
- `depth.values` window length is not explicitly asserted even though it is named as a retention source.

This is not a separate blocker if K1/K2 are repaired with mixed Trade+L2 fixtures and explicit retained
window-size assertions. As committed, compile-RED hides the gaps.
