The feature-gated approach is justified by the measured shape of the integration-test
suite, and the O12 verify step correctly has a branch for a successful command that ran

### B-1 — O-12 cannot become the specified oracle from task 12a as written

O-12 does place subscribe(w1, ETHUSDT) after test_wait_for_pump(w1, BUDGET) and before
test_release(w1); its setup guard is a real assert(in_flight). Thus the intended
rendezvous, unlike O-1's settle pause, is the right shape. It is not presently executable:
the feature run fails with E0432 because lib.rs:77 still exposes test_sync only under
cfg(test).

More importantly, task 12a is incomplete. It names the outer module and two pump call
sites, but src/test_sync.rs:48 independently gates the exported rendezvous module with
cfg(test). After only the three stated changes, the import from O-12 still has no
rendezvous to import.

The test also calls claims(o12, 4, ...), while MANIFEST contains no o12 entry. The coverage
assertion therefore fails as soon as the import becomes available. That is a
test-specification defect, not a legitimate RED against the engine mechanism.

Finally, the body observes only a snapshot type and absence of BTCUSDT in drain. Drain may
return an empty vector, and O-12 does not assert delivery of the new selector, non-empty new
frames, subs.len() == 1, or repeat determinism required by milestone §10.3. It can accept a
server that goes silent after the switch. This does not satisfy the required oracle for
CT-RFC-09 §2.4.

Condition to clear: the committed RED artifact must cross its stated rendezvous boundary
after task 12a, satisfy its own manifest precondition, and observe every post-release
outcome named in milestone §10.3.

### B-2 — architect changed Cargo.toml outside the milestone and role scope

The measurement behind the testing feature is valid: an undeclared cfg(feature = testing)
becomes unexpected_cfgs under clippy -D warnings (the minimal Cargo reproduction exits 101),
while the audited crate exits 0 with the declaration. Declaring the feature is mechanically
required to keep the ordinary CI build green.

It remains a build-manifest change. M-65 §2 allows crates/gateway-serve/Cargo.toml only to
engine-dev (and then only its own dependencies); architect's allow-list does not include it.
Task 12a assigns the feature declaration to engine-dev, whereas §10.3.1 task 12b assigns the
same declaration to architect. Commit 180f78e carries [architect] and changes that manifest.
Mechanical necessity is not a scope-guard exception.

Condition to clear: reconcile ownership in the milestone and land the manifest change through
the role and path allowed by the reconciled artifact set; do not treat the need for a clean
CI build as a silent expansion of architect's write zone.
