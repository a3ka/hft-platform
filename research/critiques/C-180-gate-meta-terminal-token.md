# C-180 — адверсарий: `TERMINAL-BRANCH-VERDICT` (gate-meta terminal-branch token)

**Предмет:** ветка `feat/gate-meta-terminal-token`, `7518553..fd6eb26` (два коммита:
`f40769b`, `fd6eb26`). Артефакты: `scripts/check_gate_meta.sh`,
`scripts/tests/red_gate_meta.sh`. Маршрут — харнесс-трек (`docs/workflow/harness-track.md`
§3/§5), роль — независимый адверсарий со свежим контекстом.

**Вердикт: REJECT — одна блокирующая находка (Б-1), три примечания.** Все шесть заявленных
автором осей конструкции подтверждены исполнением (§3); дефект — в НЕВЫПИСАННОЙ группе
(правило Р-3 разбора 28.08): сверка пути токена — подстрочная, и причина считается
вычитанием, поэтому токен открывает файлы, которых НЕ называет.

## Б-1 (БЛОКЕР). Токен открывает файл, который он не называет; порог причины гасится чужим путём

**Где:** `scripts/check_gate_meta.sh:337` — `case "${rest}" in *"$1"*)` — проверка
ПОДСТРОКИ по всей строке токена, а не равенства с названным путём;
`scripts/check_gate_meta.sh:338-339` — `__r="${rest//"$1"/}"` — «причина» есть остаток
после удаления ВСЕХ вхождений судимого пути.

Следствие: путь судимого файла, встречающийся в строке токена **в позиции причины**,
(а) открывает проверку предковости этому файлу и (б) сам служит «причиной ≥12» для
соседнего пути. Заявления 2 («действует только на тот путь, который в нём написан») и
3 («причина ≥12 символов помимо пути») ложны как реализованы. `GM-44` пиннит только
«чужой путь ≠ судимый»; `GM-43` — только «короткая причина». Группа «путь судимого файла
присутствует НЕ как названный путь токена» не выписана ни одним сценарием — ровно Р-3.

**Реализм канала — не теоретический.** Естественная форма причины — цитата решения
арбитра, объявившего ветку терминальной (текст-подсказка самого барьера `:437` требует
«ветка объявлена терминальной решением арбитра»); файлы арбитража живут в
`research/arbitration/**` и судятся ЭТИМ ЖЕ барьером. Токен, честно цитирующий
`A-018-*.md` в причине, молча открывает файлу `A-018-*.md` его СОБСТВЕННУЮ проверку
предковости — то есть маскирует настоящий дефект класса «аудировалась другая линия
истории» у файла, для которого токен никто не чеканил. Барьер при этом печатает ЛОЖНЫЙ
аудит-след: «открыто явным TERMINAL-BRANCH-VERDICT в <sha>» для файла, которого ни один
токен не называет.

**Воспроизведение Д-1** (живой барьер `fd6eb26`, без мутаций): репо-фикстура с двумя
вердиктами `research/critiques/C-100-a.md` и `research/arbitration/A-018-m68.md`, у обоих

`VERDICT: PASS`, exit=0.

**Почему это не покрыто оговоркой «токен подделываем».** Оговорка — про ИСТИННОСТЬ причины
(терминальность машинно не проверяется). Пофайловость же заявлена как МАШИННОЕ свойство и
запиннена сценарием `GM-44`; здесь она нарушается без всякой подделки — ЧЕСТНОЙ строкой,
написанной самым естественным образом. Дефект унаследован от `archived_token_for`
(`check_gate_meta.sh:288-293`, та же пара «подстрока + вычитание») — **предмет расширил
площадь известной слабой конструкции**, причём оценка `C-133` N-3 («чужой токен с чужим
путём не совпадёт — поверхность ничтожна») опиралась именно на предположение точного
совпадения, которое, как показано, не выполняется.

**Условие снятия.** Наблюдаемое поведение: Д-1 обязан давать exit=1 с `FAIL` на
`A-018-m68.md`; Д-2 обязан давать exit=1 на оба файла. Проба обязана нести оба
анти-бланкета этой группы (причина цитирует путь соседнего судимого файла; строка из двух
путей без причины) — оба КРАСНЫЕ против нынешней реализации `fd6eb26` (RED-по-сути,
`harness-track.md` §3). Решать, чинить ли одновременно ту же конструкцию в
`archived_token_for`, — автору; если нет, предел назвать в комменте функции.
