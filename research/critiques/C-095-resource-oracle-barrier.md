## 3. Находки

### F-1 [БЛОКЕР] Проба не имеет ни одной фикстуры «ЧЕСТНЫЙ оракул С СОСЕДЯМИ» — ветка `OK` не проверена ни в одной содержательной форме

**Где.** `scripts/tests/red_resource_oracles.sh:41-56` (`honest_oracle()`) —
фикстура не содержит НИ ОДНОГО `#[test]`:

```
$ grep -c '#\[test\]' <честная фикстура пробы>
0
```

Все сценарии, ожидающие от барьера `exit=0`, кормят его вырожденной формой:
RO-1 (`:98`) и RO-6 (`:141`) — файл с НУЛЁМ тестов; RO-10 (`:171`) и предсостояние RO-11
(`:180`) — файл с ОДНИМ тестом. Комбинация «потоковый учёт + ДВА и более теста» —
то есть **ровно та форма, в которую этот PR приводит все четыре оракула** — пробой не
предъявляется никогда.

**Следствие, замеренное, а не выведенное.** Стаб **S7** не открывает файл на предмет
механизма учёта вообще: он блокирует всё, где `#[test] ≥ 2`. Проба даёт ему `11/11`. При
этом на РЕАЛЬНОМ дереве предмета S7 выдаёт **шесть ложных срабатываний** — блокирует все
шесть честных потоковых оракулов, включая четыре, которые чинит этот PR:

```
$ ROOT=/tmp/hft-adv-roracle bash s7_proxy_testcount.sh
FAIL  crates/gateway/tests/red_gateway_bounded.rs: процессный счётчик при 2 тестах ...
FAIL  crates/gateway/tests/red_snapshot_noclone.rs: ... при 3 тестах ...
FAIL  crates/journal/tests/red_compaction.rs: ... при 10 тестах ...
FAIL  crates/journal/tests/red_det_prodscale.rs: ... при 2 тестах ...
FAIL  crates/research-cli/tests/red_stream_grid.rs: ... при 2 тестах ...
FAIL  crates/venue-binance/tests/red_book_bounded.rs: ... при 7 тестах ...
VERDICT: FAIL (6 из 13)   exit=1
```

Проба зелёная против барьера, который на предмете красный шесть раз. Это и есть определение
отсутствия различающей силы: **проба не может отличить «оракулы переведены на потоковый
учёт» от «у оракулов удалили лишние тесты»** — оба состояния делают барьер зелёным, и оба
дают `11/11`.

`harness-track.md` §5 п.1 ставит условием merge'а «проба… КРАСНАЯ против набора обманных
стабов». Условие не выполнено четырежды.

**Воспроизведение.** Недостающие фикстуры построены и прогнаны; каждая убивает свой стаб,
и ни одной из них в пробе нет:

| фикстура (форма) | РЕАЛЬНЫЙ | S6 | S7 | S8 |
|---|---|---|---|---|
| F-A: `thread_local` + 2 теста *(форма всех четырёх правленых оракулов)* | 0 | 0 | **1** | 0 |
| F-B: аллокатор БЕЗ счётчиков + 2 теста *(форма `venue-binance`)* | 0 | **1** | **1** | 0 |
| F-C: `thread_local` со СВОИМ именем счётчика + служебный `AtomicBool` + 2 теста | 0 | 0 | **1** | **1** |

S8 особенно нагляден: он судит по идентификатору `T_CUR`, а не по механизму. Проба даёт ему
`11/11` И он зелёный на реальном дереве — потому что фикс назвал счётчик `T_CUR` во всех
четырёх файлах. Отличить S8 от настоящего барьера нельзя ни пробой, ни предметом; он
развалится молча в первый же день, когда кто-то назовёт свой потоковый счётчик иначе.

### F-2 [БЛОКЕР] Fail-closed «дно» барьера обходится КОММЕНТАРИЕМ — и уже обходится на этом дереве

**Где.** `scripts/check_resource_oracles.sh:49-52` — детектор:

```bash
grep -rl --include='*.rs' 'global_allocator' "${ROOT}"
```

Это поиск ПОДСТРОКИ в тексте файла. Он совпадает с прозой: комментарий, объясняющий, что
файл КОГДА-ТО был ресурсным оракулом, регистрируется как ресурсный оракул.

**Не гипотеза — состояние предмета.** `crates/venue-binance/tests/red_book_bounded.rs`
содержит `global_allocator` ровно один раз, в комментарии на строке 35:

```
35:// TD-023: прежняя редакция мерила память через `#[global_allocator]` + глобальный счётчик `CUR`.
```

Ни аллокатора, ни `thread_local!`, ни атомика в файле нет (`thread_local=0 atomic=0`).
Барьер считает его тринадцатым оракулом и печатает «учёт потоковый». Заявленное
«оракулов проверено: 13» — на деле 12 оракулов и одна прозаическая ссылка.

**Чем это опасно.** Шапка барьера (`:26-28`) объявляет своим главным свойством fail-closed
дно: «Ноль найденных — FAIL… гейт, зеленеющий от исчезновения предмета, — не гейт (урок
CB-5)». Дно защищено ТЕКСТОМ, а не предметом. Демонстрация — дерево, где ресурсных оракулов
нет вовсе, а есть один файл с таким комментарием:

```
$ ROOT=<дерево только с комментарием> bash scripts/check_resource_oracles.sh
OK    crates/x/tests/red_alloc.rs: учёт потоковый
VERDICT: PASS — оракулов проверено: 1, процессных счётчиков не найдено
exit=0            ← ожидалось exit=2
```

Ровно тот исход, который барьер объявляет невозможным. Пробой не покрыто: RO-3 (`:111`)
подаёт ПУСТОЕ дерево, а не дерево с ложным совпадением.

### F-3 [БЛОКЕР] Регулярка процессного счётчика уклоняема обычными формами Rust — мутация подтверждает

**Где.** `scripts/check_resource_oracles.sh:63`:

```bash
'^[[:space:]]*static[[:space:]]+[A-Za-z_][A-Za-z0-9_]*[[:space:]]*:[[:space:]]*Atomic[A-Za-z0-9]+'
```

Якорь `^\s*static` и требование, чтобы `Atomic` шло НЕПОСРЕДСТВЕННО после `:`, отсекают
формы, которые пишет обычный разработчик (и которые генерирует «qualify path» из IDE):

| форма | барьер |
|---|---|
| `static CUR: AtomicUsize = ...` *(канон, форма 7 нечинёных оракулов)* | ЛОВИТ |
| `static CUR: std::sync::atomic::AtomicUsize = ...` | **ПРОПУСК** |
| `pub static CUR: AtomicUsize = ...` | **ПРОПУСК** |
| `static mut CUR: usize = 0;` *(процессный изменяемый счётчик, не атомик)* | **ПРОПУСК** |
| `static CUR: portable_atomic::AtomicUsize = ...` | **ПРОПУСК** |

**Мутационный контроль на четырёх правленых оракулах, ДВА направления.** Нейтрализация
потокового учёта проведена по одному файлу за раз, дерево возвращалось после каждой:

- **(a) канонической короткой формой** — барьер краснеет на всех четырёх (0→1). Хорошо:
  инвариант ПИННИТСЯ против той формы, ради которой барьер написан;
- **(b) полностью квалифицированным путём** — барьер остаётся ЗЕЛЁНЫМ на всех четырёх
  (exit=0). Все четыре оракула могут регрессировать обратно к процессному счётчику, и барьер
  этого не увидит.

Проба содержит RO-5 (`:123`) — уклонение от регулярки для АТРИБУТА `#[ global_allocator ]`.
Симметричного сценария для СЧЁТЧИКА нет, хотя счётчик и есть предмет инварианта.

## 4. Вердикт: **REJECT**

Не по строгости, а по невыполненному условию merge'а. `harness-track.md` §5 п.1 требует
пробу, КРАСНУЮ против набора обманных стабов; замер — зелёная против четырёх из восьми,
причём один из них (S7) демонстрируемо неверен на самом предмете. Плюс два дефекта в
САМОМ барьере, живые на этом дереве: fail-closed дно, обходимое комментарием (F-2, уже
обойдено файлом `venue-binance`), и регрессия всех четырёх правленых оракулов, которую
барьер не видит (F-3(b)).

Замысел и каркас — годные; работы на один короткий круг.

### Условие снятия

1. **F-1** — добавить в пробу сценарии, отличающие ИНВАРИАНТ от ПРОКСИ. Минимум три,
   формы предъявлены и прогнаны выше:
   - `RO-12` честный `thread_local` + ДВА `#[test]` ⇒ exit=0 (убивает S7);
   - `RO-13` `global_allocator` без единого счётчика + два теста ⇒ exit=0 (убивает S6);
   - `RO-14` `thread_local` с ПРОИЗВОЛЬНЫМ именем счётчика + служебный атомик + два теста
     ⇒ exit=0 (убивает S8).
   Приёмка — не «сценарии добавлены», а прогон: `BARRIER=<S6|S7|S8> проба` обязан дать FAIL.
2. **F-2** — детектор обязан опознавать ОБЪЯВЛЕНИЕ, а не упоминание: искать атрибут
   (`#[...global_allocator...]` вне строк, начинающихся с `//`), либо отсеивать совпадения в
   комментариях. Сценарий пробы: дерево, где `global_allocator` есть ТОЛЬКО в комментарии,
   ⇒ exit=2, а не 0. Отдельно — снять `venue-binance/tests/red_book_bounded.rs` с учёта
   (он не оракул) либо назвать это осознанным исключением в тексте барьера.
3. **F-3** — расширить `procwide` на `pub static`, полностью квалифицированные пути и
   `static mut`. Приёмка — мутация (b): подстановка `std::sync::atomic::AtomicUsize` в любой
   из четырёх правленых оракулов обязана дать exit=1.
4. **F-4** — привести комментарий `red_gateway_bounded.rs:70-73` в соответствие с кодом.
5. **F-5** — на усмотрение founder'а: либо механизм пишется, либо утверждение о нём
   снимается из `gates.md` §4. Merge этого PR не блокирует.

Пределы, названные в шапке барьера (`:122-133`), под эти находки НЕ подводятся: предел №4
(«`thread_local!` засчитывается по наличию, не по применению») говорит о ПРИМЕНЕНИИ
найденного, тогда как F-3 — о ненахождении вовсе, а F-2 — о ложном нахождении. Названный
предел не покрывает необъявленный.
