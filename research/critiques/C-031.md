## C-030 closure

### R1 — Retention coupling

**Status:** CLOSED, with accepted NOTE on override.

Rev2 makes the default rule strict: local prune is allowed only when checkpoint coverage proves
the segment is covered through its derived `last_seq`; otherwise the segment stays local and is
reported as skipped. The criterion is selector-agnostic, using a single `covered_through_seq`
artifact from `gateway-checkpoint` (`milestones/M-38b-checkpoint-reducer.md:163-183`).

The RED coverage is concrete:

- `uncovered_segments_are_not_pruned_and_are_reported` keeps uncovered local segments and reports
  a checkpoint-related skip reason (`crates/journal/tests/red_retention_checkpoint_coverage.rs:129-178`).
- `covered_segments_are_pruned` proves covered segments can be removed
  (`crates/journal/tests/red_retention_checkpoint_coverage.rs:184-213`).
- `coverage_boundary_is_exact` forces the `last_seq = first_seq(next)-1` boundary
  (`crates/journal/tests/red_retention_checkpoint_coverage.rs:222-259`).
- `absent_coverage_blocks_prune_but_still_offloads` proves offsite backup is not blocked
  (`crates/journal/tests/red_retention_checkpoint_coverage.rs:265-291`).

**Decision on `allow_prune_without_checkpoint`: accepted.** It is non-default, operator-explicit,
and every such prune must be named in `RetentionReport.pruned_without_checkpoint_coverage`
(`crates/journal/tests/red_retention_checkpoint_coverage.rs:301-323`). This is a reasonable
escape hatch: literal strictness can let a broken checkpoint path fill disk until the recorder
stops, losing new data to preserve old local hot data. The audit trail prevents silent data loss.

### R2 — Real legacy `stream_from` oracle

**Status:** CLOSED.

`red_stream_from.rs` now writes an actual headerless legacy segment, declares it through the
legacy manifest path, appends modern segments, and asserts exactly one pre-header segment is
present (`crates/journal/tests/red_stream_from.rs:226-306`). The core oracle compares
`stream_from(..., after)` to the full event set filtered by seq for every cursor
(`crates/journal/tests/red_stream_from.rs:315-330`).

An implementation that skips a legacy segment by its synthetic `first_seq == 0` will miss legacy
events with `seq > after` and fail this test. The old placebo condition is gone.

### R3 — Hidden full replay plus fake small `ReadStats`

**Status:** CLOSED.

The new prefix-pruned gateway RED records the expected snapshot before prune, creates a checkpoint
covering the deleted prefix, physically removes covered prefix segment files, then requires
`snapshot_from_checkpoint` to return byte-identical output with bounded tail reads
(`crates/gateway/tests/red_checkpoint_prefix_pruned.rs:116-199`).

That closes the C-030 bypass. A hidden full replay cannot read history that is no longer on disk.
To pass all three forcings while still not solving TD-044, an implementation would have to
special-case the tests or invent data outside the journal/checkpoint inputs; that is outside the
useful threat model for RED tests.

### N1 — Reducer state field list

**Status:** CLOSED, with wording note.

The actual mutable state fields of `Reducer` are accounted for in the milestone state table:
`ohlcv`, `cvd`, `vwap`, `depth`, `vp`, `session_max_time_s`, `book`, `heatmap_buckets`,
`bubbles`, `at_ms`, and cursor (`milestones/M-38b-checkpoint-reducer.md:36-56`). The omission of
`selector` is intentional and correct: it is configuration, covered by `selector_fingerprint`,
and supplied by the caller after fingerprint validation.

Advisory wording issue: the same section still says completeness is held by
`#[derive(Serialize, Deserialize)]` on `Reducer` (`milestones/M-38b-checkpoint-reducer.md:58-60`),
while also forbidding selector serialization (`milestones/M-38b-checkpoint-reducer.md:51-56`).
`engine-dev` must resolve this explicitly, e.g. by using a serializable checkpoint-state type or
by skipping/rebinding `selector` without weakening the state-field coverage. Do not serialize a
stale selector copy into the checkpoint.

### N2 — `journal_lineage`

**Status:** CLOSED.

The rev2 lineage rule is suffix-compatible and not too broad: manifest entries are limited to
`index`, `epoch_id`, `source`, and `first_seq`, deliberately excluding wall-clock creation time
and size so compaction does not invalidate a good checkpoint
(`milestones/M-38b-checkpoint-reducer.md:116-129`).

The rule is also not too weak for the stated TD-044 gate. Missing manifest entries are legal only
for checkpoint-covered prefix segments; currently visible suffix segment headers must match
field-for-field. The prefix-pruned RED exercises the legal case, and the uncovered-missing test
guards against inventing deleted tail data
(`crates/gateway/tests/red_checkpoint_prefix_pruned.rs:264-322`).

## Advisory notes

### N3 — Add a canary for the override CLI flag if the escape hatch stays

The milestone promises `journal-retention` flags `--checkpoint-coverage` and
`--allow-prune-without-checkpoint` (`milestones/M-38b-checkpoint-reducer.md:201-205`,
`232-242`). The verify canary currently greps only `checkpoint-coverage`
(`scripts/verify_M-38b.sh:69-71`). The library RED forces override behavior, but a dev could wire
the library field and forget the operator CLI flag.

Recommended implementation tightening: extend the canary to grep
`allow-prune-without-checkpoint` in `crates/journal/src/bin/journal-retention.rs`.

### N4 — Preserve the fail-closed default when implementing override

The override is accepted only under the rev2 contract: default false, explicit operator action,
and a named report entry for every prune without coverage. A broad "best effort prune" mode or a
silent report omission would reopen C-030 R1.
