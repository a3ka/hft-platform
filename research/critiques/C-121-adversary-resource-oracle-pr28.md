## §5 — Находки

### B-1 (BLOCKER) — override-текст «пределы, названные честно» ЛОЖЕН на 3 из 5 пунктов

`scripts/check_resource_oracles.sh:50-64` — шапка, названная в PR-теле обоснованием
founder-override («Шесть непокрытых классов перечислены поимённо в шапке»), утверждает
НЕ ЛОВИТ для:
- `OnceLock<AtomicUsize>` / `lazy_static!` (`:53`) — ЛОВИТСЯ (RO-20/RO-21 зелёные);
- `#[tokio::test]` / `#[rstest]` (`:58`) — ЛОВЯТСЯ (RO-22 зелёный; стаб rstest → exit=1);
  строка `:61` называет это «самым дешёвым кандидатом на починку, если решим вернуться» —
  починка УЖЕ в этом же файле, `:164`;
- `thread_local!` в комментарии (`:62`) — ЛОВИТСЯ (RO-23 зелёный).

Причина установлена по истории: шапка написана коммитом `a071496` ДО фикса `7d154ff`,
который закрыл R2/R3/R8/R10 и шапку не синхронизировал. Направление безопасное (покрытие
занижено, не завышено), но это ТОТ ЖЕ класс H-12 («сводка противоречит телу»), поднятый
на уровень, где он перестаёт быть NOTE: **этим текстом подписывается founder-override**.
Override, чья легитимность держится на «пределы названы честно», не может опираться на
шапку, где три предела из пяти — не пределы. Реальный остаток после `7d154ff`: R4 (макрос
из другого файла), R9 (сосед-модуль; оба — `TD-157`, принятый предел), `#[test_case]`
(стаб S1: exit=0, «тестов в бинаре 0»), `thread_local!` по НАЛИЧИЮ (нижний блок §ПРЕДЕЛЫ
п.4), `/* */`-блочные комментарии.

Воспроизведение каждого пункта:
```
cd <checkout PR>; D=$(mktemp -d); mkdir -p $D/crates/x/tests
printf '#[global_allocator]\nstatic A: X = X;\nstatic CUR: OnceLock<AtomicUsize> = OnceLock::new();\n#[test] fn a() {}\n#[test] fn b() {}\n' > $D/crates/x/tests/red_alloc.rs

```

**Условие снятия:** шапка `:50-64` переписана по фактическому состоянию `7d154ff`
(остаток: R4, R9, test_case, thread_local-по-наличию, блочные комментарии), и PR-тело
приведено к ней. Кода это не требует.

### B-3 (MAJOR) — три мутации барьера проходят пробу 21/21; ширина детектора не запинена
