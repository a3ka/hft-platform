## Finding K1 — Task 9 schema-version oracle is not RED

The milestone makes `GATEWAY_SCHEMA_VERSION` 6 -> 7 mandatory because both CVD semantics and
`cvd_session_base` shape change non-additively (`milestones/M-38a-cvd-session-ledger.md:50-51`,
`:105-106`). Task 9 names `red_gateway_export_v2` as the oracle for this bump
(`milestones/M-38a-cvd-session-ledger.md:93`), and `scripts/verify_M-38a.sh` labels that command
as "bump GATEWAY_SCHEMA_VERSION 6->7" (`scripts/verify_M-38a.sh:23-24`).

But `red_gateway_export_v2` only asserts that `snap.schema_version == GATEWAY_SCHEMA_VERSION`;
it never asserts that the constant is `7` (`crates/gateway/tests/red_gateway_export_v2.rs:83-97`).
The current source still has `pub const GATEWAY_SCHEMA_VERSION: u32 = 6`
(`crates/gateway/src/lib.rs:36`), and the verify run shows the schema step passes today:

```text
=== task #4 — bump GATEWAY_SCHEMA_VERSION 6→7 (schema_version в Snapshot/Frame) ===
running 2 tests
..
PASS: cargo test -p gateway --test red_gateway_export_v2 --quiet
```

This is not a RED oracle. `engine-dev` can implement the session ledger and leave the public
schema at v6 while the named Task 9 gate stays green.

Required fix before dispatch:

1. Add a sacred assertion that `GATEWAY_SCHEMA_VERSION == 7`.
2. Assert both `Snapshot.schema_version == 7` and a `Frame.schema_version == 7` from `frames_since`.
3. Keep the existing v1-additive depth/provenance checks as regressions; they do not prove the
   M-38a non-additive version bump.

## Finding K2 — The overlap-multistep vantage is not at the session boundary

The milestone requires merge byte-identity through midnight and explicitly says whole-session
drop must apply to existing state in `Snapshot::apply` / `evict_series_bundle_under_window`
(`milestones/M-38a-cvd-session-ledger.md:53-58`). The testing rule requires a vantage where
existing state overlaps the final window, not a disjoint/empty observation
(`.claude/rules/testing.md:143-150`). The milestone also claims coverage for "overlap-курсор у
границы + multistep-fold" (`milestones/M-38a-cvd-session-ledger.md:95-100`).

The committed `windowed_live_eq_replay_overlap_multistep` fixture crosses midnight in the input,
but chooses `let c = Cursor::at(seqs[seqs.len() - 6])` (`crates/gateway/tests/red_gateway_window.rs:337-351`).
With the fixture's 180 one-second events from `d2-90s` through `d2+89s`, that cursor is around
`d2+84s`; its 60s existing window is entirely inside S2. The final window is also entirely inside S2.
Therefore the test does not exercise the case where existing state still contains S1 and the final
apply path must evict S1 as a whole past session. It checks S2 overlap/fold, but not the specific
whole-past-session drop symmetry between reducer-finish and bundle-merge.

Realistic miss: an implementation can drop past CVD sessions correctly in `Reducer::evict_window_state`
for `snapshot(LATEST)`, but leave stale S1 entries in `evict_series_bundle_under_window` during
`Snapshot::apply`. The current test starts after S1 is already absent from `merged`, so the final
`merged.series == full.series` comparison (`crates/gateway/tests/red_gateway_window.rs:401-412`) can
miss that drift.

Required fix before dispatch:

1. Move the cursor near the boundary while retaining overlap, e.g. around `d2+35s` for the current
   fixture/window, so `snapshot(C)` contains S1 tail + S2 head and `snapshot(LATEST)` contains only S2.
2. Add precondition asserts before applying frames:
   - `merged` contains at least one S1 `cumulative_delta` row;
   - `full` contains no S1 rows and `session_base(full.cvd_session_base, s1) == 0`.
3. After multistep fold, assert `merged` has no S1 rows, `session_base(merged.cvd_session_base, s1) == 0`,
   and then keep the full `merged.series == full.series` byte-identity assertion.
