## Blocking Findings

### B1 — `verify_M-10.sh` can pass without the R-001 report

Evidence:

- M-10 objective is the first end-to-end R-001 OBI Track A report
  (`milestones/M-10-r001-obi-killscreen.md:8-11`).
- Task 4 requires `research/reports/R-001-obi-trackA.{json,md}` with mandatory
  `span/se/verdict/gap_ref` (`milestones/M-10-r001-obi-killscreen.md:76`).
- `verify_M-10.sh` only validates the report if `REPORT_JSON` exists
  (`scripts/verify_M-10.sh:31-55`).
- If no report exists, the script emits `NOTE`, increments no failure counter, and continues
  (`scripts/verify_M-10.sh:54-55`).

Worst case: `research-dev` implements `classify_verdict` and the new report fields enough for
`red_killscreen` to pass, does not run R-001, and `verify_M-10.sh` exits `0` because missing
R-001 remains a `NOTE`. The milestone can then advance without the artifact it was created to
produce.

Required repair:

1. Make missing `research/reports/R-001-obi-trackA.json` and `.md` a `FAIL` for the final M-10
   acceptance gate.
2. If architect wants a pre-report RED-phase mode, split it explicitly, e.g. `verify_M-10.sh --red`
   vs final default fail-closed mode. The default used by dev Done Block must require the report.

### B2 — KS-I-5 `gap_ref` is specified but not tested or verified

Evidence:

- M-10 adds `verdict` plus `gap_ref` as mandatory report content
  (`milestones/M-10-r001-obi-killscreen.md:37-38`).
- KS-I-5 requires the verdict to reference gap statistics for the test window
  (`milestones/M-10-r001-obi-killscreen.md:53`).
- Task 1 claims `red_killscreen.rs` covers `KS-I-5 gap-ref`
  (`milestones/M-10-r001-obi-killscreen.md:73`).
- The RED test input has no `gap_ref` field and no gap-ref test
  (`crates/research-cli/tests/red_killscreen.rs:27-38`, `:43-146`).
- The verify script checks `data_span_days se_sharpe verdict code_hash`, but not `gap_ref`
  (`scripts/verify_M-10.sh:33-38`).

Worst case: the generated R-001 report carries a classifier verdict but no E8 gap evidence.
`verify_M-10.sh` still passes, so risk-critic/founder receive a numeric verdict without the
data-window quality proof M-10 names as mandatory.

Required repair:

1. Add `gap_ref` to the report-required field list in `verify_M-10.sh`.
2. Add a RED assertion that `ValidationReport` / report JSON cannot satisfy M-10 without a
   non-empty `gap_ref` referencing the generated gap artifact.
3. If gap generation lives outside `classify_verdict`, do not force it into `KillScreenInputs`;
   gate it in a report-level RED instead.

### B3 — TD-015 ledger epoch is not actually gated, and the script points at the wrong ledger path

Evidence:

- M-10 KS-I-3 requires `ledger_n` and V[SR] to use only records from code `>= 5141fd9`
  (`milestones/M-10-r001-obi-killscreen.md:51`, `:82-83`).

  `research/trials-ledger.json`.

  range, ledger source path, or exclusion of pre-`5141fd9` records
  (`scripts/verify_M-10.sh:33-38`, `:53`).

local ledger, while the official verify script still passes. That directly weakens the
anti-overfit gate that protects founder from signing a report with incomparable Sharpe history.
