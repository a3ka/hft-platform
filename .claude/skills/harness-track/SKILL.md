# Харнесс-трек — исполняемая процедура

Канон маршрута — `docs/workflow/harness-track.md`. Здесь — как его ИСПОЛНЯТЬ: кого запускать,
с каким мандатом, что кому передавать. Скилл нужен потому, что маршрут отличается от
`04-workflow.md` §2, и без явной процедуры роль скатывается в привычный milestone-цикл — тот
самый, который на M-60 дал четыре круга гейта, из которых три нашли дефекты в самих оракулах.

## Фаза 0 — проверить, что предмет ДЕЙСТВИТЕЛЬНО харнесс

Три вопроса подряд, все три обязаны дать «нет»:

1. Исполняется ли это прод-процессом (recorder / gateway-serve / venue-ingest / ops-cron)?
2. Меняет ли это НОРМУ, а не инструмент (инварианты `RK-I-*`/`INTG-I-*`/`CT-I-*`, границы A/B/C,
   фазы роадмапа, `docs/DESIGN.md`, `docs/0N-*.md`, `docs/fa/**`)?
3. Может ли ошибка здесь испортить журнал, позицию или деньги?

Хотя бы одно «да» — СТОП, идём полным циклом `04-workflow.md` §2. Скилл здесь не применяется.

Зона трека: `scripts/check_*.sh` · `scripts/tests/red_*.sh` · `scripts/verify_M-*.sh` ·
репо-тулинг (`next_artifact_id.sh`, `gc_worktrees.sh`) · `.github/workflows/**` · `.githooks/**`.

`.claude/**`, `CLAUDE.md`, `docs/04-workflow.md` остаются под замком §11 и требуют
`FOUNDER-APPROVED` в теле коммита — трек этого НЕ отменяет.

## Фаза 1 — Fable строит: анализ проблемы и план улучшений

Architect запускает субагента (`subagent_type: architect`, `model: opus` — Fable называется
ЯВНО, frontmatter её не гарантирует). Один субагент на предмет, со СВЕЖИМ контекстом.

Мандат обязан содержать:

- **Startup-протокол** — перечень файлов, читаемых ДО работы: `CLAUDE.md`,
  `.claude/rules/{gates,testing,scope-guard,commit-discipline,branch-hygiene,handoff-block}.md`,
  `.claude/agents/architect.md`, `docs/workflow/harness-track.md`, предметные файлы.
- **Своё дерево:** `git worktree add /tmp/<имя> --detach origin/<ветка>`; общий чекаут не трогать.
- **Предмет замером, а не по памяти:** какие файлы, какой класс дефекта, чем он предъявлен.
- **Границу зоны** — что править МОЖНО и что НЕЛЬЗЯ, с причиной на каждый запрет.
- **Требование анти-плацебо:** план обязан называть, какими СТАБАМИ проверяется каждый барьер,
  и какой стаб обязан его убить. Без этого план — намерение, а не конструкция.
- **Форму продукта:** документ-план в `docs/plans/<тема>-<дата>.md` ЛИБО готовый набор
  (барьер + проба + стабы) — в зависимости от того, что заказано.

Пример вызова:

```
Agent(subagent_type="architect", model="opus", prompt="""
<Startup-протокол>
<Предмет: файл:строка, класс дефекта, чем предъявлен>
<Зона: разрешено / запрещено с причинами>
Задача: разобрать проблему и предложить план улучшения харнесса.
План обязан называть: (1) какой инвариант защищаем; (2) какими стабами он проверяется;
(3) какой стаб обязан убить барьер, если тот сломан; (4) предел механизма — что он НЕ ловит.
Ничего не коммить в main. Работать в /tmp/<имя>. Вернуть план текстом + путь к артефакту.
""")
```

## Фаза 2 — architect принимает работу Fable

- Прогнать лично то, что можно прогнать (`bash -n`, пробы против стабов, `verify_*`).
- Закоммитить продукт на ветку трека **явными путями** (`git add <файл>`, затем
  `git commit -- <путь>`; `commit -a` и `add -A` запрещены барьером `.githooks/pre-commit`).
- **Запушить ветку немедленно** — предмет, предъявляемый гейту, обязан быть в `origin`
  (`gates.md` §8). Без этого критик получит предмет, которого не видит.

## Фаза 3 — Terra ломает: handoff founder'у на запуск критика

Architect НЕ запускает codex сам — он отдаёт founder'у paste-ready команду. Обёртка:
`.claude/wrappers/codex-critic.sh`.

```
HFT_BRANCH=<ветка предмета> bash /home/nous/hft-platform/.claude/wrappers/codex-critic.sh
```

Модель по умолчанию — **`gpt-5.6-terra`**: критик и есть та роль, ради которой не экономят
(асимметричная цена ошибки). Переопределяется `HFT_CODEX_MODEL=<имя>`.

Обёртка сама делает `fetch`, разворачивает worktree от `origin/$HFT_BRANCH`, поднимает codex
с bootstrap'ом роли критика и убирает дерево, если оно чистое и всё запушено.

**Требование к CLI:** Terra доступна с `codex-cli >= 0.147.0`. Системный `/usr/bin/codex`
на этой машине — `0.142.5` и отвечает отказом `400 invalid_request_error: requires a newer
version of Codex`; обновить его нельзя без root. Свежий CLI ставится в пользовательский
префикс и обёртка предпочитает именно его:

```
npm install -g --prefix "$HOME/.local" @openai/codex@latest
```

Обёртка проверяет версию ДО запуска и отказывается fail-closed с инструкцией, если бинарь
старый (иначе критик молча уехал бы на слабой модели). Осторожно при диагностике: рядом с
отказом codex печатает warning «Model metadata … not found» — по нему легко заключить, что
модели не существует. Это неверно: решение принимается по телу ошибки, а не по warning'у.

Handoff-блок (`.claude/rules/handoff-block.md`) обязан нести в §D:

- команду выше — целиком, с подставленной веткой;
- HEAD предмета (`git log -1 --format='%h %s'`) — чтобы критик судил то же, что architect сдал;
- **что именно проверять исполнением**: перечень стабов, которые обязаны убивать барьер, и
  мутации, которые обязаны ронять пробу;
- напоминание о форме вердикта (см. Фазу 4) — критик пишет в `research/critiques/`, НЕ в
  `.omc/plans/`.

## Фаза 4 — вердикт и закрытие

**Вердикт критика — ФАЙЛ `research/critiques/C-NNN-<тема>.md`, закоммиченный на ветку предмета
и запушенный.** Номер — только `bash scripts/next_artifact_id.sh C`. Вердикт, живущий в
транскрипте или в `/tmp`, аудит-трейлом не является: инцидент M-49 (два REJECT'а испарились
вместе с транскриптом субагента, ~300k токенов работы гейта), инцидент 2026-08-15 (вердикт
критика M-60 записан в `/tmp/.../.omc/plans/` и был бы потерян вместе с деревом).

Дальше architect правит по находкам и вливает **через PR** — прямой push в `main` отклоняется
защитой ветки:

```
gh pr create --base main --head <ветка> --title "<...>" --body "<...>"
gh pr checks <N>                      # красный CI ⇒ merge физически невозможен
gh pr merge <N> --merge --delete-branch
```

## Что в треке НЕ сокращается никогда

| требование | почему |
|---|---|
| анти-плацебо стабами | на M-60 четыре дефекта из четырёх найдены так: «отказ падает 127» давал `PASS 11/11`, «зашитый лимит» — `PASS 11/11`, «зашитый origin» — `PASS 23/23` (воспроизводил `C-062`), «`df` мимо PATH» — `PASS 12/12` |
| позитивный контроль | иначе проба может быть вечно-красной, и её «объявят шумом и выключат» |
| мутационный контроль | «нейтрализация X → сценарий Y FAILED», сырым выводом |
| независимый критик | автор себя не проверяет: на M-60 автор объявил блокер закрытым, не построив решающий стаб; независимый агент построил и опроверг |
| вердикт файлом | см. Фазу 4 |
| уборка фикстур | реестр в ФАЙЛЕ + `trap EXIT`; замер «каталогов после прогона» числом (класс, давший 10 400 каталогов `/tmp`) |
| замок §11 | правки `.claude/**`, `CLAUDE.md`, `docs/04-workflow.md` требуют `FOUNDER-APPROVED` покоммитно |

## Предел скилла, названный честно

Механической проверки, что предмет ДЕЙСТВИТЕЛЬНО харнесс (Фаза 0), нет — это
`COGNITIVE-ONLY`. Кандидат на механизацию: проверка, что PR трека не трогает `crates/**`
(кроме `*/tests/**`), `crates/contracts/**` и документы норм. Пока её нет, ответственность за
границу лежит на architect'е, и ошибка здесь означает, что прод-код проехал по облегчённому
маршруту.
