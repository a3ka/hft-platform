# Branch hygiene — общий чекаут ≠ общая ветка (инцидент 2026-07-13)

Источник: инциденты «чужие RED-коммиты уехали с чужим push» (2026-07-11), «chain-break
TD-014» (2026-07-12), «reviewer переключил общий чекаут на main поверх ветки architect'а +
вердикт критика остался untracked-файлом» (2026-07-13).

## Проблема

`/home/nous/hft-platform` — ОДИН рабочий каталог, а ролей много. Когда роль делает
`git checkout` в общем чекауте, она меняет состояние под ногами у всех остальных.
Следствия, которые мы уже видели:
- architect работает на `feat/M-NN`; reviewer переключает чекаут на `main` → следующий
  агент видит «пропавшую» работу и/или коммитит не туда;
- вердикт critic'а (`research/critiques/C-NNN.md`) остаётся **untracked** и выглядит как
  «файл чужой параллельной сессии» — хотя параллельных сессий нет;
- незапушенный коммит dev'а живёт только в его worktree → цепочка рвётся.

## Правила (BINDING)

1. **Ветка milestone'а — общая, чекаут — свой.** Роль, которой нужно состояние, отличное
   от текущего HEAD общего чекаута, обязана взять СВОЙ worktree:
   `git worktree add /tmp/hft-<role>-<milestone> <branch>` — и работать там.
   Общий чекаут переключает ветку ТОЛЬКО тот, кто её сейчас ведёт (architect на этапе
   спеки, dev в своей цепочке).
2. **Перед `git checkout` в общем чекауте — проверь, чей HEAD.** `git branch --show-current`
   + `git status --porcelain`. Есть чужие незакоммиченные файлы или ты не знаешь, кто вёл
   ветку → НЕ переключай, возьми worktree.
3. **Артефакт роли коммитится ролью.** Вердикт critic/risk-critic
   (`research/critiques/C-NNN.md`) — это АРТЕФАКТ гейта, а не черновик: критик коммитит его
   на ветку milestone'а (`docs(critic): C-NNN verdict ...`) в том же ответе, где выносит
   вердикт. Untracked-файл = потерянный аудит-трейл.
4. **Push-scope перед КАЖДЫМ push** (`gates.md` §8): `git log origin/<branch>..HEAD` —
   только твои коммиты. Чужие → СТОП.
5. **Незнакомый untracked-файл — не «чужая сессия», а нарушение (1)–(3).** Не удалять,
   не игнорировать: выяснить владельца по `research/critiques/`, `milestones/`, содержимому;
   передать founder'у, если владелец не определяется.

## Запрет `commit -a` / `add -A` в общем чекауте (закреплено 2026-07-14)

Третий инцидент того же класса: reviewer, находясь в ОБЩЕМ чекауте, который architect переключил
на `docs/doc-gate`, сделал `git commit -am` — и (а) **снёс вердикт критика** `C-006-doc-gate.md`
(198 строк, артефакт гейта), (б) увёл свои §8-правки не в `main`.

**Правила:**
1. **Никогда `git commit -a` / `git add -A` в общем чекауте.** Только явные пути:
   `git commit -- PROJECT-STATE.md TECH-DEBT.md`.
2. Reviewer/critic работают **из своего worktree** (см. выше), а не в общем каталоге.
3. **Коммит НЕ ИМЕЕТ ПРАВА удалять** `research/critiques/*`, `milestones/*`, `docs/rfc/*` —
   это артефакты гейтов и аудит-трейл. Если `git status` показывает их удаление — СТОП, ты не на
   своей ветке. (Механический барьер — pre-commit/CI-проверка — вынесен на doc-гейт: `C-006` re-audit.)
