# Состояние оркестрации — передача незавершённой работы между сессиями

Ведёт architect. Обновляется при КАЖДОМ запуске/возврате агента.
Назначение: сессия architect'а обрывается по исчерпанию контекста, а работа продолжается.
Этот файл + `SESSION-HANDOFF.md` + `PENDING-SIGNATURE.md` — всё, что нужно новой сессии.

**Главный принцип, делающий перенос возможным: каждый агент ПИШЕТ и ПУШИТ результат в git.**
Отчёт в чат не принимается. Проверено дорогой ценой: за 31.07 канал возврата субагентов вернул
пустоту семь раз подряд (включая разведку на 189k токенов и два вердикта гейта). Всё, что было
записано в ветку, — уцелело; всё, что осталось «в отчёте», — исчезло.
Отсюда правило RN-19 (`gates.md` §8): **отчёт агента — гипотеза, состояние git — факт.**

## Как новая сессия поднимает работу (порядок действий)

1. Прочитать: `CLAUDE.md` → `.claude/rules/*` → `docs/SESSION-HANDOFF.md` → **этот файл** →
   `docs/PENDING-SIGNATURE.md`.
2. `git fetch origin && git branch -r` — посмотреть, какие ветки из таблицы ниже появились.
3. По каждой строке таблицы: если ветка есть — работа приземлилась, проверить и выполнить
   «что делать с результатом». Если ветки нет — агент не доехал, перезапустить по мандату.
4. **Ничего не мержить в `main`, если запись в `PENDING-SIGNATURE.md` требует подписи founder'а.**

## Правила оркестрации, выведенные практикой (соблюдать)

1. **Мандат агенту обязан требовать: записать файл в репозиторий и запушить.** Read-only агенту
   нельзя поручать результат — ему нечего терять, теряет оркестратор (сгорело 189k токенов).
2. **Проверять приземление командами git, а не чтением отчёта** (RN-19). Одна попытка вернуть
   агента через `SendMessage`, при повторном провале — пушить самому из его worktree:
   `git push` не меняет ни автора, ни коммиттера, аудит-трейл цел.
3. **Гейты прогонять самому**, если это одна команда с коротким выводом. Два субагента подряд
   сожгли 350k токенов на прогон `verify_M-49.sh`, который выполняется одной строкой.
4. **Ветка на задачу, worktree на роль.** Общий чекаут не переключать.
5. **Стоп перед границей C.** Работа доводится до «готово к подписи» и останавливается.
