## §2. Стратегическая роль
Какую ровно проблему решает; где в потоке `book→signals→alpha→portfolio→strategy→risk→oms→venue`
(или вне него — journal/contracts/sim/research); почему без него нельзя.

## §3. Что модуль ЕСТЬ
- **Онион-подструктура:** core (без I/O) / mid / outer (I/O) подмодули с одной строкой роли.
- **Доменный словарь:** ключевые типы (T2/T3) с назначением.
- **Обработка отказов/деградации:** таблица (условие → детерминированный исход; всегда
  fail-closed где касается денег/риска).

## §4. Что модуль НЕ ЕСТЬ
Конкретные отрицания ответственности СОСЕДНИХ модулей (как EINHARD IS-NOT): «НЕ диспетчер
(это oms)», «НЕ считает риск (это risk)», «НЕ ходит в сеть (это venues/outer)» и т.п.
Именно это держит границы.

## §5+. Ключевые секции (специфичны модулю)
