# FA — ai-copilot: AI-наставник реального времени (Слой 9, недетерминированный)

STATUS: FA v1 (2026-07-22, architect). AI-копилот — потребитель дериватив-слоя (`docs/fa/viz-backend.md`),
изолированный от детерминированного ядра. Заменяет ручной «скриншот в ChatGPT каждые 30с» непрерывным
авто-контекстом. Источники: `docs/07-cockpit-backend-roadmap.md` §7, бриф UX/UI §14/§15/§21.7/§21.8,
`DESIGN.md` (инвариант «LLM не в горячем цикле»), `docs/03-integration-contract.md` (границы).

---

## §1. Принцип: AI ВНЕ детерминированного ядра

LLM недетерминирован → его выводы **НЕ живут в market-журнале** (`DET-I-1` цел, `docs/06` §5). AI —
read-only консюмер СКОМПОНОВАННОГО контекста, не сырого потока и не пикселей. Наш инвариант:
**LLM не в горячем торговом цикле** (`DESIGN` §6, границы A/B/C). По умолчанию AI **ордера не шлёт**
(бриф §14.4/§23) — образовательный/советующий режим; автоисполнение — отдельный будущий режим с явной
founder-подписью (Граница C).

## §2. Пять слоёв (разделение — BINDING)

```
1 Дериватив-слой (детерминир., наш)  ─┐
2 Event Engine (детерминир., наш)     ├─▶ 4 AI-Context Composer (наш) ─▶ 5 LLM-сервис (внешний,
3 Strategy Definition (контракт)      ─┘        │                            недетерминир.) ─▶ Audit-Log
                                                └── те же числа, что видит UI (единый источник правды)
```

1. **Дериватив-слой** (`viz-backend`): все индикаторы — те же числа, что видит человек. AI и UI видят ОДНО.
2. **Event Engine** (наш, детерминир., M-26): визуальные паттерны → структурированные **события**
   (absorption, exhaustion, breakout, acceptance, failed-auction, liquidity pull/replenish, CVD-divergence,
   TPP «Перевёртыш»/«Слипание»). **LLM не смотрит на пиксели** — паттерн отдаётся фактом
   `{type, price, ts, evidence}`. Детерминированные редьюсеры → идут и в UI-аннотации, и в AI, и в alerts.
3. **Strategy Definition** (контракт, M-27): «Fabio» и др. = versioned-конфиг — какие индикаторы/события
   важны + каркас решения (Market State→Location→Aggression→Price Response→Trigger→Invalidation) + правила
   инвалидации. Стратегий — сколько угодно (бриф §15); стратегия НЕ содержит кода, только декларацию.
4. **AI-Context Composer** (наш, M-27): каждые N сек / на значимом событии собирает компактный снапшот
   `{market_state, location(POC/VWAP/VAH/VAL/HVN/LVN), aggression(CVD/footprint/delta), price_response,
   liquidity, tpp, active_events[], strategy_state, user_position?}` (бриф §21.7). Версионированный контракт.
5. **LLM-сервис** (ОТДЕЛЬНЫЙ, недетерминир., внешний): `context + strategy + events` → структурный вывод
   (Market State/Location/Aggression/Price Response/Interpretation/Confirmation/**Invalidation**/Confidence/
   Evidence, бриф §14.2). Модель-агностичен, мультимодален (опция «скрин как усиление», не основа).

**Размещение (решение сессии):** LLM-сервис — отдельный бэкенд-процесс `ai-copilot` (не в ядре, не на
фронте), подписан на дериватив+event поток через Read Gateway, стримит вывод на фронт через тот же WS.
Работает непрерывно без открытого UI (алерты/коммент в моменте). Провайдер/модель — конфиг (founder).

## §3. Audit-Log (BINDING — бриф §21.8)

Каждое AI-сообщение сохраняется: входной контекст (снапшот), версия стратегии, ts, вывод, confidence,
invalidation, последующий исход. Живёт в **ОТДЕЛЬНОМ** store (не market-журнал). Назначение: воспроизводимость
рассуждения, ретро-разбор («что AI видел и почему сказал»), обучение. Аудит — не опция.

## §4. Инварианты (RED-оракулы; sacred, architect-only)

| ID | Инвариант |
|---|---|
| AI-I-1 | AI-выводы НЕ пишутся в market-журнал (`DET-I-1` цел). grep-канарейка: `ai-copilot` не импортирует journal-writer |
| AI-I-2 | AI видит ТОЛЬКО AI-Context (скомпонованный дериватив-слой), не сырой поток и не приватные ключи (бриф §23). Единый источник правды с UI |
| AI-I-3 | AI по умолчанию read-only: нет order-egress пути из `ai-copilot`; автоисполнение — только через founder-подписанный режим (Граница C, `RK-I-2` байпаса нет) |
| AI-I-4 | Каждый вывод несёт **Invalidation** + Confidence + Evidence (бриф §14.4: нет рекомендации без уровня отмены) |
| AI-I-5 | Каждое AI-сообщение аудируется (вход/стратегия/вывод/исход); отсутствие audit-записи → сообщение невалидно |
| AI-I-6 | Event Engine детерминирован (VB-I-1): те же данные → те же события; AI зависит от событий, не от пикселей |
| AI-I-7 | AI не использует данные другой биржи без явного указания в контексте (бриф §14.4) |

## §5. Соответствие границам (`03`) и контракт-слою (`05`)

- **Граница A:** дериватив/Event — чистые редьюсеры (детерминир.). **AI-слой — ЗА границей детерминизма**
  (недетерминир.), связь с ядром — только через AI-Context (read-only) + Audit (write в свой store).
- **Граница C:** любое движение к реальным ордерам от AI — только founder-подпись (`INTG-I-3`); по умолчанию
  недостижимо (AI-I-3).
- **Контракты:** AI-Context / Strategy-Definition / Event / Audit — T-designate версионированные формы в
  своих крейтах; T1-ядро не трогают; промоушен в `crates/contracts` — при кросс-языковом консюмере.
