**Прод после merge (замер 2026-07-31T14:26Z):** recorder перезапустился на ужесточённом коде
поверх живого каталога и **поднялся** — Up 13 мин, healthy; heartbeat отставание 4.4 с;
`next_seq` 137 579 079 (растёт без разрыва); сегменты 140/141 закрыты по ~1 GiB, 142 активный;
свободно 86.7 GB. Это был главный риск merge'а — ложное срабатывание ужесточения не дало бы
recorder'у стартовать.

**Итоговый контракт JR-I-8.** `open_with` не начинает запись с `seq` ≤ максимального уже
присутствующего. Нечитаемый хвост ⇒ `Err` с диагностикой (файл + причина + действие), не старт
с `meta_seq`. Страж держится и когда окно скана (4 MiB) не достаёт до начала файла. Операторский
выход — файловая декларация `journal.force-next-seq.json`, одноразовая, с аудит-следом.
Пол защиты — три состояния: `Known` (учитывает читаемый ПРЕФИКС повреждённого сегмента,
вычисляется потоково при ограниченной памяти), `NoSegments` (пол 0 законен), `Unknown`
(**отказ** — незнание не есть разрешение). `readable_floor` зовётся ТОЛЬКО в ветке нечитаемого
хвоста при наличии декларации — горячий путь старта не тронут.

**Уроки, закреплённые правилами (все в `main`):**
- вердикт reviewer'а — артефакт в `research/reviews/R-NNN.md`, коммитится (иначе пропадает);
- запретный список в спеке правки существующего кода;
- мутационный контроль — ДВА вопроса, и вопрос 2 нельзя закрывать первым найденным объяснением;
- **форма прода снимается ЗАМЕРОМ по ssh** и называется в спеке (3 из 6 кругов — один дефект:
  фикстура 8 KiB против 1 GiB; эталон, исключающий читаемый префикс; `.zst`-жертва там, где
  активный сегмент прода СЫРОЙ);
- RN-19: приземление работы субагента проверяет оркестратор фактами git (отчёт = гипотеза,
  git = факт); при повторном провале пушит сам — `git push` не меняет авторство.

**Новый долг от R-003 (не блокеры, приземлены осознанно):**
- **TD-052** — пол ограничен по ПАМЯТИ, но не по ВРЕМЕНИ: в состоянии `Unknown` прочитывается
  и декодируется весь каталог.
- **TD-053** — `READABLE_SCAN_MAX_CARRY = 64 KiB` против санити-капа ридера 64 **MiB**: событие
  крупнее 64 KiB скан пола трактует как порчу ⇒ ресинк на 1 байт ⇒ **пол может быть занижен**.
  ⚠️ **Требует замера нормальным инструментом.** Грубый скан architect'а по сырому сегменту дал
  ложные срабатывания (нашёл «фрейм 62 MB») — вывод по нему делать НЕЛЬЗЯ. Замерить максимальный
  реальный размер события через сам крейт (`read_all`/`stream` на копии сегмента) и, если события
  > 64 KiB достижимы (кандидат — L2-снапшоты книги, особенно после M-45), поднять severity:
  занижение пола открывает тот же seq-reuse, который M-49 закрывал.
