# C-111 — адверсарий оси «ложноположительные и цена остановки»: verdict-gate

- **Предмет:** `scripts/check_verdict_gate.sh` + `scripts/tests/red_verdict_gate.sh` +

- **Ось (харнесс-трек §3/§5):** законный рабочий сценарий, который барьер ломает. Джоб стоит
  в агрегате — его красное физически держит merge ЛЮБОГО PR репозитория.
- **Вердикт: REJECT.** Два блокера, оба воспроизведены исполнением: (1) в ОБЕИХ прод-формах
  вызова (pull_request и push) HEAD — merge-коммит, и барьер схлопывает позиции всех
  вердиктов ветки в одну — рекламируемый им самим штатный путь погашения НЕ РАБОТАЕТ НИГДЕ,

  `PR_BASE_SHA` барьер судит ЧУЖИЕ вердикты, приехавшие из `main`, и красит невинный PR по

## F-111-1 — BLOCKER. Прод-форма (HEAD = merge-коммит) убивает штатный путь погашения

**Что сломано.** На pull_request-событии `actions/checkout` ставит HEAD на
`refs/pull/N/merge` — merge-коммит ветки в main; на push-событии после слияния HEAD — сам
merge-коммит. Обход позиций файлов идёт `git log -m` (`scripts/check_verdict_gate.sh:182`),
и `-m` разворачивает merge против первого родителя: ВСЕ вердикт-файлы ветки показаны как
добавленные ИМ. Максимум по коммитам (`:179`) даёт обоим файлам ОДНУ позицию — позицию
merge-коммита. Дальше тай-брейк «отказ побеждает» (`:275-280`) гасит топологический порядок
ветки: REJECT из круга 1 бьёт APPROVE из круга 2, хотя тот лежит строго позже.

**Воспроизведение (герметичная фикстура: ветка с REJECT, затем APPROVE тем же ключом —
ровно сценарий VG-7 пробы, объявленный PASS):**

```
=== E1a: PR-событие, HEAD = merge-коммит (refs/pull/N/merge), база = СВЕЖИЙ main tip ===
── VERDICT-GATE: диапазон 0a1a00ea..HEAD
FAIL  ключ M-72: последний вердикт диапазона — REJECT (research/critiques/C-501-a.md); проходного по тому же ключу позже НЕТ
вердиктов в диапазоне: судимых 2, без шапки 0; ключей 1; погашено токеном 0
VERDICT: FAIL (1)        exit=1

=== E1b: контроль — ТОТ ЖЕ диапазон, HEAD = вершина ветки (форма пробы VG-7) ===
VERDICT: PASS            exit=0

=== E1d: push-событие на main после слияния того же круга ===
FAIL  ключ M-72: ...     exit=1
```

**Рецепт из вывода барьера — ложь в прод-форме.** Сообщение (`:300`) предписывает:
«погашение — вердикт с проходным исходом по ключу ОТДЕЛЬНЫМ коммитОМ позже». Исполнено
буквально (E1c: добавлен ТРЕТИЙ коммит с PASS тем же ключом, merge пересобран):

```
FAIL  ключ M-72: последний вердикт диапазона — REJECT ...; проходного по тому же ключу позже НЕТ
вердиктов в диапазоне: судимых 3 ...   exit=1
```

Текст «проходного по тому же ключу позже НЕТ» печатается при двух проходных, лежащих позже
по топологии ветки. Агент, следующий подсказке, попадает в цикл «добавь вердикт → всё ещё
красное» без диагноза; единственный работающий выход — токен, то есть исключение становится
обязательным ритуалом на КАЖДОМ исправительном круге — ровно класс «токен-ритуал неотличим
от его отсутствия», от которого барьер открещивается сам (`:63-66`).

**Проба гоняет суррогат, а не прод-форму.** `run_sut` (`scripts/tests/red_verdict_gate.sh:86-92`)
всегда вызывает барьер с HEAD = вершина ветки; ни один из 34 сценариев не ставит HEAD на
merge-коммит ветки в main. Нарушено свойство 1 «Целостности гейта» (`testing.md`): «прогоняет
ПРОД-ФОРМУ, а не суррогат — тот же путь вызова, что у прода». VG-32 (merge-born) проверяет
evil merge, но не форму HEAD.

**Самореференция, делающая блокер немедленным.** Этот трек сам заводит ОБЩИЙ ключ `C-110`
для трёх адверсариев. Настоящий файл — REJECT с ключом `C-110`. После его влития в ветку
предмета НИКАКОЙ более поздний проходной вердикт ключа `C-110` не откроет PR ветки в
прод-форме (E1a); ветка ляжет в main только через `VERDICT-CLEARED: C-110 — …`. Барьер
блокирует приземление собственного гейт-трейла с первого же употребления.

**Условие снятия.**
1. Проба несёт сценарий «исправительный круг, HEAD = merge ветки в main ⇒ PASS» и сценарий
   push-формы с merge-HEAD — оба обязаны быть КРАСНЫМИ против текущей реализации
   (предъявить), зелёными после фикса.
2. Позиция файла не наследуется от merge-разворота против первого родителя; fail-closed путь
   «позиция недоказуема» остаётся только для файлов, реально рождённых merge'ем (evil
   merge, VG-32 держит).
3. Текст подсказки не утверждает «позже НЕТ», когда решение принято тай-брейком.
Дизайн фикса — за автором (`gates.md` §4, граница reviewer↔architect по духу).

## F-111-2 — BLOCKER. Отставшая база PR: барьер судит чужие вердикты из main

**Что сломано.** База берётся из события (`:124-148`) — это правильно против B1 — но на
pull_request `PR_BASE_SHA` фиксируется при создании PR и не следует за `main`, а HEAD
(`refs/pull/N/merge`) содержит ТЕКУЩИЙ `main`. Тогда `git diff BASE HEAD` (`:212`) включает
вердикты, влитые в `main` ЧУЖИМИ PR за окно отставания, и они судятся как предмет ветки.
Шапка барьера обещает судить «вердикты, принесённые самим диапазоном» ветки — под отставшей
базой это молча расширяется до чужих.

**Воспроизведение на РЕАЛЬНОЙ истории.** PR #18 (`docs/P-012-decision`, невинный) слит
merge-коммитом `1a94c580`, чей первый родитель — `81dcbc13` (merge PR #19, несущего
`R-090` REJECT). Если база PR #18 отстала на ОДИН merge (зафиксирована до слияния #19):

```
EVENT_NAME=pull_request PR_BASE_SHA=1a0270e3  (HEAD=1a94c580)
FAIL  ключ R-090: последний вердикт диапазона — REJECT (research/reviews/R-090-pending-signature-recheck.md); ...
VERDICT: FAIL (1)   exit=1        # отставшая база
EVENT_NAME=pull_request PR_BASE_SHA=81dcbc13
VERDICT: PASS       exit=0        # свежая база
```

Тот же исход на герметичной фикстуре (E2): docs-ветка без единого вердикта краснеет по ключу
`A-010` из чужого merge. Частота окна — замер по последним 34 merge'ам `origin/main`:
**7 слияний из 34 (21 %) несут отказной вердикт** — каждое ~5-е слияние открывает окно, в
котором КАЖДЫЙ открытый PR с отставшей базой красен по чужому ключу.

**Цена для невинного агента.** Снять красное он может только: (а) вписав
`VERDICT-CLEARED: <чужой-ключ> — <причина>` — аттестуя устранение находок, о которых ничего
не знает (принуждение к ложному аудит-следу); (б) пересоздав PR ради свежей базы — путь
нигде не назван. Оба хуже честного отказа.

**Предел честности замера.** Отставание `base.sha` — посылка мандата («GitHub обновляет
base.sha не мгновенно»); в сеть я не ходил и на живом GitHub его не мерил. Механика
доказана герметично: ЛЮБОЕ отставание базы при рефьюз-несущем merge в окне даёт красное.

**Условие снятия.** Субъект суждения — изменения ВЕТКИ, а не окна отставания: например, на
pull_request сужать диапазон до merge-base с первым родителем HEAD (он и есть текущий main
в прод-форме) — решение за автором; проба несёт сценарий «отставшая база + чужой отказ в
окне ⇒ PASS» (красный против текущей реализации). Если автор решит оставить поведение —
предел объявляется в шапке явно, с названным дешёвым выходом для невинного PR.

## F-111-3 — MAJOR. Правка старого вердикта (link-fix) пере-судит его целиком

`--diff-filter=AM` (`:212`) судит и Modified. Починка висячей ссылки в историческом REJECT —
штатная работа (§9 `gates.md` требует «связность и висячие ссылки»; правки идут по всему
`research/`):

```
=== E-mod: link-fix в СТАРОМ отказном вердикте ===
FAIL  ключ R-090: последний вердикт диапазона — REJECT (research/reviews/R-090-old.md); ...
exit=1
```

Токен здесь снова требует причины «почему отказ погашен» от агента, чинившего ссылку.
**Условие снятия:** судить M-файлы только при изменении блока GATE-META (снятие/подмена
исхода — реальная угроза, её ловить надо), либо явно назвать предел в шапке + путь выхода
для косметической правки. Проба — сценарий «link-fix тела старого отказного вердикта ⇒ PASS»
и «правка шапки СТАРОГО вердикта ⇒ судится».

## F-111-5 — NOTE. «Штатного пути погашения» не существует в природе этого репозитория

Реплей барьера по 34 последним merge'ам `origin/main` (обе формы: push-прод-форма
HEAD=merge, PUSH_BEFORE=первый родитель; и авторская HEAD=вершина ветки): 7 красных на 6 PR —
поимённо #7 (`M-60` ESCALATE + `M-60b` REJECT), #13 (`C-092`), #19 (`R-090`), #27 (`R-4`,
три REJECT подряд), #31 (`PR-31`), #34 (`A-010`); 27 зелёных. Совпадает с замером шапки —
шапка честна. Но: **ни в одном из 34 диапазонов ни разу не встретился паттерн «отказ, позже
погашенный проходным ТЕМ ЖЕ ключом»** — ключи в практике преимущественно собственные номера
вердиктов (`R-090` → перепроверка легла как `R-091` NOTE со СВОИМ ключом — merge PR #19 был
человечески законен, барьер держал бы его как непогашенный). Это не случайность практики, а
следствие нормы: `gates.md` §12 — «продолжение по предмету берёт СВОЙ номер», а конвенции
«что писать в `milestone:` повторного круга» нет нигде. Итог: путь погашения вердиктом
мёртв дважды (нормой §12 — и F-111-1 в прод-форме), выход один — токен, 7 из 7 случаев.
**Условие:** конвенция ключа (общий предмет, как `C-110` этого трека, а не свой номер)
закрепляется тем же чейнджсетом, что барьер, и проба держит её положительным примером.

## F-111-6 — NOTE. Squash-merge стирает токен из тел коммитов

`VERDICT-CLEARED` живёт в теле коммита ветки; squash-слияние тел не сохраняет — push-событие
на `main` красное один прогон, деплой замирает fail-closed до следующего push. Норма
предписывает `gh pr merge --merge` — предел назван, не блокер. Самовосстановление: следующий
push диапазоном squash-коммит не захватывает.

## Ответ на вопрос оси: цена ложного красного и путь снятия без подделки токена

- **Цена.** Джоб в агрегате ⇒ красное держит merge ВСЕХ PR (F-111-2 красит и невинные), а
  push-форма красит сам `main` (деплой замирает fail-closed). По замеру: 21 % реальных
  merge'ей несли отказ ⇒ при действующем барьере каждый из них — стоп до токена; окно после
  каждого такого merge — риск красного для всех отставших PR.
- **Путь снятия без подделки.** Для СВОЕГО исправительного круга токен честен (находки
  устранены — причина правдива), но он ЕДИНСТВЕННЫЙ работающий путь (F-111-1 закрывает
  вердиктный), чего дизайн не признаёт. Для ЧУЖОГО ключа (F-111-2) и косметики (F-111-3)
  честного токена НЕТ: агент не может аттестовать устранение чужих находок — остаётся
  пересоздание PR (не документировано) либо ложь в аудит-следе. Барьер, чей единственный
  выход — недоступный честному агенту токен, будет «объявлен шумом и выключен»
  (`harness-track.md` §3) — и потянет за собой доверие к соседним честным барьерам агрегата.
