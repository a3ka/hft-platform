# Вердикты гейтов с БРОШЕННЫХ линий истории — архив, а не воскрешение

**Заведено architect'ом 2026-08-24** по решению founder'а, найдено раскопками потерянной
между сессиями работы.

## Почему архив, а не `research/critiques/`

Попытка положить эти файлы в штатные каталоги вердиктов была сделана и **отбита барьером**,
и барьер прав:

```
$ EVENT_NAME=push PUSH_BEFORE=<main> bash scripts/check_gate_meta.sh
FAIL  research/arbitration/A-011-…: audited_head «0b0cef23…» НЕ предок HEAD — аудировалась
      другая линия истории
VERDICT: FAIL (10)      ← состав ЭТОГО архива: десять файлов, десять FAIL
```

Число названо точно (`R-124` Б-2). Первая попытка автора включала одиннадцатым `C-094-M-68.md`
и давала `FAIL (11)`; он из архива исключён (см. «Чего здесь НЕТ»), поэтому цитировать `11`
рядом с составом из десяти значило бы приводить прогон, которого этот архив не производит.

Проверка `git merge-base --is-ancestor <audited_head> HEAD` (`check_gate_meta.sh:371`)
**безусловна, обхода у неё нет намеренно** — это класс `C-062`: вердикт, вынесенный над
историей, которой в этом репозитории нет. Токен `ARCHIVED-VERDICT` её не открывает и не
должен: он заведён для до-нормативных артефактов БЕЗ шапки, а не для шапки, чья ревизия
лежит на другой линии.

Существо: у этих вердиктов **предмет действительно не в `main`**. Положить их в
`research/critiques/` значило бы утверждать обратное. Архив говорит правду: работа была,
вердикт вынесен, линия брошена.

## Что эти вердикты говорят о процессе, а не о предметах

**ОДИН `ESCALATE` не получил арбитра — `C-114`.** `gates.md` §0 триггер 3: «Вердикт
`ESCALATE` от critic/risk-critic» — созывается арбитр. По `docs/plan-abc-2026-08-20` арбитра
нет: `ls research/arbitration/` в `main` не содержит решения об этом предмете.

**`C-109` арбитра ПОЛУЧИЛ, и им был `A-011`** — файл, лежащий строкой выше в таблице этого же
README. Первая редакция абзаца утверждала обратное; опровержение лежало в предъявляемом
документе (`R-124` Б-1):

```
$ sed -n '11p;14p' A-011-process-package-dispute.md
**Созыв:** `gates.md` §0, триггеры 2 (три круга по одному предмету), 3 (`ESCALATE` от critic)
**Круги:** `C-106` REJECT · `C-107` REJECT · `C-109` ESCALATE — прочитаны целиком с диска.
```

**`C-110`/`C-111`/`C-112` — НЕ три круга, и триггер 2 НЕ срабатывал** (`R-124` Б-3). Все три
несут ОДИН `audited_head`:

```
$ grep -m1 'audited_head' C-11{0,1,2}-*.md | awk '{print substr($2,1,12)}'
```

(Вывод показан ровно так, как его печатает команда — тремя строками. `R-125` NOTE-3: прежняя
редакция склеивала их через `·`, то есть показывала вывод, которого команда не производит.
Класс `R-097` N-7 — в разделе, где утверждение держится на прогоне, показанное обязано быть
произведённым.)

Предмет между вердиктами не менялся — исправительных кругов не было; `C-111` сам называет их
«тремя адверсариями» с общим ключом. Это ОДИН круг из трёх параллельных осей. Триггер 2
говорит о ТРЁХ КРУГАХ по предмету, то есть о несходимости итераций, и здесь не применим.
Заморозка предмета стоит на `П-017` A2 и в этом триггере не нуждается.

аудит-трейл.
