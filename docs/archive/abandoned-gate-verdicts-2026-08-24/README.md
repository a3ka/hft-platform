# Вердикты гейтов с БРОШЕННЫХ линий истории — архив, а не воскрешение

**Заведено architect'ом 2026-08-24** по решению founder'а, найдено раскопками потерянной
между сессиями работы.

## Почему архив, а не `research/critiques/`

Попытка положить эти файлы в штатные каталоги вердиктов была сделана и **отбита барьером**,
и барьер прав:

```
$ EVENT_NAME=push PUSH_BEFORE=<main> bash scripts/check_gate_meta.sh
FAIL  research/arbitration/A-011-…: audited_head «0b0cef23…» НЕ предок HEAD — аудировалась
      другая линия истории
VERDICT: FAIL (11)
```

Проверка `git merge-base --is-ancestor <audited_head> HEAD` (`check_gate_meta.sh:371`)
**безусловна, обхода у неё нет намеренно** — это класс `C-062`: вердикт, вынесенный над
историей, которой в этом репозитории нет. Токен `ARCHIVED-VERDICT` её не открывает и не
должен: он заведён для до-нормативных артефактов БЕЗ шапки, а не для шапки, чья ревизия
лежит на другой линии.

Существо: у этих вердиктов **предмет действительно не в `main`**. Положить их в
`research/critiques/` значило бы утверждать обратное. Архив говорит правду: работа была,
вердикт вынесен, линия брошена.

## Что эти вердикты говорят о процессе, а не о предметах

**Два `ESCALATE` не получили арбитра.** `gates.md` §0 триггер 3: «Вердикт `ESCALATE` от
critic/risk-critic» — созывается арбитр. `C-109` и `C-114` повисли. Отдельно
`feat/harness-verdict-gate` набрал ТРИ круга (`C-110`→`C-111`→`C-112`) — это триггер 2 того
же §0, арбитр тоже не созывался.

Это тот же класс, что стоил семи кругов на PR #65 и был назван уроком №1 передачи
`session-handover-2026-08-24`. Здесь он предъявлен ещё двумя экземплярами, оба — ДО того
инцидента.

## Содержимое не правлено

Перенос побайтный. Известный дефект сохранён и назван, а не исправлен задним числом:
`C-101` озаглавлен внутри как `C-100` — след разводки коллизии идентификаторов
(`d6e6c31`, `A-010` §E). Править текст чужого вердикта при архивировании значит подделывать
аудит-трейл.
