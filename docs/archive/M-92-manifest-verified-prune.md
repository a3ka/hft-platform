## 1. Objective

Уборщик журнала удаляет локальный сегмент ТОЛЬКО если sha256 этого сегмента совпала с суммой,
посчитанной НА СТОРОНЕ офсайт-копии (Storage Box), по имени файла. Отбор кандидатов — прежний
`retention_plan`. Копирования «в холодный каталог» ни на каком пути нет. Это программа той же
процедуры, что исполнена вручную 2026-09-08 и 2026-10-01.

## 4. Форма — задана ДОСЛОВНО (RED компилируется против этих имён)

```rust
// crates/journal/src/segments.rs — АДДИТИВНО, ре-экспорт из crates/journal/src/lib.rs
pub struct ColdManifest { /* имя файла → sha256 hex */ }
impl ColdManifest {
    /// Строки вывода `sha256sum`: `<64 hex>  <имя>`; пустые строки пропускаются; имя без '/';
    /// точный дубль строки допустим, дубль имени с другой суммой — Err.
    pub fn parse(text: &str) -> std::io::Result<ColdManifest>;
}
/// Как `retention_execute`, но доказательство — совпадение с манифестом; НИКОГДА не копирует.
/// Удаление — ТОЛЬКО `prune_segment(seg, proof)`; `ColdCopyProof` чеканит отдельная функция сверки
/// с манифестом (приватный конструктор), в теле удаления нет ни `remove_file`, ни литерала
/// `ColdCopyProof { … }` (`R-217` Б-2; шаг гейта `task1-proof`). Граница — позиции КАТАЛОГА (`I-2ter`).
/// Кандидаты обходятся по возрастанию индекса; первый неподтверждённый (нет строки, сумма
/// не совпала, ошибка чтения или удаления) обрывает удаление — младшие идут в `failed`
/// с причиной `blocked-by <имя>` (`I-2bis`).
/// `ColdCopyProof` выдаётся только при равенстве sum(local) == manifest[name] (приватный конструктор
/// сохраняется — тот же типовой барьер).
pub fn retention_execute_with_manifest(dir: impl AsRef<Path>, plan: &RetentionPlan,
    policy: &RetentionPolicy, manifest: &ColdManifest, mode: RetentionMode) -> io::Result<RetentionReport>;
```

**Бинарь `journal-retention`:** `--plan-out <файл>` (имена `plan.offload_and_prune`, по одному в строке,
в любом режиме); `--cold-manifest <файл>`; в `--mode apply` `--cold-manifest` обязателен, `--cold` —
отказ (`exit 1`, сообщение называет `R-180` F-1). Несовпадение/отсутствие строки — `exit 2`, имена в выводе.

**Скрипт `deploy/bin/journal-retention-cron.sh` (контракт, проверяемый `c1`/`c2`):**
1. `RETENTION_RUNNER … --mode dry-run --plan-out=/work/plan.txt` — план;
2. `${RETENTION_REMOTE_SHA_CMD} journal/<имя>…` по именам плана → `RETENTION_WORK_DIR/manifest.txt`
   (префикс `journal/` снимается); дефолт шва — `ssh -i ${JOURNAL_OFFSITE_SSH_KEY} -o IdentitiesOnly=yes
   -p ${JOURNAL_OFFSITE_SSH_PORT} <user@host из JOURNAL_OFFSITE_DST> sha256sum`;
3. **режим — ТОЛЬКО файл-переключатель** `${RETENTION_MODE_FILE}` (дефолт `/var/lib/hft/retention.mode`) с содержимым `apply`;
   файла нет или в нём иное ⇒ `dry-run`; переменная `RETENTION_MODE` окружения режим НЕ задаёт (`/etc/cron.d`
   перезаписывается каждым кодовым деплоем — так 2026-09-23 была стёрта строка `CHECKPOINT_BANDS`). При `apply` —
   `RETENTION_RUNNER … --mode apply --cold-manifest=/work/manifest.txt`;
4. аудит-след (`A-044` O-1…O-3) — в `RETENTION_AUDIT_DIR` (дефолт `/var/lib/hft/prune-audit`):
   - три записи с суффиксами `…plan.txt` (имена кандидатов, по строке), `…manifest.txt` (строки `sha256sum`
     С КОРОБКИ, ровно тот файл, что передаётся бинарю в `--cold-manifest`) и `…report.txt`;
   - **формат отчёта — дословно:** одна строка на имя плана: `pruned <имя>` либо `kept <имя> <причина>`
     (у младших за обрывом префикса причина — `blocked-by <имя>`, `I-2bis`)
     (причина непуста, например `mismatch local=<sum> remote=<sum>` или `absent-remote`);
   - **отчёт — ТОЛЬКО строки формата** (без заголовка и комментариев); второй токен — голое имя
     файла (`A-045` §2);
   - **уникально БАЗОВОЕ имя файла каждой записи**, плоско в `RETENTION_AUDIT_DIR`; подкаталог на
     прогон (`prune-audit/<run_id>/…`) НЕ достаточен — `c4` сравнивает базовые имена (замер `A-045`);
   - **имена уникальны на ПРОГОН** (дата недостаточна: ручной прогон и cron в тот же день столкнутся) —
     записи прошлых прогонов не перезаписываются;
   - **порядок:** план и манифест записаны в аудит-след ДО `apply`; отчёт — после;
   - **носитель аудита недоступен** (каталог не создаётся / запись не удалась) ⇒ `apply` НЕ зовётся, выход
     ненулевой, тревога; то же в `dry-run` — ненулевой выход;
5. ненулевой выход бинаря — тревога (как сегодня).
`RETENTION_WORK_DIR` (дефолт `/var/lib/hft/retention-work`) монтируется в контейнер как `/work`.

**compose, сервис `journal-retention`:** журнал — **rw** (удаление); `gateway-ckpt:/ckpt:ro` (артефакт
покрытия); `${RETENTION_WORK_DIR}:/work`; монтирование `/cold` и переменная `JOURNAL_COLD_DIR` удаляются.

## 6. Пределы, названные честно

1. **Манифест — недоверенный вход с другой машины.** Подделка манифеста (тот, кто владеет хостом,
   владеет и ключом коробки) не ловится — ловится порча и отсутствие копии. Это тот же предел, что у
   ручной процедуры 01.10.
2. **Снапшотов на коробке нет** (`П-023`): ключ прода умеет удалять копию. M-92 на коробке не удаляет
   ничего; снапшоты — решение founder'а (стоят денег).
3. **Пользователь теряет локальную историю старше `RETENTION_RETAIN_DAYS`** — двухъярусное чтение
   (`П-023` п.3) не построено. Так же было после 08.09 и 01.10.
4. **Старый `verify_cold_copy` остаётся в библиотеке** для существующих sacred-оракулов `red_retention*`;
   с прод-пути (`apply` бинаря) он недостижим (`b1`). Снятие — отдельной ревизией тест-корпуса.
5. **Инвариант удаления в `docs/fa/journal.md` отсутствует** (`R-180` F-5; первый свободный `JR-I-13`).
   Задача 5 вносит его — правка формы FA, судится тем же критиком.
