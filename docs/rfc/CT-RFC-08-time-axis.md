## §0. Факты (все — замером, `origin/main` @ `0b4a398`)

1. **Контракт обещает:** «время — mono_ns для порядка» (`crates/contracts/src/lib.rs:5`);
   то же — `docs/DESIGN.md` §3, `docs/05-contract-layer.md:51`, `docs/fa/journal.md:68`
   («длительность/порядок»).
2. **Реализация даёт:** `epoch: SystemTime::now()` при КАЖДОМ открытии журнала
   (`crates/journal/src/lib.rs:110` — `open()`, `:167` — `open_with()`);
   `ts_mono_ns = SystemTime::now().duration_since(self.epoch)` (`:205-213`).
   Следствия: обнуление на каждом рестарте recorder'а (рестарт = каждый деплой, TD-086);
   немонотонность внутри сессии при NTP-отводе (`SystemTime` — не steady;
   `duration_since` при отводе → `Err` → `unwrap_or(0)`); осью порядка поле не является —
   порядок несёт `seq`.
3. **Сломанные консюмеры — ЧЕТЫРЕ** (rev2: +strategy, `C-056` B2):
   - `crates/alpha/src/lib.rs:191-192` — stale-expiry сигнальных сэмплов (TD-081, AL-I-4):
     через границу рестарта сэмплы прошлой сессии «свежи вечно»;
   - `crates/strategy/src/lib.rs:102` — TTL-expiry in-flight интентов
     (`ev.ts_mono_ns <= submitted_ts_mono_ns + ttl_ns`, ST-I-3): тот же класс — через
     границу рестарта интенты не протухают;
   - `crates/sim/src/exchange.rs:108,141` — latency-модель (зрелость ордеров/отмен по оси):
     через границу рестарта ось падает → зрелость искажена; бэктест по журналу с рестартом
     тихо неверен;
   - `crates/signals/src/obi.rs:120` — транзитивный источник (штампует `ts_event_mono_ns`
     для alpha).
   Транзитивные ПЕРЕНОСЧИКИ значения (не сравнивают ось, но прокидывают её в метрики):
   `crates/sim/src/strategy_backtest.rs:119`, `crates/research-cli/src/grid.rs:388`.
4. **Прод-read-path поле НЕ использует:** `grep ts_mono_ns crates/gateway*/src` → 0;
   агрегаты сидят на `ts_exch_ms` (`crates/gateway/src/lib.rs:90,748`) и `seq`.
5. В журнале ~157.9M событий с текущей семантикой (замер VPS 2026-08-03); они не
   переписываются никогда (append-only, CT-I-3). Прод-каталог содержит МНОГО сессий:
   значение оси у хвоста может быть НИЖЕ исторического максимума (короткая последняя
   сессия после длинной) — существенно для §2.1/§2.2.

## §1. Проблема одним абзацем

T1-поле обещает больше, чем даёт: читатель, поверивший докстроке, пишет корректный код
против несуществующей гарантии — уже четырежды (§0.3). Пока execution отложен, цена —
искажённый research (sim) и мёртвые expiry (alpha/strategy — оба в будущем live-пути);
при входе в execution та же ось попадает в latency-замеры и SLA — цена станет денежной.

**Двухчастная природа фикса (урок B1 вердикта `C-056`):** (а) сама ось чинится до
монотонной; (б) но expiry-консюмеры (alpha/strategy) меряют не «порядок», а **физическую
давность данных** — им монотонная ось НЕ достаточна по построению (простой писателя в
монотонную ось не входит). Поэтому решение раздвоено: JR-I-13 для оси (§2.1–§2.4) +
перевод expiry-консюмеров на физическое время (§2.5) — это НЕ «детект регрессии»,
отвергнутый вердиктом, а смена измеряемой величины.

## §2. Решение

### 2.1. Семантика поля (новая нормативная докстрока T1)

> `ts_mono_ns` — **монотонно неубывающая ось эпохи честности**: для любых событий одного
> журнала, записанных в сегменты `schema_version >= 5`,
> `seq_a < seq_b ⇒ ts_mono_ns_a <= ts_mono_ns_b` (JR-I-13). Внутри одной сессии писателя
> разности — физические наносекунды steady-clock; **через границу сессии разность НЕ
> является длительностью** (простой писателя в ось не входит). Физическая давность/
> длительность через границы сессий — только по `ts_wall_ms`/`ts_exch_ms`.
> Для сегментов `schema_version <= 4` монотонность не гарантируется ДАЖЕ внутри журнала
> (ось стартовала с нуля на каждой сессии и подчинялась wall-clock); граница эпох
> машинно-читаема из `SegmentHeader.schema_version`.

Сужение до эпохи ≥5 — ответ на `C-056` B4: сшивку нового с legacy-историей гарантировать
нельзя, не солгав (хвост-значение ≠ исторический максимум — §0.5; полный скан ~27 GB ради
one-time якоря — цена без выгодополучателя: все консюмеры §0.3 переводятся на физическое
время либо gap-детект, §2.5). Честное сужение вместо ложной глобальной гарантии.

### 2.2. Реализация записи (O2-rev2: tail-anchor + durable high-water)

1. **Ось внутри сессии:** `ts_mono_ns = mono_base + (instant_now − instant_at_open)` —
   `std::time::Instant` (steady). NTP не влияет по построению.
2. **`mono_base` — по той же лестнице доверия, что `next_seq`** (требование `C-056` B3:
   ось получает второй durable-источник, как `seq` имеет `journal.meta`):
   - `journal.meta` расширяется версионированно: к `next_seq` добавляется
     `mono_high_ns` — high-water оси, пишется тем же атомарным `write_meta`
     (tmp+rename, `segments.rs:349-354`) на каждом flush. Старый 8-байтовый файл
     читается как «`mono_high` отсутствует» (совместимость);
   - `mono_base = max(meta.mono_high_ns, mono последнего события читаемого хвоста)` —
     ровно формула `resolve_next_seq_with` (`segments.rs:1466-1476`), применённая ко
     второй величине. Случай «мета есть, сегментов нет» (restore/карантин — `C-056` B3б)
     закрыт: ось продолжается с меты, JR-I-13 держится;
   - **хвост нечитаем** (M-49-путь, `resolve_next_seq_or_declared`,
     `segments.rs:2158-2200`): операторская декларация `journal.force-next-seq.json`
     расширяется полем `force_mono_floor_ns` (та же дисциплина, что `force_next_seq`);
     при нечитаемом хвосте И отсутствии `mono_high` в мете open **отказывает** без
     декларации нового поля — fail-closed, зеркально JR-I-8. С декларацией →
     `mono_base = max(meta.mono_high_ns?, force_mono_floor_ns)`;
   - журнал пуст (нет ни меты, ни сегментов) → `mono_base = 0`.
3. **Guard в `append`** (fail-closed против недосмотра): назначаемый
   `ts_mono_ns < последнего назначенного` → кламп в неубывание + счётчик
   `mono_clamped_total` в heartbeat (аддитивное поле безопасно: `HeartbeatSample` без
   `deny_unknown_fields` — проверено критиком, `C-056` N5).
4. **Порядок операций в `open_with` — в запретный список milestone'а** (`C-056` N4):
   `mono_base` снимается ДО `decide_open_segment` (`lib.rs:136` перед `:141`) — бамп
   схемы гарантированно откроет новый сегмент, и якорь, снятый после решения, увидел бы
   пустой хвост.

### 2.3. Отвергнутые альтернативы (обязательная секция)

- **O1 «только передокументировать»**: перекладывает инвариант на дисциплину каждого
  будущего читателя — конструкция «правило вместо гейта», систематически не
  выдерживающаяся в проекте. Отвергнуто.
- **O3 «ось как производная от wall»** (`max(prev+1, ts_wall_ms×1e6)`): квантует
  внутрисессионный шаг до ~мс, убивая ns-дельты latency-модели sim. Отвергнуто.
- **Глобальный JR-I-13 через one-time полный скан истории** (вариант (i) `C-056` B4):
  цена — скан ~27 GB при первом schema-5 open; выгодополучателя нет (§2.1). Отвергнуто
  в пользу честного сужения до эпохи ≥5.
- **Детект регрессии оси как фикс expiry-консюмеров** (rev1 §2.5): опровергнут `C-056`
  B1 — на schema-5 данных регрессии нет, а простой писателя невидим для монотонной оси
  по построению. Отвергнуто; замена — §2.5.
- **Новый `SysEvent`-маркер «писатель перезапустился»** как источник границы сессии:
  работал бы, но это настоящий аддитивный вариант T1-enum с отдельной ценой (bump эпохи,
  match-ревизия по workspace — RN-8), при том что вся нужная информация УЖЕ есть в каждом
  событии (`ts_wall_ms`) и в `SegmentHeader`. Отвергнуто как избыточное; может быть
  введён позже отдельным RFC, если появится консюмер, которому граница сессии нужна
  ТОЧНЕЕ, чем wall-gap.
- **Переименование поля / новый вариант схемы:** ломает консюмеров ради имени при
  неизменной сериализации. Отвергнуто.

### 2.4. Граница эпох: бамп `SCHEMA_VERSION` 4 → 5 + расширение её нормы

Wire-формат не меняется, но меняется СЕМАНТИКА эмитируемых данных ⇒ бамп
`SCHEMA_VERSION` 4 → 5: сегмент schema-5 = «JR-I-13 держится»; реюз сегмента schema-4
бинарём schema-5 запрещён механикой `decide_open_segment` (`segments.rs:2278`) —
граница честности машинно-читаема, миграция данных не нужна.

**Нормативная правка докстроки `SCHEMA_VERSION` — часть ЭТОГО RFC** (закрытие открытого
вопроса rev1, `C-056` N1; заодно закрывает класс Д1 «смена семантики при неизменной
форме»): формулировка «Bump'ится при КАЖДОМ новом варианте» (`contracts/src/lib.rs:13-19`)
расширяется до:

> Bump'ится при КАЖДОМ новом эмитируемом варианте **И при любом изменении СЕМАНТИКИ
> эмитируемых данных при неизменной форме** (пример: CT-RFC-08 — семантика `ts_mono_ns`).

Основание законности: `05-contract-layer.md` §4 и так требует bump в составе любого
contract-RFC; `decide_open_segment` использует версию как машинный маркер изоляции
эпохи — семантическая эпоха изолируется тем же механизмом, что вариантная.

### 2.5. Консюмеры (та же milestone-связка, RED-first) — rev2 по `C-056` B1/B2

Принцип: **expiry меряет физическую давность — физическим временем.** `ts_wall_ms` есть
в каждом событии; под новой осью он остаётся единственным сквозным физическим временем.
Поведение при NTP-аномалиях объявляется, не подразумевается:

- **alpha (TD-081/AL-I-4):** freshness переводится на wall:
  `fresh = ev.ts_wall_ms <= sample.ts_wall_ms + horizon_ms` (сэмпл получает wall-штамп —
  T3-правка `SignalOutput`/`obi`, внутренняя для конвейера). Отвод часов назад
  (`ev.ts_wall_ms < sample.ts_wall_ms`) → сэмпл объявляется stale — fail-closed в
  сторону штиля. Форвард-скачок часов → преждевременный stale — приемлемая полярность
  (отсутствие мнения, не edge по протухшим данным; существующая семантика
  `den_fresh == 0`).
- **strategy (ST-I-3):** TTL in-flight интентов — та же схема на `submitted_ts_wall_ms`;
  обратный ход wall → интент истекает немедленно (fail-closed: лучше пере-отменить, чем
  держать намерение неограниченно).
- **sim:** внутрисессионные ns-дельты остаются на оси (для них она честна). Граница
  простоя писателя детектируется БЕЗ нового контракта:
  `wall_gap = ev.ts_wall_ms − prev.ts_wall_ms`; `mono_gap = (ev.ts_mono_ns −
  prev.ts_mono_ns)/1e6`; `wall_gap − mono_gap > порог сессионного разрыва` (порог —
  параметр sim; дефолт — дизайн milestone'а) → **консервативная политика разрыва**:
  pending-ордера и pending-отмены считаются отменёнными на границе (пессимизм DESIGN §5:
  через простой писателя fill'ов не бывает), детерминированно и одинаково в ×N прогонах.
- **signals/obi:** добавляет wall-штамп в сэмпл (источник для alpha) — механическая
  правка того же milestone'а.
- **gateway/gateway-serve:** изменений нет (ось не используется — §0.4).

## §5. Что этот RFC НЕ решает (явно)

- Кросс-venue выравнивание часов (`ts_exch_ms` разных бирж) — вне предмета.
- Смена `seq`-семантики — не трогается (ось порядка была и остаётся `seq`).
- Ретро-исправление исторических сегментов — запрещено природой журнала.
- **Шардирование (CT-RFC-07):** JR-I-13 — свойство ОДНОГО журнала (одного писателя).
  В модели шардов каждый шард — свой писатель и свой `mono_base`; слияние шардов по
  `seq` даст немонотонную ось между шардами. При диспетчеризации CT-RFC-07 его §Tasks
  обязан учесть JR-I-13 пошардно (записано сейчас, чтобы не потерять — `C-056` N6).
- Наблюдаемость длительности простоя писателя как продуктовая метрика — тема ops;
  здесь названы только источники (`wall`-гэп).
