## §4. Узел C — переписан целиком (снятие B1 и B2)

### 4.1 Формулировка вместо категорической (снятие B1)

rev1 утверждал «источник НЕ обрезан на 1.3 %». **Это верно только для установившегося
режима.** Точная формулировка, полученная замером и прогоном на собранном крейте @ HEAD:

1. **Установившийся режим — не обрезан биржей.** Пейлоад строится из собственной diff-книги
   адаптера и ограничен **±60 %** от mid: `crates/venue-binance/src/lib.rs:31` `BUCKET_WIDTH`,
   `:33` `MAX_REL_DIST=0.60`, `bucket_levels` `:948-979`. Gateway считает полосы по этому
   пейлоаду: `crates/gateway/src/lib.rs:927-930`, `depth_within` `:1241-1272`.
2. **После старта процесса и после любого sequence-gap — обрезан REST-снимком.**
   `DiffAction::Gap` `:254-267` → `state.book = None` `:259` → `SessionEffect::FetchSnapshot`
   `:263-266` → `fetch_snapshot` с жёстким `limit=5000` `:27`, `:853-855`.
3. **Барьера, удерживающего эмиссию до восстановления глубины, НЕТ.** `resyncing` читается
   **ровно один раз** — для дедупликации `FetchSnapshot` (`:246`); эмиттер смотрит только на
   наличие книги и ненулевое биржевое время (`:369-371`, `:382-384`).
4. **«1.3 %» — число BTCUSDT, не константа.** Замер в репозитории:
   `research/data-quality/depth-probe-binance.md:104-124` — BTCUSDT −1.29 %/+1.33 %,
   **ETHUSDT −4.50 %/+4.40 %**, фьючерсы (`limit=1000`) −0.18 %/+0.19 %.
5. **Пейлоад затирает и книгу gateway:** `crates/gateway/src/lib.rs:910` →
   `book::OrderBook::apply_snapshot`, который `crates/book/src/lib.rs:79-94` делает
   `bids.clear()/asks.clear()` и вставляет уровни снапшота.

**Прогон на собранном крейте @ HEAD:** steady → охват `bid 60.000 % / ask 60.000 %`; после
gap первый же тик эмитит `L2Snapshot` охватом **1.300 %**, полоса 3 % падает 5.00 → 4.00,
полоса 0.1 % не меняется.

**Итог:** источник обрезан **не всегда, а в окне после ресинка/старта, и ровно для полос
глубже фактического охвата REST для данного символа**.

`research/reports/R-001-obi-trackA.md`), а план ограничился фразой «груз в `docs/archive/`»

`feat/M-60-mechanisms` план назвал «19 строк», тогда как замер даёт **23 добавления /
160 удалений** в `milestones/BACKLOG.md`.

**Новая форма:** удаление ref'ов — **отдельный предмет со своим кругом**, предъявляемый в
момент исполнения (`A-011` §1.2). Его предусловие — **артефакт полноты на КАЖДЫЙ ref**,
содержащий:

1. разрешённый SHA ref'а и `git rev-list --left-right --count`;
2. двухточечный `git diff --name-status origin/main origin/<ref>`;
3. для КАЖДОГО добавленного файла — поимённый хранитель в `main`/`docs/archive/**` и
   доказательство эквивалентности (diff или хеш), а не ссылка на каталог;
4. `У-1` (патч + SHA на диске) и `У-2` (живые адресаты) по `R-095`;
5. для `feat/M-60-mechanisms` — **построчная судьба всех 23 добавленных строк** `BACKLOG.md`.

**Пока артефакт не предъявлен и не пройден гейт — ни одна команда удаления не выполняется.**
Предок в другой ветке доказывает **retention графа, а не полноту содержимого** — это
разграничение принято от `C-113` целиком.

**Что остаётся `COGNITIVE-ONLY` и ПОЧЕМУ механизировать нельзя:** проверить, КТО нажал merge,
