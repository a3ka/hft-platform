### 2.1 Причина подтверждена и точнее, чем описана

Предыдущий круг воспроизвёл коллизию (я cargo не запускал — запрет мандата): два дерева, общий `CARGO_TARGET_DIR`, имя бинаря совпало дословно (`red_oracle-b37410301541f367`) ⇒ `-C metadata` не кодирует путь дерева. Ошибка **двусторонняя**: и ложный зелёный, и ложный красный (это и есть M-62).

Уточнение: в тексте «слот принадлежит собравшему **последним**». Замер: после первой сборки не пересобирает никто (1,0,0,0) — cargo сверяет mtime, чекаут worktree старше сборки соседа. **Вердикт замерзает на том, кто собрал ПЕРВЫМ.** Правило с неверным механизмом через месяц породит неверное действие.

### 2.2 Обязанность №2 (`число строк Compiling`) — опровергнутая метрика

```
изолированное дерево, ПОВТОРНЫЙ прогон:   Compiling=0   вердикт ВЕРНЫЙ
отравленный общий target:                 Compiling=0   вердикт ЛОЖНЫЙ
```

`Compiling=0` — нормальное состояние здорового повторного прогона. Требовать эту цифру — завести оракул, **не краснеющий против конкретного слома**. Прямо запрещено файлом, в который вносят: §«Оракул обязан мерить ТО, ЧТО ОБЕЩАЕТ» и §«Целостность гейта», свойство 3.

Различает — **путь исполненного бинаря**, который cargo печатает бесплатно: `Running tests/x.rs (…/debug/deps/x-hash)`. Ноль новых норм.

Добавочно: требование **не доживает до Done Block.** Предписанная агрегация `grep -E "^test result"` вычищает `Compiling` всегда; `tail -10` при 124 строках `Compiling` их тоже не содержит — они печатаются первыми. Норма непроверяема по построению.

### 2.3 Обязанность №1 — коллизия с нормой суточной давности

## 3. П-2 — «`git commit` без путей коммитит весь индекс» → **ВНЕСТИ ПЕРЕПИСАННЫМ + ХУК**

### 3.1 Механика подтверждена мной (песочница, git)

### 3.2 НО текст несёт две ошибки, обе в ключевой фразе «форма ровно одна, и в любом дереве»


### 3.4 Барьер РЕАЛИЗУЕМ — главная находка круга

Хук не видит argv, но **различает по `GIT_INDEX_FILE`** (замерено мной живым хуком):

```
git commit  (без путей)  -> index                     ОТКЛОНИТЬ
git commit -- <путь>     -> next-index-<pid>.lock     ПРОПУСТИТЬ
git commit -a            -> index.lock                ОТКЛОНИТЬ (уже запрещён)
git commit --amend -m    -> index, staged пусто       ПРОПУСТИТЬ (исключение)
автоматический merge     -> pre-commit НЕ вызывается вообще (0 вызовов) — 82 merge/мес не задеты
```

Пропуск обязан быть **белым списком** (`next-index*`), иначе `commit -a` (`index.lock`) проскочит.

Трение околонулевое: из **1025** не-merge коммитов месяца **63 % трогают ровно 1 путь, 91 % — не больше 3** (медиана 1, p90 3, max 22). Сегодня хуков нет: только `prepare-commit-msg.disabled-2026-08-06`, `core.hooksPath` не задан, механизмов установки в репо **0**.

Честная оговорка для самой правки: `.git/hooks` не версионируется (нужен `scripts/install_hooks.sh`), `--no-verify` обходит ⇒ **предупреждающий контур, как docs-freeze**, но срабатывает ДО ущерба, а не после merge.

| класс правки | процедура |
|---|---|
| **изложение** — нумерация, орфография, статус-колонки, обновление устаревшего замера под факт | self-push автора; аудит не нужен (норма §9) |

**Дешёвая замена полного аудита для среднего случая** (80 % ценности за 15 % цены) — обязательная преамбула из четырёх вопросов с замерами в самой правке:

3. Правило **воспроизведено** на предмете (одна песочница)? — поймало бы обе ошибки П-2 и метрику П-1.
4. Что эта правка делает **лишним** (какие строки уходят)? — единственный механизм против храповика; сегодня ни одна из 33 строк не удаляет ничего.

А новый файл здесь — доминирующий случай: каждый артефакт гейта (`research/reviews/R-NNN.md`, `research/critiques/C-NNN.md`, milestone-спека, RED-файл) рождается новым. Правило в текущей редакции для них неисполнимо.
 (б) При merge форма ЗАПРЕЩЕНА самим git (sb2 C): `fatal: cannot do a partial commit during a merge`, exit=128. Merge-коммитов в origin/main за месяц — 82 из 1107 (7 %).
 (в) Третье, мягче (sb2 B): `git commit -- <путь>` берёт РАБОЧЕЕ ДЕРЕВО и молча выбрасывает частичный stage (`git add -p`): застейджено «staged-version», в коммит ушло «worktree-version». Текст об этом молчит.
Правило зоны, которое не отрабатывает на новом файле и падает на merge, вносить в таком виде нельзя.

3) ЧЕСТНО ЛИ РАЗЛИЧЕНИЕ «не покрыто»? Наполовину. Замер origin/main:.claude/rules/branch-hygiene.md, строки 48-51: «## Запрет `git commit -a` / `add -A` в общем чекауте / 1. Никогда ... Только явные пути: `git commit -- PROJECT-STATE.md TECH-DEBT.md`». Предписанная форма уже написана, дословно и с тем же синтаксисом. Честная часть претензии одна и узкая: ЗОНА («в общем чекауте» в заголовке и в п.1), а инцидент случился в worktree. Плюс не назван механизм. Это правка области действия существующего пункта, а не новая норма. Вставлять третью формулировку того же в тот же файл, за 7 строк до уже существующей (новый текст — строки 44-50, действующая формулировка — 50-51), значит рождать расхождение при рождении: старая говорит «в общем чекауте», новая — «в любом дереве».

Содержимое коммита тождественно содержимому индекса (sb1: индекс 3 → коммит 3), поэтому `git diff --cached --stat` из п.9 строки 36 показал бы на b35e57a все 6 путей до коммита, а `git show --numstat HEAD` из той же п.9 — сразу после. 5) МЕХАНИЧЕСКИЙ БАРЬЕР РЕАЛИЗУЕМ, и это главная находка. Хук не видит argv (sb3: `args=''`, GIT_PARAMS нет), но различает по `GIT_INDEX_FILE`: явные пути → `$GIT_DIR/next-index-<pid>.lock`, без путей → `$GIT_DIR/index`. Замерено в обоих случаях. Штатные сценарии проверены живым хуком:
 — автоматический merge: pre-commit НЕ вызывается вообще (sb6 M1 — ни одной строки хука), 82 merge/месяц барьер не трогает;
 — конфликтный merge: вызывается, лечится исключением по `MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD`/`REBASE_HEAD` (sb7: «исключение MERGE_HEAD — пропускаю», exit=0);
 — `--amend` правки сообщения: отвергается, нужен ещё один exempt на ПУСТОЙ staged-набор (sb7, +1 строка);
 — close-out reviewer'а на два файла: `git commit -- PROJECT-STATE.md TECH-DEBT.md` проходит (sb5 T2, exit=0) — это ровно та форма, что уже написана в строке 51;
 — воспроизведение инцидента: отвергнуто с перечислением обоих путей (sb5 T1, exit=1).
Хук общий для всех worktree: `/tmp/hft-arch-rules/.git` = `gitdir: /home/nous/hft-platform/.git/worktrees/hft-arch-rules`, хуки резолвятся в общий `.git/hooks` (подтверждено sb4 случай 6 — сработал в worktree). Сегодня хуков нет: в `.git/hooks` только `prepare-commit-msg.disabled-2026-08-06`, `core.hooksPath` не задан, в репозитории нет ни одного механизма установки (`git ls-tree | grep -i hook` пусто).
Трение околонулевое: из 1024 не-merge коммитов месяца 63 % трогают ровно 1 путь, 91 % — не больше 3 (медиана 1, p90 3).
Честная оговорка, которую надо назвать в самой правке: `.git/hooks` не версионируется, нужен `scripts/install_hooks.sh` и строка в startup, а `--no-verify` его обходит — то есть это предупреждающий контур, как docs-freeze в gates.md §11, а не неподделываемый барьер. Разница с §11 в пользу хука: он срабатывает ДО ущерба, а не после merge.

6) ФОРМА НАРУШАЕТ РЕШЕНИЕ, ПРИНЯТОЕ 10 ДНЕЙ НАЗАД. Из 7 добавленных строк (101 слово, 960 байт) 4 — пересказ вчерашнего случая (SessionInner, session.rs, docker-compose.yml). Ровно этот жанр вырезал 9a9f533 от 2026-08-03 «компрессия правил, нарративы инцидентов убраны», −433 строки, автор — тот же architect. Нормативного содержания здесь на одно предложение.

Вывод: содержание правки нужное, но её место — не п.9 branch-hygiene и не 7 строк текста. Первично — хук (носитель, покрывающий все 40 worktree и не требующий чтения), вторично — правка ЗОНЫ существующего раздела «Запрет» на 5 строк вместо 7 добавленных, с исправлением обеих фактических ошибок. **Дешевле:** Два шага, оба дешевле предложенного.

ШАГ 1 (главный, носитель — не текст). `.githooks/pre-commit` + `scripts/install_hooks.sh` (`git config core.hooksPath .githooks`), ~15 строк, проверено в песочнице:
```sh
#!/bin/sh
GD=$(git rev-parse --absolute-git-dir)
for m in MERGE_HEAD CHERRY_PICK_HEAD REVERT_HEAD REBASE_HEAD; do [ -e "$GD/$m" ] && exit 0; done
git diff --cached --quiet && exit 0            # amend только сообщения
case "$(basename "${GIT_INDEX_FILE:-index}")" in next-index*) exit 0;; esac
echo "ОТКАЗ: git commit без явных путей берёт ВЕСЬ индекс. Форма: git commit -- <путь>…" >&2
git diff --cached --name-only | sed 's/^/  в индексе: /' >&2
exit 1
```
Отвергает воспроизведённый инцидент (exit=1, перечисляя оба пути), пропускает 82 merge/месяц (pre-commit на автоматическом merge не вызывается вообще), пропускает конфликтный merge/revert/cherry-pick/amend, пропускает close-out `git commit -- PROJECT-STATE.md TECH-DEBT.md`. В правилах — одна строка со ссылкой на скрипт и честной меткой, что `--no-verify` его обходит (аудит-след, не подпись), по образцу gates.md §11.

ШАГ 2 (остаток текста — ЗАМЕНА, а не добавление; правится раздел «Запрет», не п.9). Вместо строк 48-51:
```

1. **Никогда `git commit -a` / `git add -A`; `git commit` без путей — тоже.** Он берёт ВЕСЬ

   (merge/revert/cherry-pick и `--amend`) — обязателен `git diff --cached --stat` из п.9.
   Механический барьер — `.githooks/pre-commit` (`scripts/install_hooks.sh`), обходится
```
