запись в `docs/PENDING-SIGNATURE.md`, `П-017` амендмент A2. Здесь — конструкция каждого,

**Порядок, установленный Р-1: сперва замер, потом код.** Если порога без ложных красных не

## 1. Барьер A — негативный ассерт обязан иметь позитивного свидетеля

### Инцидент, который он ловит (ограничитель §3bis(2))

| дата | случай |
|---|---|
| 2026-08-21 | `R-086` §2 — первая половина `O-12` различала инструменты поиском имени символа в кадре, которого кадр не несёт; негативная половина была зелена ВСЕГДА |
| 2026-08-22 | `R-106` Б-1 — ВТОРАЯ половина того же теста, тот же дефект; починив первую, автор не тронул вторую |
| 2026-08-22 | `П-014`, дважды подряд у architect'а: фикстура возвращалась к исходному состоянию; дренаж одним батчем не задействовал проверяемый путь |

Общее: ассерт «ничего лишнего не пришло» истинен, когда не пришло НИЧЕГО ВООБЩЕ.

### ЗАМЕР — общее правило НЕ строится

```
негативных ассертов в crates/*/tests/**:              115 в 47 файлах из 159
тест-функций с негативным ассертом:                   91
  из них со свидетелем:                               23
  БЕЗ свидетеля (краснели бы):                        68  = 75 %
```

**75 % ложных красных — это PR #33 буквально** (там было 36 из 53, и барьер закрыли
арбитром). Большинство законны: `intact_journal_is_not_declared_truncated` утверждает
отсутствие дефекта, и «свидетель» там — сам факт построения фикстуры.

### ЗАМЕР — узкая форма СТРОИТСЯ

Вакуум прячется не в любом негативном ассерте, а в ассерте над результатом ФИЛЬТРА: именно
там предикат может не совпадать НИКОГДА.

```
функций «.filter(...) + негативный ассерт»:            9
  со свидетелем:                                       3
  БЕЗ свидетеля (краснели бы):                         6
```

Шесть — поверхность обозримая, каждый случай проверяем глазами за один заход:

```
red_catalog_equivalence.rs    :: assert_manifest_executed
red_segment_meta_bound.rs     :: assert_catalog_truthful
red_compaction.rs             :: c8_repeated_compaction_self_heals_crash_window
red_replay_digest_delivery.rs :: rd_6_digest_run_is_read_only_on_journal_data
red_retention_compacted.rs    :: rt_z_4_apply_offloads_and_prunes_compacted_segments
red_depth_lifetime_perlife.rs :: dv_i_14_band_is_attributed_per_life_and_output_is_deterministic
```

### Конструкция

```
для каждой тест-функции в crates/*/tests/**.rs:
    если тело содержит `.filter(` И негативный ассерт
       (`assert!(X.is_empty())` | `assert_eq!(X.len(), 0)` | `assert_eq!(счётчик, 0)`)
    то тело обязано содержать позитивного свидетеля
       (`assert!(!X.is_empty())` | `assert!(X.len() > …)` | `assert_eq!(X.len(), N>0)`)
    иначе FAIL
```

**Первый шаг постройки — НЕ код, а разбор шести.** Каждый из них либо получает свидетеля
(тогда барьер зелен на корпусе), либо оказывается законным исключением (тогда нужен явный
опт-аут — комментарий `// NEGATIVE-ONLY: <причина>` в теле функции, и барьер его уважает).
Опт-аут без причины ≥12 символов не засчитывается — форма как у `FOUNDER-APPROVED`.

### Проба — обязательные сценарии

1. фильтр + негативный ассерт без свидетеля ⇒ FAIL;
2. то же со свидетелем ⇒ PASS;
3. негативный ассерт БЕЗ фильтра ⇒ PASS (узость правила, анти-бланкет);
4. опт-аут с причиной ⇒ PASS; опт-аут без причины ⇒ FAIL;
5. setup-guard: пустой каталог тестов ⇒ FAIL, а не тихий ноль.

**Мутации:** снять требование свидетеля ⇒ падает (1); расширить на все негативные ассерты
⇒ падает (3); принять опт-аут без причины ⇒ падает (4).

### Названный предел

Барьер СТРУКТУРНЫЙ. Он не увидит вакуум, спрятанный иначе: предикат, который может совпасть,
но не совпадает на этой фикстуре (`П-014`, случай «фикстура вернулась к исходному
состоянию»), — за пределами разбора текста. Из трёх инцидентов барьер ловит **два из трёх**
(`R-086`, `R-106`); третий — процедурный, и против него работает изолирующая мутация как
шаг приёмки, а не барьер. Это надо сказать в шапке барьера, а не умолчать.

## 2. Барьер B — строка §Tasks не несёт нормативного содержания

### Инцидент (ограничитель §3bis(2))

Класс «расхождение носителей», четыре срабатывания на M-65, два — ПОСЛЕ написанного против
него §10bis той же спеки:

| | что произошло |
|---|---|
| `C-098` B-2 | `Cargo.toml` назначен и задаче 12а, и 12б |
| §Tasks 12б | требовала конструкцию, которую §10.3.1 отвергает абзацем ниже |
| §Tasks 13 | contract-RFC против §11 |
| **`25c323d`** | **строка §Tasks написала «§11 пересмотрен замером» — §11 никто не пересматривал.** Из этого вырос арбитраж `A-015` и разворот решения против architect'а |

Тот же вариант независимо предложен арбитром — `A-015` §6, вариант (а).

### ЗАМЕР — строится

```
строк задач во всех спеках:                    340
с нормативными маркерами:                        6  = 1.8 %, в 4 файлах
```

Шесть строк, все длиннее 120 символов, маркеры «снята», «РЕШЕНО», «снят»:

```
M-09  зад.2   «снята»   len=412      M-38b зад.0c «РЕШЕНО»  len=452
M-38b зад.0b  «РЕШЕНО»  len=446      M-38b зад.0e «РЕШЕНО»  len=377
M-58  зад.4   «снят»    len=284      M-62  зад.6  «снята»   len=126
```

**1.8 % — принципиально иная картина, чем у Р-1** (там совместное правило краснело на
90–100 % корпуса). Причина: Р-1 пытался мерить ДЛИНУ — прокси; здесь меряется НАЛИЧИЕ
нормативного глагола, то есть сам признак.

### Конструкция

```
для каждой строки таблицы §Tasks в milestones/M-*.md, ИЗМЕНЁННОЙ в push-диапазоне:
    если ячейка содержит нормативный маркер
       (пересмотрен | отменён | НЕ требуется | снят | решено | конфликта нет | правится)
    то в ТОМ ЖЕ диапазоне обязан существовать вердикт критика (`research/critiques/C-*.md`),
       называющий этот милестоун,
       ЛИБО тело коммита несёт `TASKS-NORMATIVE: <причина ≥12 символов>`
    иначе FAIL
```

**Судится ТОЛЬКО изменённое в диапазоне** — иначе шесть исторических строк краснят каждый
PR. Это то же решение, что у `check_artifact_ids`: барьер судит вводимое, а не универсум.

### Проба — обязательные сценарии

1. строка задачи с маркером «пересмотрен», без вердикта и без токена ⇒ FAIL;
2. та же строка при наличии `C-*.md` про этот милестоун в диапазоне ⇒ PASS;
3. та же строка с токеном `TASKS-NORMATIVE:` и причиной ⇒ PASS; без причины ⇒ FAIL;
4. строка БЕЗ маркера, любой длины ⇒ PASS (анти-бланкет: не мерим длину — урок Р-1);
5. историческая строка с маркером, НЕ тронутая диапазоном ⇒ PASS;
6. изменение колонки Status (`⏳`→`✅`) ⇒ PASS — dev вправе двигать её один;
7. setup-guard: спека без §Tasks ⇒ SKIP с явной строкой, не тихий ноль.

**Мутации:** снять требование вердикта ⇒ падает (1); судить весь файл вместо диапазона ⇒
падает (5); принять токен без причины ⇒ падает (3); заменить проверку маркера на длину ⇒
падает (4).

### Названный предел

Перечень маркеров конечен и подделываем: «§11 больше не действует» его обойдёт. Барьер
ловит ФОРМУ, а не смысл, и это `COGNITIVE-ONLY`-остаток, который обязан стоять в шапке.
Ценность не в непробиваемости, а в том, что типовая формулировка перестаёт проходить молча:
`25c323d` был бы пойман.

## 4. Воспроизведение замеров

Оба скрипта инлайн, в `scripts/` ничего не добавлено — одноразовый замер не имеет права
увеличивать харнесс (ограничитель §3bis(1)).

**Барьер A** — прогон из корня репозитория:

```python
import re, glob
NEGF = re.compile(r'\.filter\(', re.S)
NEG = re.compile(r'assert!\(\s*[\w.]+\.is_empty\(\)|assert_eq!\(\s*[\w.]+(\.len\(\))?\s*,\s*0\b|assert_eq!\(\s*\w+,\s*0\b')
POS = re.compile(r'assert!\(\s*![\w.]+\.is_empty\(\)|assert!\(\s*[\w.]+\.len\(\)\s*[>=]|assert_eq!\(\s*[\w.]+\.len\(\)\s*,\s*[1-9]')
FN = re.compile(r'^\s*(?:async\s+)?fn\s+(\w+)')
cand=[]; wit=0
for f in sorted(glob.glob('crates/*/tests/*.rs')):
    src=open(f,encoding='utf-8',errors='replace').read().split('\n')
    b=[i for i,l in enumerate(src) if FN.match(l)]+[len(src)]
    for k in range(len(b)-1):
        body='\n'.join(src[b[k]:b[k+1]])
        if not (NEGF.search(body) and NEG.search(body)): continue
        if POS.search(body): wit+=1
        else: cand.append((f.split('/')[-1], FN.match(src[b[k]]).group(1)))
print(len(cand)+wit, wit, len(cand)); [print(*c) for c in cand]
```

**Барьер B** — прогон из корня репозитория:

```python
import re, glob
H=re.compile(r'^(#{2,4})\s+(.*)$'); T=re.compile(r'(Tasks|Задачи|Работы)\b', re.I)
MARK=re.compile(r'(пересмотрен|отменён|отменен|НЕ требуется|не требуется|снят[оа]?\b|решено|конфликта нет|правится)', re.I)
tot=0; hit=0
for f in sorted(glob.glob('milestones/M-*.md')):
    L=open(f,encoding='utf-8').read().split('\n')
    for i,l in enumerate(L):
        m=H.match(l)
        if not (m and T.search(m.group(2))): continue
        lv=len(m.group(1)); j=i+1
        while j<len(L):
            m2=re.match(r'^(#{1,6})\s',L[j])
            if m2 and len(m2.group(1))<=lv: break
            s=L[j].rstrip()
            if s.startswith('|') and not re.match(r'^\|[\s:\-\|]+\|?\s*$',s):
                c=[x.strip() for x in s.strip('|').split('|')]
                if re.match(r'^\**\d+[а-яa-z]?\**$', c[0]):
                    tot+=1
                    if MARK.search(s): hit+=1
            j+=1
print(tot, hit)
```
