## 1. Дефект — разрыв зависимости, а не небрежность

`docs/04-workflow.md` §Close-out разводит роли: закрытость называет reviewer
(`PROJECT-STATE.md` — его зона), переезд спеки и гейта в `docs/archive/` делает architect
(`milestones/*`, `scripts/verify_*` — его зона). Шага «реестр отражает закрытие» нет ни у
одной роли. Reviewer на практике писал закрытость УСЛОВНОЙ — «НЕ ЗАКРЫТ — close-out за
architect'ом», то есть истинность его реестра зависела от действия роли, которая этот реестр
писать не вправе и о нём не думает. После переезда некому было переписать строку.

## 3. Решение: (а) + (б)

**(а) Норма — разрыв зависимости.** Reviewer, признав милестоун закрытым, пишет «ЗАКРЫТ»
сразу; переезд — следствие закрытия, а не условие. Формула «НЕ ЗАКРЫТ — close-out за
architect'ом» запрещена. Текст — `docs/04-workflow.md` §Close-out (таблица ролей + абзац),
строка роли — `.claude/agents/reviewer.md` п.7.

**(б) Механизм — `scripts/check_ps_on_archive.sh`**, шаг джоба `roadmap-sync` (уже в
агрегате `All checks passed` — правка агрегата не нужна). Почему отдельный скрипт, а не
расширение `check_roadmap_sync.sh`: триггер общий, но реестр другой и FAIL-условия другие;
слияние перекрасило бы существующую пробу (`red_roadmap_sync.sh`, её позитивные фикстуры без
`PROJECT-STATE.md`) и смешало бы два независимых отказа в одном exit-коде.

Почему требование выполнимо ролью переезда: architect `PROJECT-STATE.md` не пишет, и барьер
этого не требует. Он требует, чтобы на ВЕРШИНЕ (в PR — дерево слияния) уже стояла запись
reviewer'а — из `main` (reviewer закрыл раньше) либо коммитом reviewer'а на ветке переезда.
Барьер навязывает ПОРЯДОК «назвал закрытым → переехал», которого и не хватало; заодно он
закрывает обратный дефект — вынос спеки, которую reviewer закрытой не называл.

Почему машинный маркер `<!-- MS-STATE: M-NN CLOSED -->`, а не проза: см. попутный замер §2.
Прецедент формы — `GATE-META`, `FACTS` (HTML-комментарий, невидимый при рендере, однозначный
для машины). Суждение reviewer'а не вычисляется — оно записывается им в читаемой форме.

### 3.1. Защищаемый инвариант

> В дереве, где спека M-NN лежит в `docs/archive/`, `PROJECT-STATE.md` несёт маркер
> `CLOSED` для M-NN и не несёт `OPEN`.

Проверки барьера:

| № | что | когда |
|---|---|---|
| 1 | для каждого `docs/archive/M-NN-*.md`, добавленного в диапазоне, на `HEAD` есть маркер `CLOSED` ровно этого номера (`M-69` ≠ `M-690` ≠ `M-69a`), вне блока кода, в КОММИТЕ (не в рабочем дереве) | триггер — переезд |
| 2 | `## `-заголовок раздела M-NN не несёт «close-out за architect» вне «цитаты» и вне `кода` — ровно та фраза, которой реестр лгал 5/5 | триггер — переезд |
| 3 | маркер `OPEN` у милестоуна, чья спека на `HEAD` в архиве | ВСЕГДА |
| 4 | строка `<!-- MS-STATE:` не по форме | ВСЕГДА |
| — | база события: нет события / zero-SHA / база вне истории; `PROJECT-STATE.md` отсутствует в `HEAD` | fail-closed |

### 3.2. Стабы пробы и какой из них убивает какой сломанный барьер

Проба `scripts/tests/red_ps_on_archive.sh`, 30 сценариев (счёт печатается пробой):

- **позитивный контроль (exit 0):** P1 маркер коммитом reviewer'а в том же диапазоне · P2 маркер
  уже в базе · P3 нет переезда · **P4 историческая проза — фраза в «цитате» (форма M-69 на
  дереве)** · **P5 «НЕ закрыт» о другом предмете (форма M-88)** · P6 фраза в `коде` · P7 соседний
  номер M-690 открыт со старой фразой · P8 `OPEN` у живого · P9 буквенный номер M-38a;
- **мутанты реестра (exit 1):** K1 переезд без раздела и маркера · K2 раздел «ЗАКРЫТ» без маркера ·
  K3 маркер `OPEN` · K4 старая фраза, реестр не тронут (форма 5/5) · K5 маркер есть, заголовок
  твердит «close-out за architect» · K6 маркер только в блоке кода · K7 маркер чужого номера
  M-690 · K8 маркер M-69a · K9 маркер только в рабочем дереве · K10 опечатка маркера · K11 без
  переезда: `OPEN` у вынесенного · K12 реестр снесён;
- **fail-closed:** F1–F3;
- **прод-форма:** R0 реальное дерево молчит; **R M-69/M-75/M-77/M-85/M-87 — реплей пяти реальных
  переездов** (worktree без чекаута на коммите переезда, диапазон `<sha>^..<sha>`): барьер
  обязан покраснеть на каждом инциденте. SETUP-guard у каждого сценария (`99` = сценарий не
  судил предмет).

Мутационный контроль (копии барьера с нейтрализованной проверкой, `PS_BARRIER=<копия>`):

| нейтрализовано | убивают |
|---|---|
| M1 проверка маркера (`if true`) | K1 K2 K6 K7 K8 K9 |
| M2 проверка `OPEN` у вынесенного | K11 |
| M3 проверка фразы в заголовке | K5 |
| M4 игнор блоков кода при разборе маркеров | K6 |
| M5 номер по префиксу, а не точно | K7 K8 |
| M6 чтение рабочего дерева вместо `HEAD` | K9 (и R0) |
| M7 вырезание «цитат»/`кода` перед поиском фразы | **P4 P6** — ложное красное на исторической прозе |
| M8 наивный критерий «НЕ ЗАКРЫТ» в заголовке | **P4 P5 P6** |
| M9 опечатка маркера молча пропускается | K10 |
| M10 триггер выключен | K1 K2 K4–K9 + все пять реплеев |
| M11 граница номера в заголовке снята | P7 |
| S1 «всегда PASS» | все K, F, реплеи (20) |
| S2 «всегда FAIL» | все P + R0 (10) |
| S3 «любой маркер CLOSED где угодно» | K5–K8 K10–K12 F1–F3 |

Ни один мутант не прошёл пробу зелёным. Сырой вывод — `ps-archive-result.md` (итог для ведущего).

### 3.3. Предел механизма — назван

1. Видит НАЛИЧИЕ маркера, не истинность и не автора: git-личность единая (`branch-hygiene.md`
   п.6). Маркер, поставленный architect'ом в нарушение зоны, барьер не отличит — ловит reviewer
   на PR и scope-guard, не этот барьер.
2. Согласованность прозы с маркером проверяется ТОЛЬКО по фразе «close-out за architect» и
   ТОЛЬКО в `## `-заголовке. Подзаголовок `###` (пример на вершине: у `M-87` «### Что осталось за
   architect'ом (milestone НЕ закрыт)») и тело раздела не читаются — это суждение reviewer'а.
3. Удаление маркера `CLOSED` у уже вынесенного не ловится (проверка 3 видит только `OPEN`).
4. 33 вынесенные ДО барьера спеки маркеров не несут и не обязаны — барьер срабатывает на
   переезде, не на состоянии архива целиком. Ретро-заполнение — зона reviewer'а, необязательно.
5. Заброшенный (не закрытый) милестоун, уезжающий в архив, барьер не различает.
6. Локальный прогон architect'а на отставшей ветке может краснеть ложно (маркер reviewer'а уже
   в `main`, но не в ветке) — лечится синхронизацией с `main`; CI в PR судит дерево слияния.
7. Под заморозкой `П-017` A2 это НОВЫЙ харнесс; основание разморозки — счёт §2, решение —
   ведущего architect'а.

## 4. Переходный шаг — кому что после merge

Первые же переезды упрутся в барьер, и это правильно. Нужны маркеры reviewer'а
(`PROJECT-STATE.md` — его зона, не architect'а и не этой правки):

- `M-68`, `M-89` — reviewer уже назвал «ЗАКРЫТ ПО СУЩЕСТВУ» (`R-213`); добавить `CLOSED`-маркер
  до их переезда;
- `M-65`, `M-71`, `M-73`, `M-45` — заголовки несут запрещённую формулу; при признании закрытыми
  переписать прозу и поставить маркер.
