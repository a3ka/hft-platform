## 0. Что НЕ переносится из einhard, и почему это важнее того, что переносится

Founder попросил взять правила приземления у einhard, где «таких проблем не возникает».
**Замер опровергает посылку:**

```
$ cd ~/einhard-runtime && git branch -r | wc -l                     97
$ git branch -r | grep -oE 'M-EH-[A-Z0-9]+([-][A-Z0-9]+)*' | sort | uniq -c | sort -rn | head -1
      5 M-EH-CASCADE-4-PHASE-0-P0        ← ПЯТЬ веток на одном предмете
$ grep -rniE 'gh pr create|gh pr merge|pull request' .claude/rules/*.md | wc -l      0
$ gh api repos/:owner/:repo/branches/main/protection
    403 "Upgrade to GitHub Pro or make this repository public"
```

У einhard **97** веток против наших 28, и дубли там есть. Проблема не решена — она
**не наблюдаема**: приземление идёт `git push origin HEAD:main` напрямую, PR-процедуры в
правилах нет ни одной строкой, защита `main` физически недоступна (private + free plan).
Ветка там — мусор от worktree, а не носитель незавершённой работы.

**Топология НЕ переносится.** Возврат к прямому push'у в `main` однажды стоил нам семи суток
красного `main` и 49 коммитов, не доехавших до прода (`gates.md` §8). Защита ветки, включённая
founder'ом 2026-08-15, — правильное изменение; она и породила класс «висячая ветка», сделав
приземление объектом, который надо доводить.

Переносятся ТРИ механизма, не зависящие от топологии.

## A1 — дерево решения в конце работы КАЖДОГО агента

### Дефект, который это закрывает

`commit-discipline.md` п.4/п.5 говорят, КТО приземляет. Ни одно правило не говорит агенту
**спросить себя об этом в конце работы**. Замер: PR #18, #19, #28, #33 — чеки зелёные,
`gh pr checks` → exit=0, механически не держит ничто. Работа сделана, гейт пройден, приземления
нет. У einhard ровно эта дыра закрыта деревом решения (`agent-self-push.md` §"Decision tree",
«every agent applies at end of own work»).

### Предлагаемый текст — вставка в `.claude/rules/commit-discipline.md` после п.5

```text
## Дерево решения в конце работы — применяет КАЖДЫЙ агент, всегда

Правила выше говорят, КТО приземляет. Этот раздел говорит, КОГДА себя об этом спросить.
Замер 2026-08-19: четыре PR с зелёными чеками стояли невлитыми — работа сделана, гейт
пройден, приземления нет. Никто не нарушил ни одного правила; никто и не был обязан
задать себе вопрос.

    Я последний в цепочке по объявленному классу (§«Класс работы» ниже)?
    ├── ДА  → все ли гейты класса зелёные?
    │        ├── ДА  → приземляю САМ: gh pr create → gh pr checks --watch (решение по
    │        │         КОДУ ВОЗВРАТА) → gh pr merge --merge --delete-branch
    │        └── НЕТ → СТОП, Handoff §E с ID гейта, который красен. Не мержу.
    └── НЕТ → следующий агент в цепочке; коммиты пушу на ветку, Handoff §D называет его
              поимённо. Не мержу.

Исход дерева — обязательная строка в Handoff §D рядом с push-статусом:
`Приземление: ✅ влито в main <SHA>` | `⏸ передано <роль>` | `⚠ блокер <gate-id>`.

**COGNITIVE-ONLY.** Механически проверить, что агент задал себе вопрос, нельзя. Наблюдаемая
часть механизирована отдельно — `scripts/check_branch_health.sh` (§B) печатает ветку с
зелёным PR, которую никто не влил, то есть ловит ИСХОД пропуска, а не сам пропуск.
```

## A2 — класс работы объявляется, и гейт маршрутизируется по объявленному классу

### Дефект, который это закрывает

Сегодня маршрут выбирается **суждением**, и суждение расходится. Живой пример этой сессии,
PR #28: `gates.md` §4 говорит «reviewer UNCONDITIONAL для кода/контрактов/риска/докса сверх
tech-debt правок»; `harness-track.md` §5 перечисляет пять условий гейта трека, и reviewer'а
среди них НЕТ, а §6 прямо пишет «здесь предмет видят две роли, а не пять». Ведущий architect
не смог решить это молча и вынес вопрос founder'у — то есть норма не работает как норма.

У einhard это Gate 8 (BINDING): автор ОБЪЯВЛЯЕТ класс, и push-гейт маршрутизируется по
объявленному классу, а не по догадке проверяющего.

### Предлагаемый текст — вставка в `.claude/rules/commit-discipline.md` перед деревом A1

```text
## Класс работы объявляется автором, и гейт маршрутизируется по объявленному классу

Строка в теле первого коммита цепочки ЛИБО в Handoff §A:
`РАБОТА-КЛАСС: substantive | harness | process-polish | mixed`

| класс | признак (любой из) | кто последний в цепочке |
|---|---|---|
| **substantive** | `crates/*/src/**` · `crates/contracts/**` · `crates/risk\|killswitch\|oms\|venue-*/**` · раскладка/формат журнала · `docs/DESIGN.md`, `docs/0N-*.md`, `docs/fa/**` (инварианты, границы, фазы) · новая milestone-спека | **reviewer** (+ risk-critic по `gates.md` §5, + critic по §1/§9) |
| **harness** | ТОЛЬКО `scripts/check_*.sh` · `scripts/verify_*.sh` · `scripts/tests/**` · `.github/workflows/**` · `.githooks/**` · репо-тулинг | **автор** после адверсария (`harness-track.md` §5) |
| **process-polish** | ТОЛЬКО `.claude/**` · `CLAUDE.md` · `docs/04-workflow.md` · `docs/workflow/**` · `milestones/*.md` · `docs/plans/**` — БЕЗ изменения инвариантов, границ, фаз | **автор** своим PR (`gates.md` §9) |
| **mixed** | тронуто больше одного класса | **reviewer**; carve-out'ы НЕДЕЙСТВИТЕЛЬНЫ |

**Класс не объявлен ⇒ читается как `substantive`** (fail-closed: неизвестный вход → строгий
маршрут, класс `RK-I-3`). Объявленный класс не совпал с дифом — находка reviewer'а/критика.

**COGNITIVE-ONLY в части истинности объявления:** машинно проверяемо, что строка ЕСТЬ и что
пути дифа не выходят за объявленный класс; что автор объявил ЧЕСТНО — суждение. Кандидат на
механизацию назван и не изображается сделанным: барьер, сверяющий `git diff --name-only`
диапазона с таблицей выше, по образцу `check_docs_freeze.sh`.
```

## A3 — смешанный класс: carve-out недействителен

### Предлагаемый текст — абзац сразу под таблицей A2

```text
**Смешанный класс губит carve-out целиком.** Тронут хоть один путь класса `substantive` —
маршрут `substantive`, независимо от того, сколько в дифе процессных или харнесс-файлов.

```

## B — механизм наблюдения за ветками (`scripts/check_branch_health.sh`)

Это **§C.1 плана, утверждённого founder'ом 18.08**, а не новая идея. У einhard такого
механизма нет — пять веток на одном ID это доказывают, — поэтому заимствовать нечего.

### Что печатает (наблюдает, НЕ блокирует — уровень 5 `binding-requires-mechanism.md`)

По каждой `origin/*` кроме `main`: отставание · возраст вершины · число НОВЫХ файлов ·
открытый PR и состояние его чеков · число прогонов CI. Плюс два агрегата:

1. **ВИСЯК** — ветка с открытым PR, у которого ВСЕ чеки зелёные, старше порога. Это
   наблюдение ИСХОДА пропуска A1: работа готова, никто не влил.
2. **ДУБЛЬ** — на один идентификатор предмета (`M-NN`, `TD-NNN`) живых веток больше одной.

### Свойства, обязательные по нормам

- **герметичность** — проба строит свой bare-origin в `/tmp` и в сеть не ходит: иначе мерила
  бы доступность GitHub, а не свой инвариант (класс `TD-135`, образец — `red_reserve_id.sh`);
- **наблюдает ОТСУТСТВИЕ** — барьер обязан краснеть, когда предмет наблюдения исчез, а не
  молча печатать пустой список (`testing.md`, целостность гейта, свойство 4);
- **уборка фикстур** — реестр в ФАЙЛЕ + `trap EXIT`, замер каталогов до/после числом;
- **не входит в агрегат `All checks passed`** — он наблюдатель, его красное не имеет права
  блокировать merge; это отличает его от барьеров.

### Названный предел

Отчёт наблюдателя никого ни к чему не обязывает. Он превращает «ненаблюдаемое» в «видно в
логе джоба» — и `process-layer-audit-2026-08-13.md` §4 прямо меряет эффективность такого
канала как низкую. Честная формулировка: это уровень 5, и выше он не поднимается без решения
блокировать merge, которого никто не принимал.

## C — уверенность, что висячих веток больше не будет: чего пакет НЕ даёт

Полной гарантии нет, и она здесь не изображается.

| что закрыто | чем |
|---|---|
| «нет прогонов» неотличимо от «не пушили» | **закрыто механизмом** — `branch-build.yml` влит, ветка собирается сама |
| приземление забывается | A1 — `COGNITIVE-ONLY`, вопрос себе в конце работы |
| маршрут выбирается суждением и расходится | A2/A3 — объявление класса; проверяемая часть механизируема, истинность — нет |
| висяк ненаблюдаем | B — наблюдатель, уровень «видно в логе» |
| **бросить готовую ветку по-прежнему можно** | **ничем.** Механизма, физически это запрещающего, не существует и не предлагается |
