## §2. Этап 0 — необратимое. Предусловие → доказательство → ОКНО → удаление

**Инвариант этапа:** удаление ref'а есть ОТДЕЛЬНОЕ, позже наблюдаемое действие. Между
публикацией доказательств и командой удаления стоит окно, в которое независимый читатель
может возразить.

### §2.1 Окно — определено, а не «после них»

**Длительность: одна сессия-передача.** Доказательства по всем трём ref'ам публикуются одним
коммитом `docs/plans/deletion-evidence-2026-08-19.md`; удаление выполняется **не раньше
следующего запуска architect'а**, то есть после того, как между публикацией и командой
прошёл хотя бы один Handoff. Основание выбора: у нас нет дежурного читателя, который
среагировал бы «через N часов»; наблюдаемая единица времени в этом проекте — передача между
сессиями, и только она гарантирует, что доказательства кто-то мог открыть.

**Что делает окно проверяемым:** дата коммита с доказательствами и дата коммита удаления —
разные, и разрыв виден в `git log`. Если удаление окажется в том же коммите или в том же
Handoff'е — окна не было, и это находка следующего гейта.

### §2.2 Условия по каждому ref'у — поимённо, из `R-095` §§У-1/У-2/У-3

**У-1 — сохранение перед сносом** (`branch-hygiene.md` п.6). Для КАЖДОГО ref'а до
`push --delete`:

```

git rev-parse origin/<ветка> >> /home/nous/salvage-2026-08-19/SOURCE-COMMITS.txt
```

Носитель доказательства: файлы патчей + `SOURCE-COMMITS.txt`; их наличие и размеры
печатаются в `deletion-evidence-2026-08-19.md`. Ответственный: **architect**.
