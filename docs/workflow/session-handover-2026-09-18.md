## 4. ЛОВУШКА, которая уже стоила круга гейта — читать до воспроизведения барьеров

`check_protected_artifacts.sh` даёт **разный ответ в зависимости от порядка родителей**
дерева слияния:

```
git worktree add <dir> --detach <ветка>      && git merge origin/main  → exit=1  ЛОЖНОЕ КРАСНОЕ
git worktree add <dir> --detach origin/main  && git merge <ветка>      → exit=0  как в CI
```

Механика: `mainline` = дерево базы + цепочка ПЕРВЫХ родителей (`:150-154`). При обратном
порядке в магистраль попадают коммиты ветки, написанные ДО переезда чужой спеки в архив;
путь оказывается в `mainline`, fallback запрещён, и барьер объявляет «исчез, и ни один
коммит его не удалял».

**Настоящий порядок подтверждён:** у `6c088ba`, `9d852a3`, `3f399ec` первый родитель — предок
`main`. То есть в реальном CI барьер зелен.

Ловушка уже сработала на `R-186` — вердикт объявил блокер, которого нет. **Кандидат в долг
(зона reviewer'а):** барьер обязан давать один ответ независимо от способа воспроизведения,
либо печатать предупреждение о порядке родителей.
