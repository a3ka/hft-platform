### 4. Факты, проверенные прошлой сессией командой

- Рыночное состояние принадлежит **ПОДПИСКЕ**: `Sub { id, selector, live: Option<LiveReducer> }`
  (`crates/gateway-serve/src/session.rs`). Два клиента с ИДЕНТИЧНЫМ запросом = два расчёта.
- Трафик: снимок 614 436 Б, среднее обновление 22 183 Б (40 кадров), такт `PUSH_INTERVAL_MS = 250`
  ⇒ ~710 кбит/с на подписку; 10 000 → ≈7.1 Гбит/с.
- **Запас по размеру кадра ДЫШИТ:** за 6 часов ушёл с ≈7× до ≈2.9× предела 2 000 000 Б. Суточной
  динамики НИКТО НЕ МЕРИЛ — открытый замер.
- Прод: один VPS, 7 ГБ RAM, журнал 74-75 ГБ, 367 сегментов, ~12 млн событий/сутки. Холодная
  пересборка слепка ≈23 мин — замер на СТАРОЙ структуре и ОДНОМ инструменте, на новую не переносится.
- Записываются ДВА инструмента (BTC, ETH), отдаётся ОДИН (`GATEWAY_SYMBOL=BTCUSDT`). Инструмент и
  параметры присылает КЛИЕНТ; код параметричен, но прогретый слепок есть только под BTC с
  каноническими семью полосами.
- `MAX_REL_DIST = 0.60` (`crates/venue-binance/src/lib.rs:33`, окно `:689`, отсев `:958`):
  записывающий контур отбрасывает всё дальше 60 % от середины. Данные дальше НЕ ЗАПИСЫВАЮТСЯ
  НИКОГДА и недостижимы даже для воспроизведения.
- **ПОЛОСА 60 % НЕ ПУСТА** — исправленная ошибка прошлой сессии, повторённая ЧЕТЫРЕ раза. Она
  несёт САМУЮ БОЛЬШУЮ накопленную величину: замер 2026-09-21, bid — 1.5 % `37 914 314 000`,
  30 % `415 647 468 000`, **60 % `753 846 141 000`**. Монотонность `D(60 %) ≥ D(30 %)` — следствие
  определения суммы, НЕ утверждение о полноте наблюдения. Метка `not-observed` означает «сумма
  полна лишь до охвата `reach ≈ 0.59`». **НЕ ПУТАЙ три величины:** накопленную глубину до 60 % ·
  кольцо 30-60 % · область дальше 60 %.
- `spawn_blocking` НЕ отменяется: pump уходит в блокирующий пул, `grep abort` → 0. Отключение
  клиента работу НЕ останавливает — наблюдалось на проде.
- Отпечаток селектора — `DefaultHasher`; имя слепка `ckpt-<fp_hex16>.bin`; Rust не гарантирует
  стабильность между версиями, оговорки в коде НЕТ. Мина: обновление toolchain осиротит все слепки
  МОЛЧА. Переключение на стабильный ключ — вместе со сменой формы состояния (план §15.6).
- Слепок отвергается при `gw_v != GATEWAY_SCHEMA_VERSION`: версия ПРОВОДА обесценивает
  ВЫЧИСЛИТЕЛЬНОЕ состояние. Развязка версий — план §15.6.
- Подписанное решение `П-014` п.4 живёт в ОДНОМ файле `/root/hft-platform/.env` (132 Б,
  `.gitignore:4`), и его резервная копия НЕ СОДЕРЖИТ ключа `GATEWAY_BANDS` вовсе ⇒ любое
  восстановление тихо откатит прод к одной узкой полосе через дефолт `${GATEWAY_BANDS:-0.001}`.
  Лекарство — версионированный несекретный профиль расчётов (план §15.5), требует ПОДПИСИ.
