# Эпохи данных журнала — где записанному нельзя доверять

STATUS: LIVING DOC (architect). Журнал append-only и бессмертен: записанное не
переписывается. Поэтому единственная защита от «тихой лжи в истории» — **явный реестр
эпох**: какие данные, с какого по какой `seq`, имеют известный дефект семантики.

Читающий (кокпит, research, бэктест, будущий продукт AlphaQuant) обязан свериться с этим
файлом ПЕРЕД тем, как строить выводы на затронутых полях. Отсутствие записи здесь означает
«дефектов семантики не известно», а не «данные проверены».

## E-002 — состав L2Delta-записи расширен на ETHUSDT (открыто 2026-08-31)

**ЭТО НЕ ДЕФЕКТ.** Все прежние записи файла описывают порчу семантики уже записанного. Здесь
другое: осознанная смена СОСТАВА записи по подписи founder'а (`П-026`, граница C). Запись
заведена потому, что правило 1 «как пользоваться» — «перед выводом на данных проверь, нет ли
эпохи, затрагивающей используемые поля» — обязано срабатывать и на такой границе: аналитик,
считающий глубину стакана по эфиру, обязан знать, что до этой точки её в журнале НЕТ.

**Что меняется.** До границы `ETHUSDT` записывался ТОЛЬКО полными снимками стакана раз в
секунду (`L2Snapshot`). После — дополнительно суб-секундными диффами (`L2Delta`, 100 мс), как
`BTCUSDT` с `M-18`. Механизм существует с `M-45` и до этой точки СПАЛ: переменная
`L2DELTA_CAPTURE_SYMBOLS` не была объявлена в конфиге, и действовал дефолт кода `["BTCUSDT"]`
(`crates/venue-binance/src/lib.rs`, `parse_capture_symbols`, `PROD_DEFAULT`).

**Граница эпохи — ОБЪЯВЛЕНА, а не вычислена.** До этого решения `EPOCH_ID` на проде не
задавался (замер 2026-08-31: `grep -c '^EPOCH_ID='` → `0`), и действовал дефолт
`own-<UTC-YYYY-MM>` (`crates/recorder/src/main.rs:481`). Такая граница есть МОМЕНТ
ПЕРЕЗАПУСКА КОНТЕЙНЕРА после полуночи UTC — то есть случайность, а не решение. Для смены
состава это негодно: граница обязана быть предъявимым фактом. Поэтому раскатка задаёт
`EPOCH_ID` ЯВНЫМ значением тем же деплоем, что и состав.

| Что | Значение |
|---|---|
| решение | `docs/PENDING-SIGNATURE.md` `П-026`, подписано 2026-08-31 |
| `EPOCH_ID` до | не задан; де-факто `own-2026-08` (дефолт по часам) |
| `EPOCH_ID` после | задаётся явно тем же коммитом, что и состав — значение вносит раскатка |
| граница по `seq` | **заполняется ПОСЛЕ деплоя** первым heartbeat'ом новой сессии, по образцу `E-001`: `next_seq` минус `events` новой сессии |
| merge-коммит раскатки | заполняется при деплое |

**Что затронуто:** любой вывод о внутрисекундной динамике книги `ETHUSDT` — хитмап,
footprint, order-flow, «съедание ликвидности». До границы этих данных НЕТ ФИЗИЧЕСКИ, и
отсутствие сигнала там не означает отсутствия события: оно означает отсутствие наблюдения.

**Что НЕ затронуто:** `BTCUSDT` (пишется диффами с `M-18`) · фьючерсы и Hyperliquid (состав
не тронут) · форма события `MdPayload::L2Delta` (T1 не меняется, `SCHEMA_VERSION` тот же) ·
трейды, funding, OI, ликвидации по любому инструменту.

**Ожидание по объёму — ОЦЕНКА, подлежащая замеру.** Дифф в 5-10× дешевле снимка, снимки —
96 % объёма журнала, поэтому ожидается ПАДЕНИЕ суточного прироста. Это оценка `M-45`, а не
факт: переснять через сутки после раскатки и вписать сюда число.

## E-001 — Hyperliquid: стороны трейдов ИНВЕРТИРОВАНЫ (открыто 2026-07-29)

**Что не так.** `venue-hyperliquid` маппил `"A" => Side::Buy`, `"B" => Side::Sell`.
Официальная нотация Hyperliquid (проверено architect'ом по первоисточнику
`hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/notation`, дословно):

> «Side = side of trade or book. **B = Bid = Buy, A = Ask = Short.**
> Side is aggressing side for trades.»

Правильный маппинг — обратный. Значит **у всех трейдов Hyperliquid в журнале поле `side`
перевёрнуто**: агрессивная покупка записана как продажа и наоборот.

**Как найдено.** RED-суита M-41 (риск R4: `venue-hyperliquid` имел 217 строк и НОЛЬ тестов
при работе в проде). Дефект D0 спеки `milestones/M-41-venue-hyperliquid-tests.md`.
Подтверждён независимо: код + первоисточник биржи.

**Граница эпохи — ЗАМЕРЕНА (2026-07-30T00:04Z).** Начало — первый записанный трейд
Hyperliquid (парсер был таким с самого начала сбора). Конец — деплой фикса M-41 на прод:

| Что | Значение |
|---|---|
| merge-коммит фикса | `51fc3cc` (M-41, reviewer APPROVED) |
| VPS обновлён | 2026-07-30T00:03:47Z (recorder перезапущен, `restarts=0`) |
| `next_seq` в первом heartbeat после деплоя | 123 209 025 (при `events=3481` в новой сессии) |
| **граница эпохи (оценка)** | **`seq ≈ 123 205 544`** = 123 209 025 − 3 481 |

Трактовка границы: трейды Hyperliquid с `seq` **меньше** ~123.21 млн записаны инвертированным
парсером. Оценка снизу-сверху сознательно грубая (±несколько тысяч событий вокруг рестарта):
точный водораздел — первый HL-трейд, записанный процессом, запущенным в 00:03:47Z. Для
практических целей (исключение периода из анализа по направлению) грубости достаточно;
для точного водораздела нужен разбор сегмента 125 по `provenance`/времени события.

**Что затронуто:**
- любые метрики по сторонам трейдов HL: CVD, delta, footprint, bid/ask-агрессия,
  order-flow imbalance, «absorption/exhaustion» по HL;
- бэктесты и отчёты, использовавшие HL-трейды как источник направления;
- НЕ затронуты: цены, объёмы, тайминги, стакан (`L2Snapshot`/`L2Delta`), funding, OI.

**Решение (architect):** данные эпохи E-001 **непригодны для анализа по направлению
сделок**. Автоматическая коррекция при чтении НЕ вводится — сознательно:
1. риск двойной инверсии (коррекция применена дважды или к уже исправленным данным) хуже,
   чем явное ограничение области применения;
2. различить эпохи машинно СЕЙЧАС нечем: `provenance` в контейнере — константа
   (`no-git-info`, TD-031/TD-032), поэтому «до/после фикса» по заголовку сегмента не
   отличить; единственный доступный признак — `seq`-граница, а она внешняя по отношению к
   данным.

**Что предложить founder'у (решение не архитектурное, а продуктовое):** если HL-трейды
нужны продукту как источник order-flow за прошлый период — единственный честный
машинный признак эпохи даёт **бамп `SCHEMA_VERSION`** при фиксе (тот же класс, что TD-033:
семантическое изменение значения поля без бампа схемы делает данные неразличимыми).
Это T1-изменение и требует contract-RFC. Пока не сделано — область применения ограничена
текстом выше.

**Смежный долг.** Отсутствие теста у адаптера, который пишет в прод, — корень находки.
Заводится вместе с close-out M-41: правило «venue-адаптер без RED-суиты не идёт в прод»
(семейство `VN-I`: 9 инвариантов заявлено, 0 оракулов — риск R9).

## Как пользоваться этим файлом

1. **Перед выводом на данных** — проверь, нет ли эпохи, затрагивающей используемые поля.
2. **Новая эпоха заводится architect'ом** в ДВУХ случаях: (а) обнаружен дефект СЕМАНТИКИ уже
   записанного (не дефект кода, который ничего не испортил); (б) **осознанно сменён СОСТАВ
   записи по подписи founder'а** — граница C, `П-011`. Второй случай добавлен 2026-08-31
   вместе с `E-002`: правило 1 («проверь, нет ли эпохи, затрагивающей используемые поля»)
   обязано срабатывать и на границе состава, иначе аналитик примет отсутствие НАБЛЮДЕНИЯ за
   отсутствие СОБЫТИЯ. Обязательные поля: что не так, как найдено
   (с первоисточником), граница по `seq`, что затронуто и что НЕ затронуто, решение.
3. **Эпоха не закрывается никогда** — записанное не исправляется. Она может только получить
   машинный признак (бамп схемы) или инструмент коррекции с доказанной идемпотентностью.
