# 00 — Откуда берутся стратегии + AI-quant команда (ответ на 4 вопроса founder'а, 2026-07-10)

## Q1. Откуда взять стартовый набор рабочих стратегий

Готовой библиотеки «рабочих» стратегий не существует нигде — опубликованная альфа умирает.
Существует публичный **канон скелетов**, у которых edge живёт не в идее, а в калибровке
на собственных данных + качестве исполнения + издержках. Стартовый набор:

1. **OBI (order-book imbalance) — стратегия founder'а, №1 в бэклоге.** Текущее правило
   «depth-имбаланс bid(3% полоса) vs ask(8% полоса) >= порога → BUY» формализуется как
   параметрическое семейство `imbalance(D_bid, D_ask, θ, horizon, exit)`; считается из
   собственного L2-потока (внешний сервис не нужен, задержка меньше); грид-бэктест +
   decay-анализ + издержки. Классика Cont/Stoikov-литературы; асимметрия полос (3/8) —
   сама по себе интересная гипотеза.
2. **Passive MM** — Avellaneda–Stoikov скелет: квоты вокруг микроцены, спред = f(вола),
   скос от инвентаря. Формулы публичны.
3. **Cross-exchange lead-lag**: Binance ведёт, Hyperliquid догоняет — сигнал с Binance,
   исполнение на HL.
4. **Funding/basis**: перп-фандинг капчур, дельта-нейтральные конструкции.
5. **Liquidation-flow**: ликвидации на HL публичны — momentum/контртренд после каскада.
6. **Short-horizon mean-reversion** после крупных агрессивных сделок + фильтр токсичности потока.

Постоянные источники гипотез: микроструктурная литература, аномалии в собственных
журналах, глаз трейдера (как №1), пост-трейд анализ собственных fills.
Честность: скелет = ~10% результата; деньги — в калибровке, исполнении, комиссиях
(на HL мейкер-ребейты) и риске. Поэтому research-платформа = moat.

## Q2. Цикл «гипотеза → бэктест → симуляция → прод → анализ» на агентах, 24/7 — ДА, с дисциплиной

- LLM-агенты ТОЛЬКО на краях цикла: формулировка гипотез, кодирование сигнала,
  интерпретация отчётов. Середина — детерминированный Rust-движок (бэктест/симуляция =
  дешёвый compute, не токены; не галлюцинирует).
- Главный риск: агенты × бэктесты = индустриальный оверфиттинг (multiple testing).
  Обязательные гейты: time-split train/val/test; walk-forward; deflated Sharpe с
  ГЛОБАЛЬНЫМ счётчиком испробованных гипотез; обязательный paper-период; человеческая
  подпись (HDP) перед live. Критик-агент обязан пытаться убить каждую стратегию
  (leakage / regime-dependence / заниженные издержки).
- Паттерн = EINHARD proposer/validator/operator дословно: LLM никогда не оценивает
  собственную работу — оценивает детерминированный движок + независимый критик + человек.

## Q3. AI-quant команда, создающая Слой 3 (Alpha) — ДА

Роли: hypothesis-researcher (генерация из литературы/аномалий + формализация идей
founder'а — приоритетная очередь), signal-engineer (SignalSpec → Rust-код + тесты),
backtest-runner (оркестрация гридов — скрипты), risk-critic (адверсарий),
portfolio-analyst (веса/корреляции/sizing-предложения).
Выход — **реестр сигналов** (версионированный, по образцу EINHARD action registry):
каждый сигнал = карточка {SignalSpec, код, валидационный отчёт, статус
candidate → paper → live → retired}.

## Q4. «Я даю сигнал — агенты делают signals → ensemble → sizing» — ДА, с разделением

- **Дизайн-тайм** (агенты + founder): формализация → грид → валидация → отчёт →
  подпись founder'а → сигнал входит в ансамбль с калиброванным весом.
- **Ран-тайм** (без LLM): детерминированный движок применяет калиброванные веса
  ансамбля и sizing-параметры (лимиты, корреляции, инвентарь). Изменение весов =
  событие с approval через очередь решений, никогда «LLM подкрутил на лету».

## Экономия (директива founder'а)
Fable — только архитектура/спеки/критические решения; bulk-чтение и черновики —
дешёвые субагенты; вся оценка стратегий — Rust-compute без токенов.
