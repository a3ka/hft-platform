## 6. Дисциплина, выведенная практикой — соблюдай

1. **Каждому субагенту — startup-протокол блоком в мандате.**
2. **Каждый агент пишет результат ФАЙЛОМ и пушит.** Отчёт в чат не принимается — канал возврата теряет результаты (наблюдалось ~десять раз).
3. **Приземление проверяй командами git**, не чтением отчёта (RN-19). Отчёт — гипотеза, git — факт.
4. **Длинная задача = инкрементальные коммиты.** Требуй: первым действием закоммить скелет и запушить, дальше коммитить по частям. Эксперимент: та же модель на той же задаче — без требования вернула ноль, с требованием выдала 366 строк.
5. **Два агента подряд без результата — не запускай третьего, проверь задачу сам.** На `det_22` три агента сожгли ~190k токенов на задаче, где врал оракул; диагноз занял пять команд.
6. **Гейт в одну команду прогоняй лично**, не через субагента.
7. **Числа и статусы — замером, не переносом.** За сутки документы соврали о состоянии кода **восемь раз**.
8. **Мутационный контроль обязателен**, включая обратный: оракул на уже сделанный фикс зелёный с первого запуска и потому не доказывает ничего — откати фикс и убедись, что краснеет.
9. **При необъяснимом красном — сначала `df -h /home`.** Переполнение диска давало ложный FAIL; чисти `target/` завершённых worktree ПЕРЕД запуском агентов.
10. **ADVISORY критика о зоне — сигнал сменить РОЛЬ исполнителя**, а не предупредить его. Диспетчеризация — обязанность оркестратора.
11. Состояние обновляй в `ORCHESTRATION-STATE.md` после КАЖДОГО завершённого шага.
