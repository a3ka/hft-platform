## Ф2 — Read-path под SaaS: проекции + квоты

R7 при SaaS — блокер существования (DESIGN-v2 §6): сегодня N клиентов = N полных
сканов журнала, соединения без cap.

**Входит:**
- **Shared-tailer + HOT-проекция** (M-39-класс, включает наработки M-38-roadmap):
  один проход по журналу на процесс; снапшот-при-подключении из RAM; каналы публикации
  per topic (venue×symbol×серия×разрешение).
- **Cap'ы и квоты (fail-closed):** глобальный/per-user cap соединений, cap подписок,
  per-connection бюджет, slow-consumer → снапшот-ресинк; невалидный лимит = отказ
  старта (конец класса «parse-error → unbounded»).
- **JWT-claims тарифа** (tier, квоты, allowed_channels) в gateway-serve — Rust
  верифицирует и применяет без похода в БД.
- **Staleness в типе (R5):** `BookView<Fresh|Stale>` — кокпит не показывает мёртвую
  ликвидность как живую (PL-I-7).
- **Нагрузочный стенд:** замер соединений/полосы на узел — закрывает
  `[verify-at-impl]` числа DESIGN-v2 §6 и даёт триггер выделения fan-out-узла (§11).
- Оракулы **PL-I-4/PL-I-5** (RED-first).

**Предусловия:** Ф1 (проекции строятся уже над целевым форматом данных).
**Acceptance:** стенд: X тыс. соединений на узле при O(1) сканах журнала и p95
snapshot-on-connect ≤ порога (числа фиксируются стендом и вносятся в DESIGN-v2 §6);
деградационная лестница §6 продемонстрирована (slow consumer, переполнение cap);
verify: лимиты обязательны.
**Объём:** ~3–4 milestone'а. **Founder:** — .

## Ф3 — App-плоскость: Postgres + Next.js каркас

Второй источник истины (DESIGN-v2 §3) и скелет продукта.

**Входит:**
- Postgres (managed, PITR) + миграционная дисциплина; **restore-drill БД — acceptance,
  не опция**.
- Auth (Auth.js) → JWT-мост к gateway-serve (ротация ключа; Ed25519 —
  `[verify-at-impl]`).
- CRUD: Profile, Workspace/View/Widget-layout, **decision-journal** (терминология
  DESIGN-v2 §3 — жёстко), alerts; RLS/tenant-скоупы.
- Каркас биллинга (Stripe-класс) БЕЗ включения платных планов (включение — Ф6).
- Fastify — только если/когда выделяется отдельный API-сервер (решение внутри фазы,
  критерий: нагрузка/структура API, не вкус).
- Оракулы **PL-I-2/PL-I-9** (у app-плоскости нет write-пути в event-store).

**Предусловия:** Ф0 (алертинг — теперь стережёт и Postgres); параллелится с Ф2.
**Acceptance:** e2e: регистрация → Workspace сохранён → JWT открывает WS-подписку по
claims; PITR-restore-drill пройден; RLS-тест (чужой tenant недоступен).
**Объём:** ~3–4 milestone'а (частично зона founder'а по D6 — границы уточняются при
спеке). **Founder:** ★ выбор провайдеров (Postgres-хостинг, auth, биллинг).

## Ф5 — AI Tutor + Agent Runtime v0 (первый wedge собран)

**Входит:**
- **Event Engine** (Rust, детерминированный): семантические события микроструктуры
  (absorption, exhaustion, CVD-divergence, …) — LLM не смотрит на пиксели.
- **Agent Runtime (Node/TS):** роли Market Observer + AI Tutor (+ Journal Analyst
  minimal); tools read-only + write в свои зоны Postgres; policy/бюджеты LLM;
  **audit-store append-only**.
- **AI Event** — единый контракт (AlphaQuant §7.3; Low/Medium/High, без фейковых
  процентов); chips/annotations в UI.
- **Tutor Workspace** (AlphaQuant §8): Lesson/Ask/History, Guided Replay по умолчанию,
  paper decision через sim [ЕСТЬ], результат — в decision-journal.
- **Оракулы INTG-I (сейчас 0 из 7!) в редакции «агенты пользователей»** (DESIGN-v2 §8.3)
  + PL-I-3 — RED ДО подключения runtime к живым пользователям.

**Предусловия:** Ф4 (терминал, в котором Tutor живёт); Ф3 (память/audit).
**Acceptance:** учебный цикл §8.2 AlphaQuant проходит end-to-end на replay (событие →
гипотеза пользователя ДО объяснения → evidence → paper decision → оценка процесса →
запись в decision-journal); audit-trail полон (tool calls, model+version, evidence);
бюджет LLM per-user срабатывает; INTG-оракулы GREEN.
**Объём:** ~4–5 milestone'ов. **Founder:** ★ LLM-провайдер/модель; ★ приём wedge.

## Ф6 — Монетизация / GA ★★

**Входит:**
- Тарифы Free/Trader/Pro/Quant (AlphaQuant §15) — включение биллинга + серверный
  enforce квот (PL-I-5) по всем поверхностям (§5 DESIGN-v2).
- **Права на данные — исполнение отложенного founder-решения** (DESIGN-v2 §14.1):
  выбранная модель (согласие бирж / лицензированный провайдер через Source Adapter §7.1 /
  bring-your-own-data) + включение лицензионного гейта **LIC-I-1..3**; при смене
  источника — оракул эквивалентности **SRC-I-1..3** обязателен.
- SLA/наблюдаемость GA: целевые uptime/latency/freshness зафиксированы и алертятся
  (§10); нагрузочный прогон на «десятки тысяч» профиля Ф2.
- Юридические формулировки (education/analytics — DESIGN-v2 §14.2) — внешняя проверка.

**Предусловия:** Ф4+Ф5; Ф2-стенд.
**Acceptance:** платящий пользователь end-to-end (оплата → tier-claims → лимиты
работают); LIC-гейт: `internal-only` событие недоставаемо платному клиенту (оракул);
SLA-дашборд + алерт-паритет по всем инцидент-классам.
**Founder:** ★★ модель прав на данные (с юристом); ★ цены/тарифы; ★ GA.
